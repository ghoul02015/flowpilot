## 三、后端实现

- `internal/bundle`：独立领域包，含清单解析/校验、选项展开快照、状态计算、四项预检、串行编排、四表存储、服务层。
- SQLite 迁移 **Version 5**：`bundle_installs`、`bundle_install_items`、`bundle_license_confirmations`、`bundle_acceptances`，只追加不改历史表。
- 活动计划唯一索引保证同套装同变体只有一个进行中计划；`requestKey` 保证重复提交幂等。
- 串行编排：单文件顺序执行，已存在且大小一致的文件跳过；必需项失败整单失败，可选项失败不阻断；支持暂停/继续/取消/只重试失败项；服务重启后计划转为“待继续”。
- 统一任务：套装安装聚合进任务中心（`bundle-install`），支持查看与删除记录。
- 下载通道默认 `hf-mirror.com`，内容一致性由官方 SHA256 校验保证。

### 实机真实下载验证（补充）

在 Spark 上真实创建 S1 安装并观察下载链路，暴露并修复了两个缺陷：

1. **进度条长期停在 0%**：`completedBytes` 只累加“已完成项”，第一个文件 20.98 GB 下完之前进度一直是 0。
   - 修复：`Service.GetInstall` 读取当前子任务的实时字节，合并进返回视图；落库值不变，避免污染事实数据。
   - 前端同时显示「当前文件已下载 X」。
2. **残留任务阻塞重试**：取消安装或平台重启后，同目标路径会留下 `paused` 子任务；再次安装时下载引擎报“已有目标为 … 的任务在进行中”，整个计划立即失败。
   - 修复：`Downloader` 增加 `FindByTarget`，创建失败时复用同目录同名任务并 `resume`／`retry`，保留已下载分片；若已有任务已完成则直接判定该项齐备。

修复后实机复验：残留任务 `dl-1794463836-39` 从 `paused` 恢复为 `running`，续传至 **2.7 GB**，进度从 4.95% 实时增长到 5.60%，当前文件字节同步显示。

实机验证过程中确认过一次 S1 许可，数据库留下 1 条确认记录（容器内 DB 以只读方式挂载，未强行清理）。该记录语义正确：管理员已阅读当前许可版本。
