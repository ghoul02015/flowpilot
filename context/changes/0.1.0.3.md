# 0.1.0.3 — 镜像构建稳定性修复

## 背景

0.1.0.2 发布后，在 Spark（DGX Spark，arm64）上通过镜像中心在线构建 `nvidia-cu130` 配方，连续两次失败，进度停在 28%。

任务详情给出的错误：

```
The command '/bin/sh -c apt-get update && apt-get install -y --no-install-recommends
  python3 python3-venv python3-dev git curl ca-certificates ffmpeg libgl1 libglib2.0-0 build-essential
  && rm -rf /var/lib/apt/lists/*' returned a non-zero code: 100
```

## 根因

日志显示 `ports.ubuntu.com` 的 `noble-security/main` 索引处于同步窗口：

```
Err:18 http://ports.ubuntu.com/ubuntu-ports noble-security/main arm64 Packages
  File has unexpected size (1492535 != 1492539). Mirror sync in progress?
E: Some index files failed to download
```

排查过程中又发现两个更隐蔽、更值得修的问题：

1. **基础镜像没有 CA 证书**：`ubuntu:24.04` 未预装 `ca-certificates`，任何 `https://` APT 源都会握手失败（`No system certificates available`）。第一版加固用 https 华为云源，结果索引一个都没拉到。
2. **`apt-get update` 在所有索引拉取失败时仍返回 0**：只打印 `W: Failed to fetch` / `W: Some index files failed`。这导致用 `apt-get update || 回退` 判断完全失效——回退分支不触发，构建继续跑到安装阶段才失败，报错变成 "Unable to locate package"，掩盖真实原因。
3. **Ubuntu 24.04 包名变更**：`libglib2.0-0` 在 noble 已改为 `libglib2.0-0t64`，原 Dockerfile 硬编码旧名，即使索引正常也会安装失败。

## 修复

### APT 层（`internal/image/image.go`）

- 依次尝试 http 镜像：华为云 → 清华 → 阿里云，全部不可用才回退官方源。
- 使用 http 而非 https，绕开基础镜像无 CA 证书的限制。
- 用日志判定成败：命中 `Err:` / `E:` / `Failed to fetch` / `Some index files failed` 即视为该源不可用。
- 所有源都不可用时输出最近 30 行日志并 `exit 1`，避免把索引问题伪装成装包问题。
- `libglib2.0-0t64` 与 `libglib2.0-0` 按索引实际存在的包名自适应。

### pip 层

- `torch` 与 `requirements.txt` 安装补 `--timeout 120`（torch 300 秒）与 `--retries 5`；pip 默认 15 秒超时在 GB 级 wheel 上极易中断。

### 任务数据

- 镜像构建／拉取任务新增 `StartedAt` / `FinishedAt`，任务中心详情不再显示“开始时间 — / 结束时间 —”。
- 取消、中断、正常结束都会写入结束时间；旧记录保持为空，显示为未记录。

## 已知边界

- Spark 到 `download-r2.pytorch.org` 实测 0.3–3.8 MB/s，cu130 依赖（torch 454MB、cudnn 651MB、cublas 543MB、triton 225MB、workflow templates 约 400MB）合计数 GB，本次完整构建约 1 小时 30 分，属带宽限制。
- torch 未锁版本，pip 解析到最新 `2.14.1+cu130`。本次启动自检通过，但 ComfyUI v0.45.0 长期兼容性未做全量验证，后续建议在配方中固定 torch 版本。
- `flowpilot.comfyui.commit_date` 仍为空：GitHub release 接口不返回该 commit 的提交时间，需要额外调 `/commits/{sha}` 才能补齐。
- 本版只做构建稳定性加固，没有改变配方内容（PyTorch 版本、CUDA 版本、ComfyUI 源码固定策略均沿用 0.1.0.2）。
