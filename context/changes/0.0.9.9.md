- 日期：2026-11-11

## 设计冻结（本版范围·精简版）

### 范围决策

统一任务框架完整实现（task_steps/task_logs/task_events、重试 attempt、幂等键、服务重启恢复续跑）规模庞大；本版交付**统一任务协议与视图层 + 迁移任务化**，将既有下载/导入/镜像任务聚合为统一模型，为 0.0.9.12（备份任务）与 0.0.9.14（升级任务）提供同一套协议。完整步骤日志体系记入后续版本。

### 统一任务模型（TaskView）

```text
id            任务 ID（各子系统 ID 加类型前缀，如 dl-xx/img-xx/mig-xx）
type          download / import / image-pull / image-build / migration
name          任务名称（文件名/镜像名/迁移描述）
objectType    model / image / instance / migration
objectRef     关联对象（路径/镜像名/实例名）
status        queued / running / paused / succeeded / failed / canceling / cancelled / partial
progress      0-100（未知总量为 -1，前端显示不确定进度）
message       当前步骤文案
error         失败原因
createdAt / startedAt / finishedAt
cancelable    是否可取消
```

### 实现

1. **迁移 004**：`tasks` 表（统一持久化模型：id TEXT PK、type、name、object_type、object_ref、status、progress、message、error、created_at、started_at、finished_at、cancelable）。
2. **internal/tasks 新包**：`Store`（Upsert/List 分页筛选/Get/MarkFinished）；`View` 统一视图结构。
3. **服务端聚合**：`GET /api/v1/tasks?type=&status=&limit=&offset=` 聚合三源——downloads（download.Manager 列表）、images（image.Manager 任务列表）、migration（tasks 表）——映射为统一 TaskView 实时返回；同时写入/更新 tasks 表持久化（迁移任务全程持久化；下载/镜像任务完成态持久化、运行态实时）。
4. **迁移任务化**：`POST /api/v1/migration/run` 改为创建任务（立即返回任务 ID），后台 goroutine 执行（复用既有 Run 逻辑），进度与结果写 tasks 表；`GET /api/v1/tasks/{id}` 查询详情。
5. **统一取消语义**：下载任务保留既有 pause/resume/cancel；迁移任务不支持取消（cancelable=false）。

### UI（任务中心）

- Tasks 页改用统一 `/api/v1/tasks`：类型徽章（下载/导入/拉取/构建/迁移）、统一状态徽章（排队/运行/暂停/成功/失败/取消/部分）、进度条（未知总量为动画态）、错误信息。
- 筛选：类型、状态；分页。
- 详情弹窗：摘要（对象、时间、耗时、错误）＋关联对象说明。
- 保留既有操作：下载任务暂停/恢复/取消/移除（按 ID 前缀路由）。

### 不做（记录）

- task_steps/task_logs 步骤日志与日志级别/虚拟化（0.0.9.14 升级框架一并）。
- 重试 attempt 与幂等键（断点续传已有；幂等待升级场景）。
- 服务重启后运行中任务恢复续跑（现有 tasks.json 恢复保留；统一表恢复 0.0.9.14）。
- 统一错误响应全 API 改造（0.0.9.14）。
- 批量清理与保留策略（0.0.9.15）。
