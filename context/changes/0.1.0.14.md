# 0.1.0.14 变更记录

- 日期：2026-11-16
- 类型：UI 结构优化（模型获取收敛）＋配色/密度微调
- 需求来源：周董确认方案——按钮 slate-700；结构选择方案 A（弹窗瘦身＋市场收敛到在线获取页签）。

## 背景与目标

0.1.0.13 后周董实测反馈：① slate-900 主按钮太深；② 市场卡片偏窄偏挤；③「添加模型」弹窗与「在线获取」页签功能重叠（同一 MarketPanel 两个副本），URL 下载/本地导入只藏在弹窗里，结构不清晰。经方案评审选定方案 A。

## 修改内容

- `index.css`：btn-primary slate-900 → **slate-700**（hover slate-600 / active slate-800）。
- `AddModelDialog.tsx`：
  - 弹窗移除「模型市场」页签，仅保留「URL 下载／本地导入」（默认 URL 下载）；页签条 3 列 → 2 列；说明文案改为指引市场前往「模型中心 → 在线获取」。
  - Props 精简为 `open / onOpenChange / onSubmit`；`MarketPanel` 继续导出供模型中心页签复用，回调类型导出为 `MarketDownloadHandler`／`OnlineDownloadHandler`。
  - 市场卡片密度：padding `px-4 py-3` → `px-5 py-4`，卡内 gap 2 → 2.5，名称 text-[15px] → text-base。
- `ConsoleLayout.tsx`：AddModelDialog 不再传 marketDownload/onlineDownload/existingModelPaths（Models 页签仍经 app-data 使用，不受影响）。
- **产品修复（回归中实测发现）**：`ModelBundles.tsx` 套装卡片「查看许可」点击后落错页签——URL 同步副作用在详情加载完成前重复触发 `openDetail`，把 `openLicense` 同步选中的「许可与声明」页签重置回「概览」。守卫改为「同 id 直接跳过」（含加载中），许可直达恢复。探针实测：修复前高亮页签「概览」，修复后「许可与声明」且许可名称可见。
- 回归脚本：`verify-demo.mjs` 市场链路（MiniMax 条目、在线搜索、仓库直达、LoRA 真实下载、横向溢出）改走 `#model-panel-online` 页签容器，断言锚点与下载轮询不变，结束后切回本地仓库页签；`e2e-audit.mjs` 弹窗断言「模型市场加载推荐目录」改为「弹窗提供 URL 下载与本地导入」。
- 回归脚本一次性翻新适配 0.1.x 界面（0.1.0.11 侧栏改造后全量回归未跑通过，以下全部为实测驱动的修正）：
  - 侧边导航 `button` → `link` 角色（12 处：ComfyUI 实例／首页看板／镜像中心／模型中心／任务中心／系统管理）。
  - 首页实例名改为直达实例详情页（`/instances/:name`），原「详情弹窗＋完成按钮」断言改写为「URL＋标题＋返回列表」。
  - 系统页改两级页签点击：先组页签（维护与支持／存储与数据／安全与审计）再分区页签（6 处）；单分区组（维护与支持）无二级页签行，组点击即直达。
  - 模型关联弹窗 supported 由异步接口回填，先等终态元素再断言一致性（消除初始 loading 态竞态）。
  - 套装取消链路为三层互斥弹窗（许可确认 → 安装向导 → 套装详情），逐层 Escape 后再断言无弹窗。
  - 模型中心统计条断言「每 3 秒自动刷新」→「实时扫描」；任务中心「已完成」断言限定到 index.html 任务行内（避开状态筛选下拉的隐藏 option）。
  - ComfyUI 实机链路：GPU 下拉选项来自硬件轮询（非看板页 60 秒一轮），改为 `state:'attached'` 等待注入后再选择——修复对话框挂载瞬间空列表把 gpu 锁定为 -1（仅 CPU）导致 ComfyUI 崩溃循环的竞态。

## 已知问题与风险

- 习惯弹窗内逛市场的用户需要适应新入口（弹窗文案已引导）。
- **待评估（UX 不一致）**：新建实例对话框把无 `flowpilot.kind=comfyui` 标签的镜像（如 comfyui-h3:spark、在线拉取的镜像）列为候选，提交后却被 0.0.9.10 供应链可信校验 400 拒绝。候选列表与信任校验口径不一致，建议下版本在候选项上标注「未认证」或在 resolve 接口过滤；本次未改动（属既有设计行为，仅报错文案引导）。
- 回归侧实例手工重建时发现：平台容器缺 `--gpus all` 会导致硬件采集 0 卡（nvidia-smi 经 NVIDIA Container Toolkit 注入）；手工部署需对齐 install.sh 的 GPU_ARGS。
