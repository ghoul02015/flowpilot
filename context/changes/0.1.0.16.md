# 0.1.0.16 变更记录

- 日期：2026-11-17
- 类型：部署／功能／文档／测试／发布
- 需求来源：原生物理机一键部署、国内外网络适配、断点续装、安全卸载、中英双语文档及 GitHub 正式发布

## 背景与目标

既有生产安装脚本把 FlowPilot 管理服务自身打包为 Docker 容器。用户要求管理平台轻量化、直接运行在物理机，同时保留现有 ComfyUI 实例管理能力，并提供完整向导、环境预检、镜像回退、终端中断恢复、后台安装、日志、默认账号设置和同脚本卸载。

经用户明确选择，本版本采用以下边界：管理服务由 systemd 原生运行，ComfyUI 实例继续由 Docker 管理；系统级安装到 `/opt/flowpilot`；管理员为 `admin`，密码在安装时设置；完成安全与测试门槛后公开 `ghoul02015/flowpilot` 并发布 `v0.1.0.16`，沿用 Apache-2.0。

## 新增内容

### 原生统一安装器

新增 `code/scripts/flowpilot-native.sh`，同一入口支持：

- `install`：交互式向导和非交互安装；默认端口 `18080`，默认账号 `admin`。
- `resume`：复用配置、阶段状态和 `.part` 下载分片，使用 HTTP Range 续传。
- `status`：查看原生服务、目录、端口和后台安装 worker。
- `uninstall`：默认保留业务数据；`--purge` 永久清理；`--remove-instances` 可选删除带 `flowpilot.instance=true` 标签的容器。
- 驱动检查：NVIDIA 驱动、GPU、NVIDIA Container Runtime；无驱动时必须显式确认 CPU 模式，不自动修改驱动。
- 环境检查：Ubuntu／Debian、systemd、amd64／arm64、磁盘、端口、Docker Engine／Socket、防火墙提示。
- 网络检查：GitHub 官方地址、DNS、代理状态（不输出代理 URL）和镜像可达性。
- 网络策略：`auto`、`cn`、`global`，支持自定义 `--mirror` 和标准 HTTPS 代理；内置 ghfast.top、gh-proxy.com、ghproxy.net 回退。
- 下载安全：Release `SHA256SUMS` 强制校验、tar 路径穿越检查、部分文件续传。
- 后台安装：`nohup`＋`setsid` 独立会话，记录 worker PID；前台中断后可续装；flock 防止并发安装。
- 日志：每次安装／卸载独立完整日志，`latest.log` 软链接，服务同时写 `service.log` 和 journald。
- 账号初始化：通过本机 API 创建 `admin`，密码隐藏输入、二次确认，或以 `0600` 密码文件／随机密码用于无人值守；密码不写入命令行、systemd 环境或日志。
- systemd：`flowpilot` 低权限系统用户、Docker Socket 组权限、开机自启、失败重启、健康门和旧 release 软链接回滚。
- 升级：停止服务后备份 SQLite 及 WAL／SHM，保留旧 release，健康失败切回旧版本。

### 双架构原生发行包

新增 `code/scripts/package-native-release.sh`：

- 使用锁文件构建前端，使用 Go 交叉编译 `CGO_ENABLED=0` 的 Linux amd64／arm64 单文件。
- 目标机无需 Go、Node.js、Python、Nginx 或 Docker Compose。
- 包内含原生服务、前端、安装器、中英文手册和 LICENSE／NOTICE／第三方声明。
- 生成独立安装器、两个 tar.gz 和统一 `SHA256SUMS`。
- 构建期支持 npm／Go Proxy 国内镜像及显式覆盖。

## 修改内容

- 根 README 改为原生部署优先，保留旧容器化安装路径，修正“当前版本没有认证”的过期描述。
- 项目版本从 `0.1.0.15` 推进到 `0.1.0.16`，同步 VERSION、后端健康版本、前端 package／lock、界面回退版本、验证脚本及既有 Docker 脚本。
- `PROJECT_RULES.md` 当前版本同步更新。
- 修复安装器读取 `/etc/os-release` 时 Ubuntu `VERSION` 变量覆盖产品版本的问题：改为子进程读取 OS 信息，并纳入真实 Ubuntu 集成回归。
- 修复后台 worker 未继承离线包／离线目录的问题：续装配置显式保存非敏感来源路径，覆盖“本地包＋后台＋resume”与“离线目录＋后台重装”。
- 修复前台转后台时 worker 重新打开 flock 锁文件、与尚未退出的前台冲突的问题：worker 改为继承同一打开文件描述符，前台退出后继续持有防并发锁；该问题由 arm64 集成测试实际发现。
- 修复后台完成标记早于锁释放的问题：worker 现在先显式释放 flock、关闭锁描述符，再写 `complete.done`，保证调用方看到完成状态后可以立即安全执行下一次 `resume` 或卸载。
- 修复通过 `/usr/local/bin/flowpilot-native` 幂等复装时，源路径经软链接指向目标自身而导致 `cp` 失败的问题：使用 `-ef` 判断同文件并直接复用已安装入口。
- 增强彻底卸载对安装器新建系统用户的清理：停止服务后最多重试五次 `userdel`，保留真实错误日志，最终仍失败则明确返回失败。
- 修正集成测试对系统用户的错误假设：arm64 底镜像预置 `flowpilot` 用户，必须验证卸载后保留；amd64 Ubuntu 无预置用户，必须验证安装器新建用户被删除。预置账户不触发 `userdel` 是产品的数据与账户保护行为，不是卸载缺陷。

## 行为与兼容性影响

- 新原生部署使用 `/var/lib/flowpilot` 作为数据根目录，`FLOWPILOT_HOST_ROOT=/`、`FLOWPILOT_HOST_GATEWAY=127.0.0.1`，与容器内路径约定明确区分。
- ComfyUI 实例仍依赖 Docker；本版本不是“全面去 Docker”的实例运行时重构。
- 原 Docker 部署脚本继续可用，但版本号同步为 0.1.0.16。
- 默认卸载不删除模型、工作流、输出、数据库或 ComfyUI 容器；只有显式 `--purge`／`--remove-instances` 才执行相应破坏性操作。
- 服务未内置 TLS，仍仅限受信任管理网络；Docker Socket 权限等同较高 Docker 管理权限。

## 已知问题与风险

- 第三方 GitHub 镜像可用性随网络变化，因此仅作为回退通道，并强制 SHA256 校验；正式仓库仍是发布事实源。
- 安装器不自动更换 NVIDIA 驱动或 NVIDIA Container Toolkit，避免影响物理机其他业务。
- `--purge` 和 `--remove-instances` 为不可逆操作，必须显式确认。
- 尚未在真实 systemd PID 1 和 DGX Spark GPU 环境验证本版本；systemd 单元已生成，但隔离测试使用管理 shim 启停真实进程。

## 回滚说明

- 原生升级健康门失败自动把 `current` 切回旧 release 并尝试重启。
- 涉及数据库向前迁移时，停止服务后同时恢复 `backups/pre-upgrade-*` 数据库及对应 WAL／SHM。
- 代码回滚使用 Git 历史中的上一版本，不强推、不改写公开历史。
