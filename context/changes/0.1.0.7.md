# 0.1.0.7 性能与请求治理

- 版本：0.1.0.7
- 日期：2026-11-13
- 依据：`docs/0.1.0.7-0.1.0.8开发规划与排期.md` 第一部分
- 范围：前端轮询与取消、任务摘要、模型分层缓存、硬件采集合并；不修改任务状态机、实例健康状态机与数据库 schema

## 一、目标与边界

本版只解决“固定周期、全局全量轮询；模型与硬件采集重复；慢请求可能重叠”，不新增业务功能。

明确不做：WebSocket、前端状态框架、schema 变更、模型内容 hash 扫描、镜像任务体系重建、工作流编辑器。

## 二、统一轮询机制

新增 `src/hooks/use-polling.ts`：

- 递归 `setTimeout`，上一次请求结束后才安排下一次，杜绝裸 `setInterval` 重叠；
- 支持 `enabled`、活跃／空闲周期、立即执行、手动 `refresh()`、`stop()`；
- 页面隐藏时清理计时器并中止进行中请求，恢复可见立即刷新并重置退避；
- 请求带 `AbortSignal`；主动取消不当作错误，不回写过期响应；
- 失败按 3／5／10／30／60 秒退避；
- 同一数据源同一时间最多一个自动请求，手动刷新先取消旧请求。

新增 `src/lib/refresh-events.ts`：只广播“哪些数据过期”，不存储数据。业务写操作后由调用方发出主题，订阅方各自刷新。

`src/api.ts` 增加 `withTimeout()`，把调用方取消信号与单请求超时合并；轮询相关接口补齐可选 `signal`。

## 四、后端改造

### 1. 任务摘要

新增 `GET /api/v1/tasks/summary`：

```json
{"counts":{"queued":0,"running":1,"paused":0,"succeeded":3,"failed":0,"cancelled":0},"total":4,"active":1,"updatedAt":"..."}
```

- 与统一任务列表复用同一聚合函数 `collectTaskViews`，保证角标与列表同源；
- 不返回任务明细、日志或镜像输出；
- 不新增表、不改变 schema。

### 2. 模型分层缓存

`internal/model` 从“2 秒整体缓存”改为本地／网络独立缓存：

- 本地 TTL 60 秒，网络 TTL 120 秒；
- 每个来源独立锁与单飞：并发读取共享同一次扫描；
- 失败保留上次成功结果并标记 `stale`／`error`，不回退成空数组；
- 本地错误只影响本地状态；NAS 失败不合并网络文件，避免把旧数据当成可读；
- 删除、下载完成、导入完成只失效本地缓存；NAS 配置变化只失效网络缓存；
- 返回 `local`／`network` 状态：`root`、`available`、`scannedAt`、`stale`、`error`。

下载引擎新增 `SetOnFinish` 回调，任务成功写入仓库后立即调用 `InvalidateLocal()`，避免页面等 60 秒才看到新文件。

### 3. 硬件采集合并与负缓存

- 2 秒短时缓存 + 单飞，并发请求共享一次采集；
- `nvidia-smi` 不存在等持续错误使用 60 秒负缓存，避免每次刷新重复执行失败命令；
- 临时失败与命令缺失分开处理；负缓存到期后自动重试；
- GPU 子项失败不影响主机、CPU、内存、存储指标。

## 五、页面显示补充

模型页读取新的来源状态，可区分本地／NAS 的可用性与过期信息；下载任务由活跃转为完成（或出现新的已完成任务）时，立即失效模型列表。

## 七、已知边界

- 本机无 GPU、无 NAS、无 5000 文件级模型库；S2／S3 只有单元测试，未做环境实测。
- 请求数下降比例未做浏览器级 10 分钟计数（缺少可复用的登录脚本执行环境），以代码路径与页面启用条件说明代替，不以估计值冒充实测。
- 任务摘要为内存与 SQL 混合聚合（与列表现有实现同源），不是单条 SQL。
