# 0.0.6.3 — 2026-11-08（搜索习惯优化：重试加固＋模糊变体＋仓库直达）

## 背景

周董实测反馈：在 ModelScope 源搜「nvfp4」显示「未找到相关仓库」，并要求从用户搜索习惯出发认真评估是否需要模糊搜索。

## 评估过程与结论

Mac 直连 curl 实测 ModelScope 搜索接口（PUT /api/v1/dolphin/models）：

| 关键词 | 结果 |
| --- | --- |
| nvfp4 | 1106 条，正常 |
| fp8 / GGUF / wan2.1 | 正常 |
| minmax（错别字） | 13 条，容错良好 |
| 视频生成（中文） | 4408 条 |

结论：源站搜索本身大小写不敏感、容错良好；空结果的真实原因是风控间歇返回 Code=200 空列表，0.0.6.2 的单次 600ms 重试未覆盖更长的风控窗口。

**否决方案**：「输入即搜」防抖自动搜索——风控敏感，频繁请求更容易触发限流；保留手动触发＋回车。

## 修改内容

### 后端（code/backend）

- `internal/catalog/online.go`
  - 新增 `OnlineSearchResult{Results, Attempts}`，`SearchOnline` 返回完整响应。
  - `searchWithRetry`：原词空结果最多重试 2 次（600ms／1500ms 退避）。
  - `queryVariants`：去版本后缀（正则 `(?i)(?:[-_ ][a-z]?|v?)\d[\d.]*[a-z]?$`，字母前缀仅在分隔符后剥除，避免误伤 Wan2.1→Wa）、分隔符归一为空格、小写化，最多 3 个、按小写去重。
  - `ParseRepoRef`：识别 `org/name`（源由当前选择决定）与 modelscope.cn（/models/org/name）／huggingface.co／hf-mirror.com（/org/name）URL。
- `internal/server/server.go`：`onlineSearch` 直接输出完整 `OnlineSearchResult`；ctx 超时 20s→25s。
- `internal/catalog/online_test.go`：既有用例适配新返回类型；新增 `TestSearchOnlineRetryThenVariant`（请求计数断言重试 3 次＋变体命中）、`TestSearchOnlineAllEmpty`、`TestQueryVariants`、`TestParseRepoRef`。

### 前端（code/frontend）

- `src/api.ts`：`searchOnlineModels` 返回 `OnlineSearchResult{results, attempts}`。
- `src/components/AddModelDialog.tsx`
  - 新增 `parseRepoRef`（与后端对齐的 TS 实现）：命中直达时构造单条结果、跳过搜索接口、自动展开文件列表；URL 指向另一源时自动切换源标签；仓库不存在时提示确认链接。
  - `attempts` state：扩展搜索时展示「原关键词未命中，已自动扩展搜索：…」；空结果提示列出全部尝试过的关键词。
  - 空态与页脚文案更新：提示可粘贴仓库名／源站链接直达，说明自动重试与模糊变体机制。

### 回归脚本（code/frontend/scripts/verify-demo.mjs）

新增两项断言：
- 「短关键词搜索命中＋attempts 透明化（nvfp4）」：接口级验证 results 非空且 attempts[0]=nvfp4。
- 「仓库名直达（跳过搜索直接展开文件列表）」：界面填入 `Comfy-Org/MiniMax-H3` 后不经搜索直接出现权重文件。

## 验证

- Go 九包 gofmt＋test＋vet 通过（首轮失败暴露版本后缀正则误伤：MiniMax-H3→MiniMax-H、GGUF 小写变体被去重跳过，修正后全绿）。
- 前端 lint／build 通过。
- DGX Spark 实机全量回归（结果见当日对话记录）。

## 风险

- 风控空响应与真空结果无法区分：attempts 透明化＋文案引导为兜底。
- 最坏路径耗时：3 次重试（2.1s 等待）＋变体请求可能超 25s ctx，由 context 收口；前端 30s 超时大于后端。
