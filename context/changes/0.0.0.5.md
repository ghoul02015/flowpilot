# 0.0.0.5 变更记录

- 日期：2026-11-07
- 类型：功能／部署／测试
- 需求来源：周董要求把 DGX Spark 的 nvidia-smi 与统一内存指标接入真实 `/api/v1/hardware` 接口，替换 Demo 遥测，并以 Spark 实机联调

## 背景与目标

0.0.0.4 的首页硬件监控全部为 Demo 模拟数据。本轮目标：后端真实采集宿主机硬件与 GPU 指标，前端采集成功即显示真实面板，失败回退 Demo；在 DGX Spark（`192.168.0.77`）实机验证。

## 新增内容

- `code/backend/internal/hardware/hardware.go`：纯标准库硬件采集器。
  - nvidia-smi CSV（`--format=csv,noheader,nounits`）解析：型号、显存、利用率、温度、功耗、功耗上限；`[N/A]` 解析为 `null`。
  - 统一内存识别：任一 GPU 显存字段为 `null` 即判定 `gpuMemoryMode=unified`。
  - `/proc/cpuinfo`、`/proc/meminfo`、`/proc/stat`（两次采样差值算利用率，首次返回 `null`）、`syscall.Statfs` 数据盘用量。
  - 宿主机主机名与系统版本经只读挂载 `/host/etc/` 读取（容器内 `/proc` 与 `/etc` 是容器自身视图）。
  - 任一子项失败只影响对应字段，GPU 不可用时返回 `gpuAvailable=false` 与 `gpuError`。
- `GET /api/v1/hardware` 路由；采集器未配置时返回 503。
- 单元测试 8 个用例：GB10 统一内存解析、双卡 L40S 解析、畸形行拒绝、主机基础信息、discrete 模式、GPU 失败降级、CPU 利用率差值、ARM 型号回退。
- 前端 `api.ts` 新增 `HardwareReport` 类型与 `getHardware()`。
- 前端 `HardwareMonitor` 重写数据流：2 秒轮询真实接口，成功显示"本机实测"面板并隐藏演示机型选择器；失败回退 Demo 并标注"硬件接口不可用"；`GpuDevice` 遥测字段支持 `null`，不可用指标显示"—"；无 GPU 时显示空态说明。
- 安装脚本 GPU 透传：检测 NVIDIA Container Toolkit，有则 `--gpus all`；无则手动挂载宿主机 nvidia-smi 二进制、`libnvidia-ml.so.1`（含 `LD_LIBRARY_PATH`）和全部 `/dev/nvidia*` 设备；无 GPU 主机跳过并提示。
- 回归脚本新增分支：`/api/v1/hardware` 可用且有 GPU 时断言真实面板（`data-hardware-source="real"`、宿主机名、统一内存提示），否则走原 Demo 断言。

## 修改内容

- 一体化镜像运行基底 `alpine:3.22` → `ubuntu:24.04`：宿主机 nvidia-smi（含 Container Toolkit 注入的二进制）按 glibc 2.39 链接，Alpine（musl）无法执行；健康检查改用 curl。
- 容器新增挂载：`${INSTALL_HOME}/shared:/data/flowpilot`、`/etc/hostname:/host/etc/hostname:ro`、`/etc/os-release:/host/etc/os-release:ro`；新增环境变量 `FLOWPILOT_DATA_DIR`、`FLOWPILOT_HOST_ROOT`。
- `server.New` 增加硬件采集器参数，`main.go` 支持 `FLOWPILOT_PROC_ROOT`／`FLOWPILOT_NVIDIA_SMI` 等环境变量。
- 版本统一升级为 `0.0.0.5`（`VERSION`、前后端、脚本、回归断言、文档）。

## 行为与兼容性影响

- 离线发布包由约 6.7 MB 增至约 33 MB（Ubuntu 基底），仍远小于常规 GPU 管理组件。
- 接口为新增，不改动既有 API；旧版卸载脚本对新容器同样适用（标签机制不变）。
- 无 NVIDIA Container Toolkit 的主机走手动挂载路径；两条路径都要求宿主机存在 nvidia-smi，否则 GPU 区块降级为空态，主机指标正常。
- macOS 本机 Demo 无 nvidia-smi，硬件面板显示主机真实指标＋GPU 空态（不再默认显示 Demo 机型）；如需查看演示机型，可在硬件接口不可用时自动回退。

## 已知问题与风险

- GB10 的 `/proc/cpuinfo` 无型号字段，CPU 型号显示为"ARM64 处理器"；后续可通过设备树或 DMI 信息补强。
- CPU 利用率为两次请求间差值，首次请求返回 `null`（前端显示"采样中"）。
- 手动挂载路径未覆盖 NVIDIA 驱动库的非标准安装位置；遇到时以 `gpuError` 形式暴露，不影响主流程。
- 容器内 nvidia-smi 采集的是整卡指标，不含 per-container 粒度。
