# 0.0.9.3 变更记录

- 日期：2026-11-10
- 类型：功能（模型中心第二批）
- 需求来源：周董指令「启动第二批（僵尸模型检测、重复检测、批量操作）。自动部署后测试」。

## 背景与目标

0.0.9.2 完成 NAS 直挂＋分组视图后，生产环境模型数量持续增长，需要低成本的仓库治理能力：

1. 僵尸模型检测：找出长期未更新的大文件，辅助清理决策。
2. 重复模型检测：找出跨目录同名同大小的冗余副本。
3. 批量操作：批量删除（本地）、批量本地化（网络），减少逐个点击。

## 新增内容（全部在前端，无后端改动）

- 僵尸检测（`Models.tsx`）：`origin==='local'` 且体积 > 1 GB 且 `modifiedAt` 早于 30 天前 → 行内「疑似闲置」徽章（amber，title 附阈值说明）。判定基于 `/api/v1/models` 已有的 `modifiedAt` 字段，新增 `ModelItem.modifiedRaw` 承载 ISO 原始值。
- 重复检测（`Models.tsx`）：ready 状态的仓库文件按「名称|大小」分组计数，>1 即标记「重复×N」（rose）。
- 筛选 chips：「仅看疑似闲置」「仅看重复」切换按钮，与搜索/类型筛选/排序组合生效。
- 批量操作：
  - 仓库文件行（有 origin 的本地/网络文件）行首复选框；下载任务行不可选。
  - 选中非空时显示工具条：「已选 N 个 · 批量本地化（仅网络）· 批量删除（仅本地）· 取消选择」，按钮按所选构成自动计数/禁用。
  - 批量删除独立确认对话框，保留运行中实例保护（列出实例名）；`App.tsx` 新增 `batchDeleteModels`（Promise.allSettled 逐个调删除接口，汇总 toast）与 `batchLocalizeModels`（复用导入引擎）。
  - 勾选状态派生修剪：仓库刷新后已消失的 id 自动失效，不进入批量范围。

## 已知问题与风险

- 僵尸判定基于文件 mtime：导入/本地化会刷新 mtime，符合"最近入库不算闲置"的直觉；阈值（30 天 / 1 GB）为前端常量，后续可按需做成可配置。
- 重复判定用「名称＋大小」启发式，不做内容哈希（大文件哈希成本高）；同名不同大小不判重。
