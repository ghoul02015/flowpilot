## 问题分析

0.0.7.3 为 ComfyUI 镜像增加了构建参数 Labels，用于镜像清单展示参数简述：

- `flowpilot.kind=comfyui`
- `flowpilot.build.variant`
- `flowpilot.build.gpu`
- `flowpilot.build.cuda`
- `flowpilot.build.platform`
- `flowpilot.comfyui.ref`
- `flowpilot.comfyui.manager`
- `flowpilot.build.summary`

在 Go 原始字符串模板中，`LABEL` 多行续行符误写为 `\\`。原始字符串不会转义反斜杠，因此最终 Dockerfile 输出了两个反斜杠：

```Dockerfile
LABEL org.opencontainers.image.title="ComfyUI" \\
      flowpilot.kind="comfyui" \\
```

Dockerfile 解析时把第二个反斜杠所在内容识别为一个不符合 `name=value` 的标签片段，导致 Docker Engine 报错：

```text
failed to parse Dockerfile: Syntax error - can't find = in "\\\\". Must be of the form: name=value
```

该问题会同时影响：

1. Web 后台手动构建。
2. 下载的一键构建脚本。

因为二者共用 `BuildDockerfile` 模板。

## 修复内容

- 修复 `code/backend/internal/image/image.go` 中 `buildLabels` 的 Dockerfile `LABEL` 多行续行符，将 Go 原始字符串里的双反斜杠改为单反斜杠。
- 保留全部构建参数 Labels 与参数简述，不回退 0.0.7.3 的 UI/功能。
- 新增 cu128/linux-amd64 场景回归测试：
  - `TestBuildDockerfileLabelContinuation`
  - `TestBuildScriptIncludesParsableDockerfileLabel`
- 测试覆盖：
  - Dockerfile 不再包含 `\\` 双续行符。
  - Dockerfile 仍包含 `flowpilot.build.platform="linux/amd64"`。
  - Dockerfile 仍包含 `flowpilot.build.summary`。
  - 一键构建脚本仍包含 `--platform 'linux/amd64'`。
