# 0.0.0.6 变更记录

- 日期：2026-11-08
- 类型：修复／测试
- 需求来源：周董要求整体评测测试小 bug、正确修复并部署实例验证

## 背景与目标

0.0.0.5 接入真实硬件采集后，对前后端、脚本做一轮整体评审，修复发现的小缺陷，升级 `0.0.0.6` 并在 DGX Spark 实例上回归验证。

## 评审发现的缺陷与修复

| # | 缺陷 | 修复 |
|---|---|---|
| 1 | `src/pages/Home.tsx` 为 Vite 脚手架死代码（连同仅被它引用的 `App.css`） | 删除两个文件 |
| 2 | 硬件面板内存／存储／GPU 内存百分比在总量为 0（采集失败）时产生 NaN | 统一 `safePercent` 防除零 |
| 3 | `getHardware` 每 2 秒轮询但无超时，请求挂起会堆积 | 增加 `AbortSignal.timeout(4000)` |
| 4 | 后端 CPU 利用率依赖两次 `/proc/stat` 差值，计数器抖动可能产生负值或超 100% | 钳制 0–100，新增回归用例 |
| 5 | 侧栏、页头写死"慧浪 GPU-S01 · 2 × NVIDIA L40S"，真实模式下显示错误主机信息 | App 启动时拉取 `/api/v1/hardware`，真实可用时显示真实主机名与 GPU 概要，失败保持默认文案 |
| 6 | 系统页"主机环境报告"标题与诊断导出 `host` 字段写死演示主机名 | 改用真实 Docker `info.Name`，回退演示文案 |
| 7 | 系统页"GPU 等硬件项仍为 Demo 数据"文案已过时 | 更正为硬件由 `/api/v1/hardware` 实时采集 |
| 8 | GB10 的 `/proc/cpuinfo` 无型号字段，CPU 只显示"ARM64 处理器"；实测 `/proc/device-tree/model` 为空，但 DMI 有 `NVIDIA_DGX_Spark` | Report 新增 `machineModel`（DMI `product_name`，下划线转空格）；安装脚本存在该文件时才只读挂载；前端真实面板显示"NVIDIA DGX Spark · 实时采集" |
| 9 | 回归脚本缺少机型信息断言 | 真实分支增加 `machineModel` 展示断言 |
