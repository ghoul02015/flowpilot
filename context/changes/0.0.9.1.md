# 0.0.9.1 变更记录

- 日期：2026-11-10
- 类型：修复（代码审查）
- 需求来源：周董要求对当前版本做专注代码审查，发现 bug 则修复并更新小版本号。

## 背景与目标

0.0.9.0 全量落地评审清单后，对本轮改动涉及的后端（instance、image/tasks、server）与前端（App、Instances、ImageManager、CreateInstanceDialog、AddModelDialog、Tasks、common、api）逐文件审查，目标是发现真实 bug 而非风格问题。

## 审查结论与修复

### 1. 镜像构建任务数据竞争（真 bug）

- 位置：`code/backend/internal/image/tasks.go` `runBuild`。
- 问题：记录被覆盖旧镜像 ID 时 `task.oldID = oldID` 未持锁写入，而 `List()`/`Get()`/`saveLocked()` 均在 `m.mu` 锁内读取任务字段，构建 goroutine 与 HTTP 读请求并发时构成数据竞争。
- 修复：写入改为持锁（`m.mu.Lock()`）。

### 2. 构建/拉取日志弹窗突然关闭（交互缺陷）

- 位置：`code/frontend/src/components/ImageManager.tsx`。
- 问题：日志弹窗按 `logsTaskId` 从任务列表实时查找；成功任务入库后记录会被后端自动清理（15 秒惰性扫描），用户正在查看日志时记录消失、弹窗闪关。
- 修复：新增 `logsSnapshot` 状态，打开日志时保存任务快照；实时记录消失后回退快照，弹窗与完整日志保持可看，关闭时一并清理。

### 3. 实例操作双击穿透（交互缺陷）

- 位置：`code/frontend/src/App.tsx` `instanceAction`。
- 问题：`busyIds.includes(id)` 基于渲染快照，同一帧内双击可绕过禁用重复提交启停请求。
- 修复：新增 `busyRef`（`useRef<Set<string>>`）同步判断与登记，state 仍用于驱动按钮禁用样式。

### 4. 新建实例默认端口 fallback 撞车（边界缺陷）

- 位置：`code/frontend/src/components/CreateInstanceDialog.tsx` `suggestPort`。
- 问题：8188–8287 全占时旧 fallback `8188 + instances.length` 可能撞上已有实例端口。
- 修复：扫描范围扩展为 8188–65535，保证返回的必然未被实例占用（宿主机其他服务占用仍由 0.0.9.0 的后端真实监听探测兜底）。
