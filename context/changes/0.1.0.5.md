# 0.1.0.5 模型许可按模型确认与界面调整

- 版本：0.1.0.5
- 日期：2026-11-12
- 依据：`模型中心授权.md`（v1.0）
- 范围：模型中心卡片、详情、安装确认弹窗、许可文件交付、确认记录；另修 0.1.0.4 套装任务失败缺陷

## 一、起因

### 1. 中午的套装任务失败

Spark 任务中心有一条失败记录：

```
bundle-bundle-1794464289531807636  failed
创建下载任务失败：已有目标为 diffusion_models/minimax_h3_image_pruned_int8_convrot.safetensors 的任务在进行中
```

排查确认是 0.1.0.4 的真实缺陷，不是外部网络问题：

1. `Pause`／`Cancel` 先调用 `stopWorker`，而 `stopWorker` 会删除 `current[installID]`；
2. 随后才读取 `currentTask(installID)`，拿到的永远是空字符串；
3. 子下载任务因此从未被暂停或取消，继续在后台下载；
4. 平台重启把运行中的下载标记为 `paused`；
5. 下一次安装创建同目标任务时被 `已有目标…在进行中` 拒绝，整个计划立即失败。

0.1.0.4 末尾补的 `FindByTarget` 复用逻辑只解决了“能不能继续”，没有解决“为什么会有残留任务”。

**修复：**

- 新增 `takeWorker`：在注销 worker、清理 `current` 之前先取出子任务 ID；
- 新增 `stopAndSettleChild`：除内存中的当前任务外，按安装项快照补一遍 `downloading` 项的 `child_task_id`，确保没有任务被遗留；
- 复用残留任务时增加 SHA256 校验：同名文件但目标哈希不同（跨清单版本）必须先取消并删除旧任务，避免复用错误内容；
- 统一任务 ID 去掉 `bundle-bundle-` 双前缀，并让详情／删除兼容历史 ID。

回归测试 `TestStopWorkerSettlesChildDownload` 覆盖暂停与取消两条路径；修复前该用例必然失败。

### 2. 许可 UI 与授权文档不一致

0.1.0.4 的许可是“套装级”、文案较长、状态只显示“待法务审核”，与 `模型中心授权.md` 的目标不一致：
商业界面需展示完整模型名、安装前确认、勾选闸门、官方与本地许可入口、按模型区分条款。

## 二、许可数据模型

### 1. 清单从“套装内嵌许可”改为“模型级许可”

`bundles.json` 新增顶层 `licenses`，键为模型名；套装只保留 `modelName` 引用：

| 模型 | 许可版本 | 年收入门槛 | NOTICE |
| --- | --- | --- | --- |
| MiniMax-H3-Image | 2026-11-10 | 100 万美元，或提供 Hosted Service | H3-Image 专属声明 |
| MiniMax-H3 | 2026-08-02 | 2000 万美元 | H3 专属声明 |

两份许可均取自官方仓库 `MiniMaxAI/*` 的 LICENSE 原文，不是摘要或改写：

- H3-Image：18,208 字节，SHA256 固定
- H3：17,604 字节，SHA256 固定

加载时校验内置文件哈希与 NOTICE 文本，防止“只改版本号不改文件”。

**校验规则新增：**

- 套装引用的模型必须配置许可，否则拒绝启动；
- 不同模型不得共用同一许可版本（防止把 H3-Image 条款复制给 H3）；
- 许可版本必须是 `YYYY-MM-DD`；
- `LICENSE`／`NOTICE` 必须位于 `licenses/` 下且哈希匹配。

### 2. 确认记录改为“模型 + 许可版本”

迁移 **Version 6 `model-license-confirmations`**：

- 新表 `model_license_confirmations`，唯一键 `(org, model_name, license_version)`；
- 记录组织、模型、许可版本、许可名称、官方地址、套餐、交付方式、确认人、部署环境、确认时间；
- 回填 0.1.0.4 的套装级确认：`h3-image-*` 映射到 `MiniMax-H3-Image` / `2026-11-10`，其余映射到 `MiniMax-H3` / `2026-08-02`。

效果：S1 确认一次后，S2 不再弹窗；S3～S5 使用 MiniMax-H3，必须单独确认。

## 六、边界

- 确认记录只代表部署方已阅读并自行确认，不代表平台授予商业授权或完成法务审核。
- 组织／租户固定为 `default`：当前平台是单租户部署，未引入多租户模型。
- 存量实例的“查看并确认”入口属于第二批，本版未做。
- 工作流模板名仍未与官方模板包核对；模板包版本也未写入镜像标签，镜像预检保持 `unknown`。
