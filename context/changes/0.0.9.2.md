# 0.0.9.2 变更记录

- 日期：2026-11-10
- 类型：功能（模型中心生产化）
- 需求来源：周董确认的 0.0.9.2 优化方案——方案 B（NAS 直挂只读＋按需本地化）、第一批范围照提案执行、僵尸/重复/批量检测留第二批。

## 背景与目标

面向生产环境模型数量多、多机维护复杂的场景：

1. 网络存储（NAS）一份模型全集群可用，实例免拷贝使用。
2. 模型中心在大文件量下保持可扫读（分组、统计、排序）。
3. 为集群维护打地基（清单带 node 字段预留）。

## 新增内容

- `code/backend/internal/storage/`（新包）：网络存储配置管理
  - 配置持久化 `<dataDir>/network-storage.json`（原子写）；校验白名单（类型 nfs/smb、地址主机名/IP、远端路径防穿越防注入）。
  - 挂载探测：挂载脚本在仓库根写入 `.flowpilot-nas` 标记，平台以标记判定生效（区分"未挂载"与"挂载但为空目录"）。
  - 挂载脚本生成：安装 nfs-common/cifs-utils、只读挂载、/etc/fstab 开机挂载、写标记、重启平台容器（bind 挂载传播限制下必需）；SMB 需用户自备 `~/.smbcredentials`。
  - `WriteExtraModelPaths(name, basePath)`：按实例生成 extra_model_paths.yaml（base_path 指向实例内 models-net），映射 ComfyUI folder_paths 支持的全部目录类别，**不含 custom_nodes**（网络仓库不注入可执行代码）；实例删除时清理。
- 实例网络挂载（`internal/instance`）：`SetNetworkStorage` 注册钩子；启用且已挂载时，Create 追加 `<hostDataDir>/network → <base>/models-net:ro` 与 `<name>.yaml → <base>/extra_model_paths.yaml:ro` 两个 bind（base = modelsTarget 父目录）；Delete 清理 yaml。
- 双仓库扫描（`internal/model`）：`SetNetworkSource` 注册来源；Report 合并本地＋网络文件（`origin`、`node:"本机"`），网络仓库抖动仅标记 `network.available=false` 不影响本地扫描；`TotalBytes` 只统计本地仓库。
- 本地化复用导入引擎：网络仓库容器路径加入导入白名单（`FLOWPILOT_IMPORT_DIRS` 追加），「本地化」即 kind=import 任务化复制（进度、暂停、校验一致）。
- 接口：`GET/PUT /api/v1/storage/network`、`GET /api/v1/storage/network/mount-script`；`/api/v1/models` 增加 origin/node/network 字段（向后兼容）。

- `System.tsx`：新增「网络存储」tab，承载 `NetworkStoragePanel`（配置表单＋状态提示＋挂载脚本下载＋工作原理说明）。
- `AddModelDialog.tsx` 市场面板：推荐目录条目卡片化（单行层级：名称＋类型＋大小·可达性＋下载/已入库，描述收起一行，HF 备选降为文字链）；在线源文件按类别分组、组内大小降序，行内直接显示大小。

- `api.ts`：ModelFile/ModelReport 扩展；新增网络存储接口族。

## 行为与兼容性影响

- 未配置网络存储时行为与 0.0.9.1 完全一致（实例仍 3 个挂载，有回归测试锁定）。

## 已知问题与风险

- 挂载生效依赖管理员在宿主机执行一次脚本并重启平台容器（bind 传播限制，脚本已自动完成重启）。
- 实例内 ComfyUI 需支持 extra_model_paths.yaml 自动加载（官方主线支持；极端定制镜像需确认）。
- NAS 直挂首次加载大模型受网络带宽影响（千兆网 GB 级模型约 1–2 分钟）；热点模型请用「本地化」。

## 回滚说明
