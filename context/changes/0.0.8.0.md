# 0.0.8.0 变更记录

- 日期：2026-11-09
- 类型：功能／重构／镜像任务体系
- 需求来源：周董评审 0.0.7.4 后确认的三项决策——A 有界并发+排队（推荐方案）；B 任务记录自动保留 20 条+手动删除；C 不自动清构建缓存、自动清被替换的悬挂镜像、手动清缓存按钮+占用展示；另加构建前磁盘水位检查与任务持久化中断标记。

## 背景与目标

0.0.7.4 及之前，镜像构建/拉取是全局单任务（`Puller` 单字段互斥），存在三类问题：

1. 一个任务网络挂起即卡死全局，且无取消机制，只能重启服务。
2. 服务重启后"进行中"状态永久残留，无法清理。
3. 覆盖同名镜像后旧镜像变 `<none>:<none>` 悬挂镜像，界面不可见但占磁盘；构建缓存只增不减。

## 新增内容

- `code/backend/internal/image/tasks.go`：`Manager` 任务管理器
  - 任务模型：`queued / running / done / error / cancelled / interrupted` 六态，kind 区分 build/pull。
  - 有界并发：最多 2 个构建 + 1 个拉取并行，超出按提交顺序排队；同名镜像（tag 归一化后）活动任务互斥，重复提交返回 `ConflictError`。
  - 停止：排队任务直接取消；进行中任务通过 `context.CancelFunc` 中止 Docker 构建/拉取 HTTP 流；`stopRequested` 标志处理"取消先于 goroutine 注册 cancelFunc"的竞态。
  - 删除：仅已结束任务可删除记录，进行中删除返回校验错误。
  - 持久化：任务记录写入 `<dataDir>/image-tasks.json`（临时文件+rename 原子写）；启动时把遗留 queued/running 标记为 `interrupted`。
  - 自动清理：`List()` 以 15 秒间隔惰性扫描本机镜像，成功（done）且镜像已入库的任务记录自动移除；已结束记录整体保留最新 20 条。
  - 悬挂镜像清理：构建前记录同名旧镜像 ID，成功后若旧镜像已无任何有效标签则自动删除并写日志。
  - 磁盘水位：提交构建前 `statfs` 检查数据目录所在盘剩余空间，<15 GB 拒绝并提示；采集失败不阻塞。
- Docker 客户端新能力：`ImageID`、`DiskUsage`（/system/df 汇总镜像与构建缓存）、`PruneBuildCache`（/builds/prune）。
- 前端 `ImageManager` 重构为任务列表模式：
  - 「构建与拉取任务」面板：状态徽章、进度条、日志、停止、删除记录。
  - 构建中/排队中任务以虚拟行进入 ComfyUI 镜像清单（排队中琥珀色、构建中 teal）。
  - 「容器镜像管理」面板新增磁盘占用行（镜像占用/构建缓存）与「清理构建缓存」按钮（二次确认 + 回收空间提示）。

## 行为与兼容性影响

- **接口不兼容变更**：`GET /api/v1/images/build`、`GET /api/v1/images/pull` 移除，旧版前端/脚本调用将收到 404；前端已同步改造。`POST /images/build`、`POST /images/pull` 响应体从单状态对象改为任务对象（含 id/kind/state）。
- 旧版无任务持久化文件，升级后从空任务列表开始，无迁移负担。
- 并发上限为代码常量（构建 2、拉取 1），后续如需可调可提为环境变量。

## 已知问题与风险

- `POST /builds/prune` 依赖 BuildKit；极老版本 Docker（非 BuildKit）会报错并如实提示用户。
- 任务日志不落盘大文件，仅内存环形 500 行＋随任务记录持久化；服务重启后中断任务保留既有日志。
- 拉取任务无百分比（Docker pull 事件流不含总体量），界面展示状态文案与事件流。

## 回滚说明

- 回滚到 0.0.7.4 即恢复单任务模式；`image-tasks.json` 不被旧版读取，可直接删除。不建议回滚后继续使用新版生成的任务记录语义。
