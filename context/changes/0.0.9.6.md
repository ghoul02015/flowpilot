# 0.0.9.6 变更记录

- 日期：2026-11-10
- 类型：功能（认证、安全与操作审计）
- 需求来源：docs/0.1.0.0版本规划.md 四、`0.0.9.6`——认证、安全与操作审计

## 背景与目标

关闭未认证管理 API，形成单管理员安全闭环。默认仍限定受控管理网，不因加入登录就宣称可公网开放。

## 设计冻结（本版范围）

### 认证模型

- 单管理员，用户名固定 `admin`，密码经 Argon2id（`golang.org/x/crypto/argon2`，新依赖）哈希存储（盐 16B、密钥 32B、时间 1、内存 64MB、线程 4，标准参数）。
- 迁移 002 新表：`users(username PK, password_hash, created_at, updated_at)`、`sessions(id PK, username, csrf_token, created_at, last_seen_at, idle_expires_at, absolute_expires_at, revoked, ip_hash, user_agent)`、`audit_logs(id INTEGER PK AUTOINCREMENT, ts, actor, action, object, result, ip_hash, request_id, detail)`。
- 会话：随机 32B ID（hex）；闲置过期 30 分钟、绝对过期 7 天；每次请求滑动续期；注销/改密撤销（改密撤销其他全部会话）。

### 初始化

- `GET /api/v1/auth/setup/status`（永远开放）：`{initialized, tokenRequired}`。
- 令牌：启动时若无用户且 `<dataDir>/init-token` 不存在则生成随机令牌写入（0600）；支持 `FLOWPILOT_INIT_TOKEN` 环境变量注入固定值（demo/E2E 用）。初始化成功后令牌文件删除、不可重放。
- `POST /api/v1/auth/setup`：`{token, password}`；令牌不匹配 3 次锁定。密码最小 8 位含字母数字。

### 中间件与防护

- 认证中间件覆盖 `/api/v1/*`，豁免仅 `GET /api/v1/health`、`/api/v1/auth/setup/status`、`POST /api/v1/auth/setup`、`POST /api/v1/auth/login`。未认证 401 `{error, code:"unauthenticated"}`；未初始化访问业务 API 返回 401 `{code:"setup_required"}`。
- CSRF：写方法（POST/PUT/DELETE/PATCH）要求 `X-FlowPilot-CSRF` 头与会话 csrf_token 匹配（登录/setup 响应返回）；SSE GET 豁免头校验（SameSite=Lax cookie 已防护）。Origin/Host 头存在时必须与请求 Host 一致，否则 403。
- Cookie：`flowpilot_session=<id>`；HttpOnly；SameSite=Lax；Path=/；请求 TLS（`X-Forwarded-Proto=https` 或自身 TLS）时加 Secure。
- 登录限流：每 IP 连续 5 次失败锁定 15 分钟（内存计数，单实例足够）；统一错误文案「用户名或密码错误」。
- 请求体上限：登录/setup JSON ≤ 8KB；既有上传链路不受影响（镜像导入走流式）。
- CORS：默认关闭，无 Access-Control-* 头。

### 审计

- 显式事件：login_success／login_failure（含原因）／logout／password_change／setup_completed／session_revoked。
- 中间件自动记录全部写操作（非 2xx 也记）：method+path、对象（路径参数）、状态、actor、IP 摘要（sha256 前 16 hex）、request_id（随机 8 hex）。
- 审计 API：`GET /api/v1/audit/logs?limit&offset&action&q`（时间倒序，上限 200 条/页）。
- 失败安全：审计写入失败仅记日志，不阻断业务（本版策略；0.0.9.16 复核）。

### API 新增清单

- `GET /api/v1/auth/setup/status`、`POST /api/v1/auth/setup`
- `POST /api/v1/auth/login`、`POST /api/v1/auth/logout`
- `GET /api/v1/auth/session`（当前用户、csrfToken、到期时间）
- `PUT /api/v1/auth/password`
- `GET /api/v1/auth/sessions`、`DELETE /api/v1/auth/sessions/{id}`

### UI

- App 启动先查 setup/status 与 session：未初始化→全屏初始化页；未登录→全屏登录页；已登录→正常布局。
- 顶栏管理员菜单：修改密码（弹窗）、退出登录。
- 系统管理新增「安全与会话」「操作审计」两个子页。
- 401 统一跳登录；写请求从登录响应取 csrfToken 注入头。

### E2E 改造

- demo-docker.sh 启动时注入 `FLOWPILOT_INIT_TOKEN`（固定 demo 值）。
- verify-demo.mjs 全流程改造：setup→login→业务断言→审计断言→改密→退出→登录失效验证。

### 兼容与降级

- `/api/v1/health` 保持无认证（回归镜像实例容器依赖）。
- 数据库不可用时认证不可用：`FLOWPILOT_AUTH_DISABLED=1` 环境变量可显式关闭认证（危险操作需人工确认，默认关闭该开关）。**默认必须认证**。

### 不做

- HTTPS 终端（Caddy/Nginx 示例放文档）；恢复码 CLI；多用户；密码找回（阶段 1 单管理员用 CLI/令牌重置）。

## 行为与兼容性影响

- **破坏性（有意为之）**：全部业务 API 需认证。未初始化访问返回 401 `setup_required`；未登录返回 401 `unauthenticated`；写方法缺 CSRF 头 403 `csrf_required`；Origin 不匹配 403。
- **豁免清单**（永远开放）：`GET /api/v1/health`（回归镜像实例容器依赖）、`GET /api/v1/auth/setup/status`、`POST /api/v1/auth/setup`、`POST /api/v1/auth/login`。
- **SSE 日志流**：GET 请求仅要求会话 Cookie（SameSite=Lax 防护），不要求 CSRF 头。
- **数据目录新增**：`init-token`（初始化后删除）、users/sessions/audit_logs 表（迁移 002）。
- **认证关闭开关**：`FLOWPILOT_AUTH_DISABLED=1` 或 `FLOWPILOT_REGRESS_MODE=1` 显式关闭（默认必须认证）；数据底座故障时认证失败关闭（全部 501/401 拒绝），绝不静默放行。
- E2E 与自动化脚本必须先初始化＋登录并携带 CSRF 头。

## 已知问题与风险

- 审计写入失败当前仅记日志不阻断业务（规划要求危险操作失败关闭——0.0.9.16 RC 阶段复核该策略）。
- 登录限流为单实例内存计数（重启清零）；多副本部署需外置计数（阶段 2 范围）。
- 密码找回不做（阶段 1 单管理员）：忘记密码需删除 users 表记录后用新 init-token 重新初始化（CLI 辅助待 0.0.9.15）。
- `X-Forwarded-For` 直接取第一段作客户端 IP（可信代理场景）；伪造该头可绕过基于 IP 的限流，但凭据校验不受影响。

## 回滚说明

- 回滚到 0.0.9.5：部署旧镜像即可。迁移 002 新表对旧版本无副作用；如已初始化管理员，回滚后认证消失（旧版无认证），建议回滚同时清理 `init-token`。
- 彻底清理：删除 users/sessions/audit_logs 表数据或整个 `flowpilot.db*`。
