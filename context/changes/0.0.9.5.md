# 0.0.9.5 变更记录

- 日期：2026-11-10
- 类型：功能（数据底座与现状基线）
- 需求来源：docs/0.1.0.0版本规划.md 三、`0.0.9.5`——数据底座与现状基线

## 背景与目标

平台自 0.0.0.1 起不维护数据库，实例配置全部存于 Docker 容器标签。随着认证（0.0.9.6）、统一任务（0.0.9.9）、审计与升级回滚的需求推进，需要一个事务性的本地数据底座。本版引入嵌入式 SQLite，将 Docker 标签中的平台事实导入数据库，建立稳定对象 ID 与迁移框架，**不改变普通用户操作流程**。

## 设计冻结（本版范围）

### 技术选型

- 驱动：`modernc.org/sqlite v1.55.0`（纯 Go、免 CGO、go 1.25 兼容、amd64/arm64 可交叉）。这是项目**首个外部依赖**。
- UUID：`github.com/google/uuid v1.6.0`（随驱动引入，直接使用）。
- 数据库文件：`<数据目录>/flowpilot.db`；备份目录：`<数据目录>/backups/`。
- 构建网络：`deploy/web.Dockerfile` 与 `demo-docker.sh` 支持 `GOPROXY`／`NPM_REGISTRY` build-arg 覆盖（受限网络传国内镜像源）。

### Schema（迁移 001：core-tables）

- `schema_migrations(version PK, name, checksum, applied_at, result)`：迁移执行器按版本序执行；已应用迁移校验 checksum（sha256 of SQL），篡改即拒绝（不静默跳过或覆盖）。
- `instances(uuid PK, name UNIQUE, container_id, container_name, image, gpu, port, container_port, auto_start, models_target, outputs_target, workflows_target, model_links, status, created_at, updated_at, orphan)`：UUID 为稳定业务身份；`orphan=1` 表示容器已消失但记录保留。
- `instance_configs(uuid PK FK→instances ON DELETE CASCADE, spec_json, updated_at)`：期望配置快照，为 0.0.9.8 期望状态核对预留。
- `settings(key PK, value, updated_at)`：键值配置（含最近同步摘要 `sync.last`）。
- 连接设置：WAL＋busy_timeout(5s)＋foreign_keys(ON)＋synchronous(NORMAL)＋单写连接（SetMaxOpenConns(1)）。

### 同步语义（导入→比对→报告）

- 新容器（DB 无记录）→ INSERT 生成 UUID，报告 `imported`。
- 同名但容器 ID 变化（重建）→ 沿用 UUID 更新 container_id，报告 `rebuilt`。
- 容器 ID 相同但标签字段变化 → 更新字段，报告 `updated`（逐字段差异：数据库值／Docker 值／采用值／原因）。
- DB 有记录但容器消失 → 置 `orphan=1`（不删除），报告 `orphans`；容器回归自动解除孤儿标记。
- 同名容器出现多次 → 记入 `conflicts`，不静默处理。
- 触发点：server 启动时一次（goroutine）、`POST /api/v1/database/check` 手动触发、实例创建/删除钩子即时写库（RecordCreate 含期望配置 JSON / RecordDelete 级联）。
- **不随 2 秒硬件轮询写库**；高频采样不入业务数据库。

### API（新增）

- `GET /api/v1/database`：schema 版本、已应用迁移、实例映射数、孤儿数、最近同步摘要、integrity_check、引擎与 journal 模式。数据底座未启用时三端点返回 503。
- `POST /api/v1/database/check`：立即同步，返回完整报告（imported/updated/rebuilt/orphans/conflicts/逐实例差异/unchanged/duration）。
- `POST /api/v1/database/backup`：`VACUUM INTO` 一致性备份（WAL 下安全），产物名 `flowpilot-<UTC时间戳>.db`。

### 降级策略

数据库初始化失败（目录不可写等）**不再退出进程**：打 ERROR 日志、数据底座接口 503、其余功能正常。原因：flowpilotd 二进制同时被回归镜像用作实例内假 ComfyUI，其实例容器无 `/data/flowpilot` 挂载，强制退出会导致回归实例崩溃循环。初始化前 `os.MkdirAll(dataDir)` 幂等建目录。

### 不做

- 不改导航结构、不改实例列表布局（数据底座卡片加在系统管理页新子页）。
- 不提供任意 SQL Web 控制台。
- 多用户／任务／审计表留待后续版本。

## 行为与兼容性影响

- **接口新增**：`GET /api/v1/database`、`POST /api/v1/database/check`、`POST /api/v1/database/backup`。既有接口零变更；`/api/v1/instances` 响应结构不变。

## 已知问题与风险

- `compareAndApply` 采用「以 Docker 实际状态为准」的单一策略；0.0.9.8 引入期望状态核对后，数据库期望值与 Docker 实际值的冲突将有更细粒度的处理。
- 实例的 containerPort 标签中不存储（0.0.9.4 及之前即如此），同步快照中该字段为 0；期望配置 JSON 在创建时保存了完整 Spec（含 containerPort），重建核对时以此为准。
- SQLite 单写连接意味着并发写会串行（busy_timeout 5s 内重试）；当前写路径仅为实例 CRUD 与同步，量级极低。
- 回归镜像实例容器内 flowpilotd 会在其容器内 `/data/flowpilot` 建自己的库（各实例独立、无害但多占 40KB 磁盘）；0.0.9.7 独立 workspace 后该路径纳入实例数据管理。

## 回滚说明

- 回滚到 0.0.9.4：直接部署旧镜像即可。`flowpilot.db`/`backups/` 对旧版本无副作用（不读取）；如需彻底清理，删除 `<数据目录>/flowpilot.db*` 与 `backups/`。
- Docker 标签在 0.0.9.5 中未做任何修改，旧版本仍能按标签识别全部实例，回退无数据风险。
