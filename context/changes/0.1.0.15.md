# 0.1.0.15 — 新建实例镜像信任标注（错误前置到表单）

日期：2026-11-16

## 背景

0.1.0.14 Spark 验证时发现口径不一致：新建实例对话框的候选镜像来自 `isComfyImage`（标签命中 **或** 名称含 comfyui/comfy-ui 的宽松过滤），而 0.0.9.10 起后端创建实例强制 `flowpilot.kind=comfyui` 可信标签校验。结果：无标签镜像（历史构建产物、在线拉取镜像）能在下拉里被选中，提交后才被后端 400 拒绝——「能选不能建」，错误暴露在最晚的环节。

## 方案

候选标注/禁用未认证镜像，校验错误前置到表单内（既不定死候选加载口径，也不放松后端校验）：

1. **后端透传逃生阀状态**：`instance.Defaults` 新增 `AllowUnlabeledImages`，`GET /api/v1/instances` 的 `defaults` 携带 `allowUnlabeledImages`，前端据此知晓平台是否以 `FLOWPILOT_IMAGE_ALLOW_UNLABELED=1` 放行。
2. **前端逐候选判定**：`CreateInstanceDialog` 对每个候选 tag 读 `Labels['flowpilot.kind'] === 'comfyui'` 计算 trusted——
   - 未认证且未放行：option `disabled`，标注「未认证，不可用」；
   - 未认证但已放行：可选，标注「未认证」；
   - 已认证：原样可选。
3. **全不可选指引**：候选均未通过认证时，状态条（琥珀色）说明原因并指引：去「镜像中心」一键构建官方镜像，或由管理员设置 `FLOWPILOT_IMAGE_ALLOW_UNLABELED=1` 后刷新。
4. **自动选择收紧**：默认镜像/首个候选只在可选集合内挑选；`next()` 增加表单内守卫，未认证镜像即使被程序性选中也在第一步拦截并提示。

## 影响面评估

- e2e-audit 不触碰新建实例镜像下拉（只测构建/拉取弹窗），候选禁用不影响审计。
- verify-demo 在带逃生阀的侧实例运行，放行分支下未认证镜像仍可选，回归不受影响。
- 已认证镜像（一键构建产物带 `flowpilot.kind=comfyui`）行为完全不变。
