## 发现的 Bug 与修复

**Bug**：以 `NONINTERACTIVE=1 nohup` 后台方式运行一键安装脚本时，步骤 2 `$SUDO python3`（配置 Docker Hub 加速）触发 `sudo: 需要密码` 后中止——yl 用户 sudo 需密码，无人值守时无法输入。

**修复**（`install-comfyui-image.sh.tmpl` 的 `need_sudo`）：

- `sudo -n true` 预检凭据；
- 交互模式：`sudo -v` 先缓存凭据，避免下载/构建中途卡提示；
- 非交互模式：明确报错并指引「先交互执行一次或配置 NOPASSWD」。
- `catalog_test.go` 新增 `sudo -n true` 片段断言；`code/scripts/install-comfyui-image.sh` 重新生成。

- **DGX Spark 一键脚本全流程实测通过**（0.0.7.1 修复版，tmux 会话内缓存 sudo 凭据后 NONINTERACTIVE 执行）：
  - 检测：GB10 `compute_cap=12.1` → `nvidia-cu130` 配方，torch 官方 cu130 源；

  - 平台闭环：用该镜像经 FlowPilot API 创建实例 `cu130-verify`（GPU 0 · 端口 8189，挂载目标自动适配 `/app/ComfyUI/...`），comfy/status 代理返回 `reachable=true · ComfyUI 0.44.0`；容器内 `torch.cuda.is_available()=True · NVIDIA GB10`，共享模型仓库（checkpoints/loras 等）正确挂载；验证后实例已删除。
- 注意事项：脚本步骤 2 会无条件 `systemctl restart docker`（约数十秒，依赖容器 restart 策略恢复），后续版本可改为配置变更时才重启。
- 经验记录：`sudo -v` 缓存的凭据在 ssh 会话关闭、pts 销毁后对后台 nohup 进程不可靠；无人值守场景应使用 tmux/screen 保活会话（本次采用），或配置 NOPASSWD。

## 已知问题与风险

- 非交互无人值守场景仍需 NOPASSWD、root 或 tmux 保活会话（sudo 仅用于脚本前几步）。
- 步骤 2 无条件重启 Docker 对同机其他容器有秒级中断，依赖其自启策略。
