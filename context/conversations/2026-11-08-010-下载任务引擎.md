# 010 · 下载任务引擎（0.0.3.0）

日期：2026-11-08

## 周董需求

> 按照建议进行下一步（模型 URL 下载真实化：断点续传＋SHA256 校验，任务中心接入真实任务流）

## 决策与方案

- **内存任务表**：下载任务存内存，平台重启记录即清，仓库文件不受影响——延续"无数据库、文件即真相"原则；归档用 rename 原子落仓，分片放 `.downloading/` 隐藏目录（模型扫描自动跳过）。
- **断点续传**：暂停保留分片、Range 续传；200/206/416 三种响应分别处理；取消删分片。
- **SHA256 可选校验**：失败不入库、留分片可重试。
- **界面合并展示**：进行中下载与仓库文件同表呈现（`dl-` 前缀区分），暂停/继续/移除任务与删除文件各走各的 API；任务中心整体切换到真实任务流。
- **测试以 API 状态为准**：回归脚本在"下载完成"与"删除完成"断言上直接轮询 API，消除界面 3 秒轮询合并行的时序干扰（本轮实际踩到一次）。

## 发现并修复的缺陷

- 已完成下载任务记录会永久阻塞同目标重新下载（冲突检查误把终态记录算作占用）——改为仅进行中任务占用目标路径，并补充回归。
- 首轮回归还暴露了界面合并行时序问题，测试改为 API 断言后稳定。

## 交付结果

- 后端 download 新包＋5 个 REST 路由；七包测试全过（含限速源中途暂停续传内容一致性）。
- 前端全链路：弹窗创建→模型中心进度/暂停/继续→任务中心取消/重试→入库→界面删除。
- Spark 实测：28 项远程回归全过；`comfyui-h3` 不受影响；产物清理干净。
