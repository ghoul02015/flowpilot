# 2026-11-11 038 · 0.1.0.2 ComfyUI 版本固定与可追溯

## 用户目标

镜像构建长期显示 `ComfyUI 版本：master`，无法确认实际版本；需要在线获取具体版本、构建时选择并固定。

## 方案

- 官方版本目录联合 Releases/Tags/Branch/Commit，区分正式 Release、仅标签、开发分支。
- 默认最新稳定 Release，而非 master。
- 用户选择后由服务端解析为不可变 commit；构建 fetch 该 SHA、detach checkout 并校验 HEAD。
- 镜像写入 OCI/FlowPilot 版本标签与源码档案。
- Web 构建、构建脚本、独立安装脚本统一固定 SHA。
- 旧镜像不伪造版本，显示“未固定提交”。

## 实施

- 新增 image.VersionResolver（ETag、10 分钟内存缓存、磁盘缓存、离线 stale）。
- 新增 versions/resolve API。
- BuildParams/BuildTask 持久化 Source；Dockerfile 从 branch clone 改为 commit fetch。
- 构建弹窗新增 ComfyUI 版本选择器；镜像清单展示实际版本与短 SHA。
- 独立安装脚本重写源码获取逻辑并补齐 `flowpilot.kind=comfyui`。
- 拉取通道实测需加入 gh-proxy（Spark 直连 GitHub 与 gitclone 均失败）。

## 验证

- 后端 15 包全绿；前端 lint/build；E2E 98 项全过。
- Spark 官方目录默认 v0.45.0（989d93d），master 固定 4d64a8b。
- Spark 容器网络通过 gh-proxy 成功 fetch 固定 SHA 并校验 HEAD。
- 固定 v0.45.0 的 CPU 验证镜像：源码固定与依赖主体安装通过；100MB 模板包下载链路长时间停滞，任务手动停止并清理，未产出验证镜像。

## 关键经验

- 最新 Tag 不等于最新稳定 Release，必须分开建模。
- `release.target_commitish` 可能只是 master，不能当精确 SHA。
- 分支解析结果必须在用户确认时冻结，构建时不能重新跟随分支。
- 无 GitHub 网络时不能静默回退 master。
- 独立脚本也是发行链路的一部分，必须同步固定版本并写入认证标签。
