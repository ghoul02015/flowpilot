# 2026-11-11 037 · 0.1.0.1 发行版体验修正

## 用户反馈

1. 点击镜像标签图标出现浏览器原生弹窗，与产品风格不一致；修改后原镜像仍保留，看起来复制了一份镜像。
2. 任务中心空白过大，需要调整空间，并补充删除、重试等操作；评估是否改叫日志中心并单独设立任务中心。
3. 系统管理存在“真实数据”“阶段 1 版本列车”等调试版痕迹，需要按发行版标准清理。

## 决策

- 任务中心名称保留，不拆分“日志中心”：当前主体是任务状态与操作，只有镜像任务有较完整日志，统一日志模型尚未建立。
- 镜像“改标签”改为“编辑镜像标签”，默认添加别名，明确重命名语义；按镜像 ID 分组消除复制错觉。
- 0.1.0.1 定位为发行版体验修复，不引入新任务框架、不变更数据库结构。

## 实施

- 镜像：产品 Dialog、alias/rename 双模式、目标冲突 409、实例引用保护、失败回滚、按镜像 ID 分组、原生 confirm 清理。
- 任务：紧凑表格/移动卡片、活跃优先、终态无错误 spinner、暂停/继续/取消/重试/删除记录/批量清理、搜索/分页、备份聚合、total 修正。
- 文案：移除真实数据/版本列车/本版；修正“无认证机制”错误提示；测试资产与生产环境隔离。

## 验证

- 后端 15 包全绿；前端 lint/build 通过；E2E 94 项全过。
- Spark 升级 0.1.0.1 healthy，comfy-01 持续运行；清理 39 条测试任务记录和 3 个回归镜像；静态资源扫描无旧调试文案。
- 发布包 MD5 `268d90993db9418e614416d30882498c`。

## 关键经验

- Docker 多标签是同一镜像的引用，不是数据复制；必须从语义和列表分组同时纠正。
- 重命名必须先检查实例引用；检查失败应阻止操作而不是放行。
- 任务“删除”必须命名为“删除记录”，并明确不影响业务产物。
- 终态任务不能复用运行中进度 UI；失败态出现旋转图标会误导用户。
- E2E 修改 Docker 标签后要前置清理测试标签，保证用例幂等。
