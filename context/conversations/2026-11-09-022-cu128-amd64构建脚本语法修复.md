# 2026-11-09-022 cu128/amd64 构建脚本语法修复

## 用户反馈

实体机器测试 `flowpilot/comfyui:cu128 · NVIDIA · CUDA 12.8（RTX 50 / B 系列）`，CPU 架构选择 `linux/amd64（x86_64）` 时，构建失败：

```text
400 Bad Request: {"message":"failed to parse Dockerfile: Syntax error - can't find = in "\\\\". Must be of the form: name=value"}
```

## 根因

0.0.7.3 在 Dockerfile 中新增构建参数 Labels，用于镜像清单展示参数简述。`buildLabels` 使用 Go 原始字符串模板，但 LABEL 多行续行符误写为 `\\`，最终输出到 Dockerfile 时是两个反斜杠。Dockerfile parser 将其中的 `\\` 当作不符合 `name=value` 的 label 片段，导致解析失败。

受影响链路：

- Web 后台手动构建。
- 下载的一键构建脚本。

二者共用 `BuildDockerfile`。

## 修复

- 版本推进到 `0.0.7.4`。
- 修复 `code/backend/internal/image/image.go` 中 `buildLabels` 的 LABEL 续行符，Go 原始字符串内只输出单反斜杠。
- 新增回归测试：
  - `TestBuildDockerfileLabelContinuation`
  - `TestBuildScriptIncludesParsableDockerfileLabel`
- 更新 `CHANGELOG.md`、`README.md`、`docs/mvp/FlowPilot_MVP_PRD.md`、`context/changes/0.0.7.4.md`。

## 验证状态

- 后端 Docker Go 环境 `gofmt -w ./cmd ./internal && go test ./...` 已通过。
- 前端 `npm run lint && npm run build` 已通过。
- 发布包 `flowpilot-0.0.7.4-arm64.tar.gz` 已生成。
- Spark 实机 `192.168.0.77` 已安装 `0.0.7.4`，健康接口返回 `version=0.0.7.4`。
- 从 Spark 服务获取 cu128/linux-amd64 一键构建脚本，提取 Dockerfile 后确认不含双反斜杠续行符。
- `docker build --check --platform linux/amd64` 对提取的 Dockerfile 解析通过，未再出现 `can't find = in "\\\\"`。
