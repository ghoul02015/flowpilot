# 2026-11-08 · 013 · 任务持久化与 ComfyUI 制图进度

## 周董指令

> 开始做任务持久化，原机的 docker 可以都先暂停、测试完后不用重新启动，这样验证的时候方便。然后界面只用显示 comfyui 的制图任务进度这些就可以了，可以在首页和 comfyui 实例有个点击链接页面，实际的使用还是跳转到实际安装好了的应用里，flowpilot 目前主要目的还是做环境和部署管理。

## 执行摘要

1. 原机业务容器（comfyui-h3、gpustack、gpustack-worker、qwen3.8×2）全部停止并保持停止，GPU/统一内存释放，回归全程不受影响。
2. 任务持久化：下载/导入任务落盘 `shared/tasks.json`（原子写、0600），重启恢复（进行中→暂停，按类型提示续传/继续），ID 序号延续；进度落盘靠 `.part` 分片偏移。
3. ComfyUI 状态代理：`GET /api/v1/instances/{name}/comfy/status` 返回 reachable/队列数/版本；容器 `--add-host host.docker.internal:host-gateway`，`FLOWPILOT_HOST_GATEWAY` 可覆盖。
4. 前端：实例列表与首页实例概览展示「制图任务」列（运行 X·排队 Y／空闲）；运行中实例提供「打开 ComfyUI」新窗口跳转真实应用。
5. 实机验证：120 MB 下载 40% 时重启容器 → 恢复暂停 → 续传完成、SHA256 通过；37 项远程回归全绿（含新增 3 项）。
6. 排障：pkill 自匹配自杀会话两次，拆调用解决；宿主机限速源用 base64 写文件 + nohup 启动。

## 关键决策

- 持久化文件放共享卷（与模型同卷）：重装保留、卸载清理，符合"一键卸载不污染环境"原则。
- 进度不逐次落盘：避免高频写盘，重启后续传偏移以 `.part` 文件大小为准。
- 产品定位收口：FlowPilot 不做工作流编辑/制图操作，只做环境与部署管理，制图跳转真实 ComfyUI。
