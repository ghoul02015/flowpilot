# 对话上下文 2026-11-07-005：DGX Spark 远程部署验证

## 用户目标与新增要求

- 周董要求在 DGX Spark 物理机上部署并验证 FlowPilot（对话中称“开始 3.0”，按项目四段版本规则本轮为 `0.0.0.4`）。
- 目标机上有在运行的业务容器，可先暂停，部署测试验证所有问题。
- 成功后截图回传。
- 必须有一键卸载机制，不能污染硬件机器环境。
- 用户提到 `usePlugin://ssh-ops`，但插件市场没有匹配的 SSH 运维插件，改用系统 SSH 完成。

## 已确认的产品和技术决策

- 安装形态：用户目录安装（默认 `~/.local/share/flowpilot`），无需 sudo，不修改系统包。
- 交付形态：`package-release.sh` 产出约 6.7 MB 离线镜像包；`install.sh` 一条命令安装；`uninstall.sh --yes` 一键卸载。
- 镜像共享保护：容器打 `flowpilot.managed=true` 标签，卸载时按标签判断是否还有其他 FlowPilot 容器；镜像 ID 比对方案因 buildx manifest/config digest 不一致被实测否决。
- 卸载目录白名单：只允许删除 `~/.local/share/flowpilot` 及 `flowpilot-*` 变体。

- 版本：`0.0.0.4`（`VERSION`、后端、前端、脚本、文档全部同步）。

## 远程验证事实

- 地址修正：用户提供的 `192.68.0.77` 不通（ping 丢包、SSH 超时），实际可用地址 `192.168.0.77`。
- 目标机：`spark-6558`，Ubuntu 24.04.4 LTS，aarch64，NVIDIA GB10（统一内存，nvidia-smi 显存 N/A），驱动 580.159.03，Docker 29.2.1／API 1.53。
- 原业务容器 `comfyui-h3`：先暂停保护，最终恢复 `running Paused=false`，全程未被卸载流程影响。
- 生产实例：`http://192.168.0.77:18080`，健康接口返回 `0.0.0.4`，Docker 信息接口返回真实 Engine 数据。
- 沙箱卸载（独立容器+目录）：容器与目录删除、共享镜像保留、生产容器健康。
- 完整卸载：容器、镜像、目录全部清理；同一离线包重装后 healthy。
- 最终状态 18 项远程界面回归全部通过，截图存于 `code/frontend/test-results/`。
- SSH 密码仅存在于本地 `.tmp/` 临时 expect 脚本（已被 .gitignore 忽略），交付后删除，未写入任何 Git 内容。
