# FlowPilot 0.1.0.7 性能与请求治理规划

- 当前基线：`0.1.0.6`
- 目标版本：`0.1.0.7`
- 版本主题：性能与请求治理
- 文档日期：2026-11-13
- 文档性质：单版本开发、测试与验收规划，不代表功能已经开发或验证完成
- 本轮交付边界：只编写本规划，不修改业务代码、不调整当前版本号、不构建发布包

---

## 一、版本定位

### 1.1 一句话目标

在不改变现有业务闭环和主要页面结构的前提下，将管理端从“固定周期、全局、全量轮询”调整为“按页面、按活动状态、按可见性触发，并具备防重叠、失败退避和主动失效能力”，降低无效请求、模型仓库扫描和硬件采集开销。

### 1.2 当前基线判断

`0.1.0.6` 已具备实例、镜像、模型、套装、任务、硬件、备份、安全和审计等主流程。本版不重做这些能力，而是解决其运行方式中的共同问题：

1. 登录后，实例、模型、下载和健康状态在全局按固定周期刷新，与当前页面是否使用这些数据无关。
2. 模型扫描缓存时间较短，扫描范围包含本地仓库和可用 NAS；大目录或网络存储抖动时可能形成持续 IO 压力。
3. 首页和硬件页均采集硬件，多个请求同时出现时缺少统一的采集合并策略。
4. 部分轮询使用固定 `setInterval`，慢请求场景需要明确防止重叠。
5. 任务、实例详情、套装和镜像分别实现轮询，缺少统一的可见性、取消、退避和手动刷新语义。
6. 部分写操作后只刷新单一列表，需要形成明确的“业务变更 → 相关缓存失效 → 页面刷新”规则。

### 1.3 本版原则

1. **先保证正确，再降低频率：**不能因降频而把运行中、失败或已完成状态长期停留在旧值。
2. **可见页面优先：**页面不可见时暂停非必要轮询，恢复后立即刷新。
3. **活动任务优先：**只有排队、运行、暂停或安装中等需要进度的状态使用短周期。
4. **写后主动刷新：**下载、导入、删除、本地化、实例操作和套装安装完成后，主动使相关数据失效。
5. **本地与 NAS 解耦：**NAS 不可用不能迫使本地模型数据同时失效。
6. **不扩大产品范围：**本版不做多机、RBAC、资源调度、工作流编辑器或大规模 UI 重组。

## 二、范围与边界

### 2.1 本版包含

1. 建立统一的前端轮询机制和刷新事件语义。
2. 改造全局实例、模型、下载、ComfyUI 状态和健康版本请求。
3. 改造首页、实例、镜像、模型、任务、硬件和系统页面的刷新策略。
4. 改造模型本地／网络仓库缓存、扫描合并和主动失效。
5. 增加硬件采集的短时合并与失败负缓存。
6. 增加轻量任务摘要，支撑导航和顶栏，避免为角标拉取完整任务列表。
7. 补齐请求取消、页面隐藏、慢请求、接口失败和恢复后的行为。
8. 建立请求数、扫描次数和活跃任务刷新时效的自动化验收。
9. 更新版本文档、测试记录、发布说明和回滚说明。

### 2.2 本版不包含

1. 不实施真实 URL 路由和页面详情重构，留待 `0.1.0.8`。
2. 不重做系统管理分组、实例详情页、模型中心信息架构或首页视觉。
3. 不新增 WebSocket；现有 SSE 日志保持，其他模块先完成轮询治理。
4. 不引入大型前端状态管理或数据请求框架。
5. 不改变统一任务状态机、实例健康状态机和数据库 schema。
6. 不改变模型下载、断点续传、SHA256、套装许可和实例关联业务规则。
7. 不做模型文件内容 hash 的全库自动扫描。
8. 不做多机集中管理、RBAC／SSO、GPU 配额和定时告警。
9. 不在本版进行大规模按需拆包；主 JS 拆包与列表虚拟化可另立版本评估。

## 三、测量基线与验收口径

### 3.1 已有观察结果

对 `0.1.0.6` 本机 Web 界面的实际检查观察到：

- 全局业务数据按 3 秒周期请求。
- 首页和硬件页存在 2 秒硬件采集。
- 任务页按 5 秒周期请求。
- 模型扫描缓存为 2 秒，实际扫描包含本地仓库及可用网络仓库。
- 本机观察时主 JS 传输量约 645 KB；该数值只作为前端观察，不作为本版拆包验收指标。

上述观察不是标准性能测试。本版实施前必须在固定环境中重新记录基线，不使用本机空环境结果代替大模型库或真实 GPU 服务器结果。

### 3.2 基线场景

| 场景 | 环境要求 | 记录内容 |
| --- | --- | --- |
| S0 空闲环境 | 无实例、无模型、无活跃任务 | 各页面 10 分钟请求数、接口失败、页面状态 |
| S1 标准环境 | 5 个实例、至少 2 个运行中、100 个模型文件 | 请求数、ComfyUI 探测数、页面刷新和内存 |
| S2 大模型库 | 至少 5000 个文件，可用小文件构造目录元数据压力 | 扫描次数、扫描耗时、API p95、磁盘 IO |
| S3 NAS 异常 | NAS 延迟、断开、恢复 | 本地模型可用性、扫描超时、状态过期提示 |
| S4 活跃任务 | 下载、构建、套装安装同时运行 | 进度刷新延迟、请求重叠、完成后刷新 |
| S5 多卡环境 | 真实 GPU，覆盖 1 卡和多卡 | 硬件采集耗时、nvidia-smi 调用次数、页面流畅度 |

S2 只用于目录扫描和元数据压力测试，不要求下载真实大模型权重，不伪造模型出图性能。

### 3.3 核心验收指标

| 指标 | 目标 |
| --- | --- |
| 请求防重叠 | 同一数据源同一时间最多一个自动刷新请求；手动刷新必须取消或等待旧请求，不并行堆积 |
| 后台页面 | 浏览器标签页隐藏时，非必要业务轮询为 0；恢复可见后立即拉取最新状态 |
| 空闲请求下降 | 相同 S0／S1 场景下，10 分钟业务请求总数较 `0.1.0.6` 下降至少 70% |
| 模型空闲扫描 | 非模型页不因全局轮询触发完整模型扫描；模型页空闲自动扫描周期不短于 60 秒 |
| NAS 隔离 | NAS 扫描失败或超时后，本地模型仍正常展示，NAS 明确标记不可用或数据过期 |
| 活跃任务时效 | 可见页面中的下载、构建和套装安装进度自动刷新周期不超过 3 秒 |
| 写后刷新 | 写操作成功后，相关列表在操作响应后立即刷新或按任务状态自动刷新，不等待长周期 |
| 功能回归 | 现有实例、模型、镜像、套装、任务、硬件和系统主流程不出现功能退化 |
| 资源目标 | 管理服务空闲内存继续满足现有 PRD 目标，不因缓存引入无界增长 |

## 四、目标运行机制

### 4.1 统一轮询语义

所有自动刷新统一具备以下能力：

1. 立即执行或按页面需要延迟执行。
2. 页面可见且 `enabled=true` 时才运行。
3. 上一次请求结束后再安排下一次，不使用无法等待异步完成的裸 `setInterval`。
4. 组件卸载、页面切换或条件失效时取消计时器，并中止可取消请求。
5. 成功后使用正常周期；失败后按 3、5、10、30、60 秒逐级退避，上限 60 秒。
6. 手动刷新立即执行，并在成功后重置退避。
7. 后台标签页暂停；`visibilitychange` 恢复时立即执行一次。
8. 自动刷新失败保留最后一次成功数据，并显示“数据可能已过期”，不清空已有列表。
9. 401 继续走现有认证处理，不由轮询器自行重试登录。
10. 业务 409、422 等状态错误不得被当作普通网络失败无限重试。

### 4.2 建议刷新周期

| 数据或页面 | 活跃／可见 | 空闲／可见 | 页面隐藏 |
| --- | --- | --- | --- |
| 全局任务摘要 | 有活跃任务 3 秒 | 无活跃任务 30 秒，或由业务事件刷新 | 暂停 |
| 实例列表 | 首页／实例页 5 秒；有状态迁移时 3 秒 | 其他页面不自动刷新，仅保留最近数据 | 暂停 |
| ComfyUI 队列 | 首页／实例页且实例运行中 5 秒 | 非相关页面不请求 | 暂停 |
| 健康与版本 | 60 秒 | 60 秒 | 暂停 |
| 首页硬件摘要 | 5 秒 | 5 秒 | 暂停 |
| 硬件管理页 | 2 秒 | 2 秒 | 暂停 |
| 模型仓库 | 模型页 60 秒；写后立即刷新 | 非模型页不按周期拉取全量列表 | 暂停 |
| 任务中心列表 | 当前页有活跃任务 2 秒 | 当前页无活跃任务 15 秒 | 暂停 |
| 镜像任务 | 有排队／运行任务 2 秒 | 无活跃任务不自动轮询任务列表 | 暂停 |
| 套装安装列表 | 有排队／安装任务 3 秒 | 无活跃任务不自动轮询安装详情 | 暂停 |
| 套装安装向导 | 弹窗打开且安装活跃 2.5 秒 | 弹窗关闭或无活跃任务停止 | 暂停 |
| 实例详情健康 | 详情打开 5 秒 | 详情关闭停止 | 暂停 |
| 实例详情事件 | 详情打开 15 秒；健康变化后立即刷新 | 详情关闭停止 | 暂停 |
| 系统管理 | 进入子页和手动重新检测 | 不新增固定轮询 | 不请求 |

以上周期为本版默认配置，集中定义，不允许各页面再新增散落的独立间隔常量。

### 4.3 业务刷新事件

建立轻量刷新事件，不引入大型状态框架：

| 事件 | 触发时机 | 需要失效／刷新的数据 |
| --- | --- | --- |
| `instances:changed` | 创建、启动、停止、重启、删除、重建 | 实例列表、首页统计、实例详情、任务摘要 |
| `models:changed` | 下载完成、导入完成、本地化完成、删除、外部手动刷新 | 本地模型缓存、模型列表、首页模型统计、套装文件状态 |
| `downloads:changed` | 创建、暂停、继续、取消、重试、删除记录、完成 | 下载列表、任务摘要；完成时追加 `models:changed` |
| `images:changed` | 拉取、构建、导入、改标签、删除、清缓存 | 镜像列表、磁盘占用、镜像选择框、任务摘要 |
| `bundles:changed` | 安装创建、暂停、继续、取消、重试、完成、关联实例 | 套装状态、安装进度、任务摘要；完成时追加 `models:changed` |
| `hardware:changed` | 手动重新检测或恢复可见 | 硬件摘要、硬件详情、兼容性状态 |
| `tasks:changed` | 任意统一任务状态变化 | 任务摘要、当前打开的任务页和对应业务列表 |

事件只表达“需要重新获取事实”，不在前端伪造最终业务状态。

## 五、前端模块开发任务

### 模块 FE-01：统一轮询器

**建议新增文件：**

- `code/frontend/src/hooks/use-polling.ts`
- `code/frontend/src/lib/refresh-events.ts`

**功能任务：**

1. 实现基于递归 `setTimeout` 的异步轮询，等待上一轮完成后才安排下一轮。
2. 支持 `enabled`、正常间隔、立即执行、手动刷新和错误退避。
3. 监听 `document.visibilitychange`，后台暂停、恢复立即刷新。
4. 每次执行创建 `AbortController`，清理时中止请求。
5. 防止卸载后 `setState`。
6. 自动刷新与手动刷新共享同一执行入口，避免并行穿透。
7. 保留最近成功时间和最近失败原因，供页面显示过期状态。
8. 不将 401 纳入普通退避；继续由全局未认证处理接管。

**验收：**

- 慢接口超过正常间隔时不出现并发请求。
- 页面隐藏 10 秒期间无自动请求。
- 恢复可见时只立即执行一次。
- 连续失败按退避执行，成功后恢复默认周期。
- 组件卸载后不再请求、不再更新状态。

### 模块 FE-02：API 请求取消与类型统一

**涉及文件：**

- `code/frontend/src/api.ts`

**功能任务：**

1. 为所有参与轮询的方法补齐可选 `AbortSignal`：实例、模型、下载、统一任务、镜像、套装、实例健康和事件等。
2. 保留现有超时；外部 signal 与超时信号需要同时生效。
3. `getUnifiedTasks` 支持传入 signal，任务页不再创建“未实际接入请求”的无效控制器。

5. 保持现有 API 路径、返回类型和错误语义，不做无关接口重命名。
6. 为新增任务摘要补充类型。

**验收：**

- 页面离开、筛选变化和弹窗关闭能够取消对应请求。
- 主动取消不会显示“网络失败”。
- 超时和真实 500 错误仍按现有错误路径处理。

### 模块 FE-03：全局数据与导航摘要

**涉及文件：**

- `code/frontend/src/App.tsx`
- 可将全局请求逻辑拆到 `code/frontend/src/hooks/use-platform-data.ts`

**功能任务：**

1. 登录成功后进行一次必要初始化加载，不在 setup／login 页产生业务轮询。
2. 实例、模型、下载不再共用一个 3 秒全量轮询函数。
3. 实例列表按当前页面和业务活动状态刷新。
4. 模型全量列表只在相关页面需要时加载；其他页面使用最近数据，不周期刷新。
5. 顶栏任务角标改用轻量任务摘要，不依赖完整下载列表推断全部任务。
6. ComfyUI 状态只探测当前仍需展示的运行实例；实例停止或退出相关页面后清理旧状态。
7. `/health` 版本读取使用独立低频策略，不在每轮业务请求后重复触发。
8. 保留现有 `refreshInstances`、`refreshModels`、`refreshDownloads` 等写后刷新能力，改为统一执行入口。
9. 后端离线状态根据实际请求结果更新，恢复后按顺序刷新关键数据，不一次并发轰击全部接口。

**验收：**

- 登录页和初始化页保持无业务轮询。
- 切换到系统页时，不继续每 3 秒拉取完整模型列表。
- 新建实例、添加模型和删除等现有操作仍即时反映。
- 后端恢复后页面数据能自动恢复，不需要刷新浏览器。

### 模块 FE-04：套装轮询治理

**涉及文件：**

- `code/frontend/src/components/ModelBundles.tsx`

**功能任务：**

1. 套装列表初始加载、手动刷新和业务事件刷新分离。
2. 活跃安装轮询依赖“活跃安装 ID 及状态”，不要因每次进度更新导致所有定时器无意义重建。
3. 多套装同时活跃时分别限制单请求，不重复请求同一安装。
4. 详情和向导共享同一安装事实时避免重复轮询；以当前可见、最需要进度的视图为准。
5. 安装完成、取消或失败后停止活跃轮询，并触发套装与模型刷新。
6. 弹窗关闭后停止详情和安装轮询。
7. 许可确认和安装预检不新增后台周期请求。

**验收：**

- 套装安装中进度持续更新。
- 同一安装不会出现两个并行轮询来源。
- 关闭详情或向导后不再请求安装详情。
- 完成后模型仓库和套装“已就绪”状态同步刷新。

## 六、后端模块开发任务

### 模块 BE-01：模型本地仓库缓存与扫描

**涉及文件：**

- `code/backend/internal/model/model.go`
- `code/backend/internal/model/model_test.go`

**功能任务：**

1. 将本地扫描结果和网络扫描结果拆成独立缓存项。
2. 本地空闲缓存默认 60 秒，网络缓存默认 120 秒；平台内写操作通过主动失效保证即时性。
3. 为同一仓库增加扫描合并：缓存失效期间多个请求到达，只执行一次实际扫描，其余请求等待同一结果。
4. 扫描过程记录开始时间、结束时间、耗时、文件数和结果；日志不得逐文件输出。
5. 为扫描增加上下文取消或超时控制；每次遍历定期检查取消状态。
6. 本地缓存失效不应强制重扫 NAS，NAS 失效也不应使本地数据不可读。
7. 缓存必须有界，仅保存最新快照，不保留无限历史。
8. 手动刷新可以提供强制刷新参数，但要限制并发并复用进行中的扫描。
9. 保留现有 `Report` 字段兼容；可新增 `scannedAt`、`stale`、`cacheStatus` 等可选元数据。

**主动失效点：**

- URL 下载完成。
- 本地导入完成。
- NAS 本地化完成。
- 模型删除和批量删除完成。
- 套装安装文件落库完成。
- 任何后续新增的模型写入路径。

**验收：**

- 60 秒内无业务变更的普通读取命中本地缓存。
- 同一时刻 20 个并发读取只触发一次实际扫描。
- 下载完成后下一次读取能立即看到新文件。
- NAS 失败时本地文件仍返回，NAS 状态明确。
- 缓存和扫描不随请求次数无限增长内存。

### 模块 BE-02：模型读取 API 与事实状态

**涉及文件：**

- `code/backend/internal/server/server.go`
- `code/backend/internal/server/server_test.go`

**功能任务：**

1. 保持 `GET /api/v1/models` 默认读取缓存事实。
2. 评估并增加受控的 `refresh=1` 手动刷新参数；自动轮询不得使用该参数。
3. 客户端断开时传递请求上下文，避免无意义的后续处理。
4. NAS 超时时返回本地结果和明确网络状态，不把整个接口统一改成 500。
5. 返回最近成功扫描时间；失败且存在旧数据时允许标记过期，不伪装为实时。
6. 记录扫描失败原因和请求 ID，便于诊断。

**验收：**

- 默认读取不会因每次请求强制全量扫描。
- 手动刷新能绕过过期缓存，但不能制造并发扫描风暴。
- 本地与 NAS 的部分失败语义在接口和界面中一致。

### 模块 BE-03：硬件采集合并与失败负缓存

**涉及文件：**

- `code/backend/internal/hardware/hardware.go`
- `code/backend/internal/hardware/hardware_test.go`
- 如兼容性检查复用采集结果，同步检查 `code/backend/internal/server/compat_api.go`

**功能任务：**

1. 对同一主机的硬件采集增加短时结果合并，避免首页、硬件页和系统页同时触发重复 `nvidia-smi`。
2. 正常采集保留现有数据字段与硬件形态判断。
3. 对明确的 `nvidia-smi` 不存在等持续环境错误使用负缓存，默认 60 秒内不重复执行相同失败命令。
4. 对超时、暂时无输出等瞬时错误使用较短退避，不与“设备永久不存在”混为一谈。
5. 手动重新检测可要求重新采集，但仍需合并同时到达的请求。
6. 兼容性检查优先复用同次硬件报告，避免一个页面重复采集。
7. 负缓存不能隐藏恢复：到期或手动检测后必须真实重试。

**验收：**

- 两个页面同时打开时，同一采集窗口内不会重复执行相同硬件命令。
- 无 `nvidia-smi` 的环境不会每 2 秒重复产生相同失败调用。
- 驱动恢复后，手动检测能够立即重新采集。
- GPU、统一内存和多卡字段保持兼容。

### 模块 BE-04：轻量任务摘要

**涉及文件：**

- `code/backend/internal/tasks/tasks.go`
- `code/backend/internal/server/tasks_api.go`
- `code/backend/internal/server/server.go`
- 对应 Go 测试

**建议接口：**

```text
GET /api/v1/tasks/summary
```

**建议返回字段：**

```json
{
  "active": 0,
  "queued": 0,
  "running": 0,
  "paused": 0,
  "recentFailed": 0,
  "updatedAt": "服务端时间"

```

**功能任务：**

1. 通过 SQL 聚合返回任务数量，不加载完整任务记录和日志。
2. `recentFailed` 的时间窗口集中定义，首版可使用最近 24 小时；不得在前后端分别写不同口径。

4. 保持现有认证、审计和任务状态语义。
5. 不为摘要新增数据库表或物化缓存；首版直接有界聚合即可。

**验收：**

- 摘要数量与统一任务列表在相同筛选口径下一致。
- 大历史任务量下无需向浏览器返回全部历史记录。
- 未登录请求仍返回 401。

### 模块 BE-05：写操作失效链路核查

**涉及模块：**

- `download`
- `model`
- `image`
- `bundle`
- `instance`
- `server`

## 十、风险与控制

| 风险 | 表现 | 控制措施 |
| --- | --- | --- |
| 降频导致状态过旧 | 实例或任务完成后页面仍显示旧状态 | 写后事件、活跃短周期、最近更新时间和手动刷新 |
| 缓存失效遗漏 | 模型已落库但列表不可见 | 建立写入口清单，覆盖任务完成回调和服务重启恢复 |
| 多请求合并异常 | 等待者长期阻塞或拿到错误快照 | 统一单飞结果、超时、取消和失败释放 |
| NAS 阻塞 | 整个模型接口超时 | 本地与网络拆分、独立状态和超时控制 |
| 后台恢复请求风暴 | 多模块同时恢复并同时请求 | 按数据优先级错开恢复，复用进行中的请求 |
| 轮询器行为不一致 | 不同页面再次出现不同错误处理 | 所有周期和退避集中定义，禁止新增私有轮询器 |
| 任务角标口径错误 | 当前页数量被当成全局数量 | 使用后端任务摘要 |
| 功能回归 | 只关注请求数而破坏业务操作 | 每页迁移后立即执行现有功能回归 |

- 不改变 ComfyUI 实例运行参数和模型链接结构。
- 前端刷新策略变化不改变服务端事实来源。

### 11.2 回滚

1. 保留 `0.1.0.6` 发布包和容器镜像。
2. 升级前创建 SQLite 一致性快照。
3. 前端轮询改造可随 `0.1.0.6` 静态资源整体回滚。
4. 模型缓存和硬件采集为内存状态，回滚后自然消失，不需要数据反迁移。
5. 新增任务摘要接口可保留不用，不影响旧前端。
6. 若出现状态更新延迟或扫描异常，优先回滚到 `0.1.0.6`，不在生产环境临时关闭全部健康检查。
