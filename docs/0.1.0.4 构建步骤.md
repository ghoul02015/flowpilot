## 一、文档用途与执行规则

### 1.1 目标

把已经确定的 `0.1.0.4` 规划拆成可执行、可审查、可测试、可回滚的工作包。实施人员应能按本文逐项完成：

1. 五个 H3 套装的 manifest 和资产坐标冻结。
2. 套装文件状态、硬件／镜像／磁盘／许可预检。
3. 单文件串行的整组下载／离线导入、断点续装和失败恢复。
4. 统一任务、实例模型关联、审计和人工验收记录。
5. 模型中心、安装向导、进度、验收和硬件入口的完整页面闭环。
6. 性能、安全、兼容性、全量回归、RC 发布和回滚演练。

### 1.2 不变边界

- S1～S3 提供标准编排；S4／S5 始终标记为实验。
- 发布包不附带模型权重，不默认出厂预装权重。
- 不自动执行 ComfyUI 工作流，不自动跑性能测试，不自动生成“慧浪认证”。
- 不改实例创建向导，不做“从套装创建实例”。
- 不做多 GPU 并行、显存叠加、SGLang／vLLM 服务化。
- 不做模型应用编辑器、提示词服务或行业业务应用。
- 不顺带改造 PyTorch 锁定策略、镜像构建系统、模型市场和本地仓库主流程。
- “文件齐备”“人工验收记录”“慧浪认证”是三个独立事实，不得互相推导。
- S5 中图像 INT8 编码器与视频 NVFP4 编码器必须同时保留。
- 软件功能发布与模型硬件认证解耦；未完成实机验收不影响编排软件 RC，但不得显示已认证。

### 1.3 执行纪律

- 本文复选框只有在对应代码、测试和证据完成后才能勾选。
- 每个工作包先补测试，再实现，再做页面接线；不得只做成功路径。
- 不修改已发布的数据库迁移 SQL，只在现有迁移后追加。
- 不用真实几十 GB 模型作为普通 CI 固定前置条件；大文件测试使用可控稀疏文件、分片和小文件哈希夹具，真实下载单独验收。
- 任一步骤发现规划与现有代码冲突，先记录差异并停下来评审，不以扩大重构范围的方式“顺手解决”。
- 实施期间不得提交或推送 Git、不得启用定时任务，除非周董另行明确授权。

## 五、WP01：资产、来源和许可冻结

### 5.1 建立资产核对表

对每一个 `BundleItem` 建立一行核对记录，至少包含：

```text
bundleId / itemKey / role / required / optionalGroup
category / fileName / targetRelativePath
repo / revision / sourceFilePath / sizeBytes / sha256
licenseName / licenseURL / snapshotDate / noticeRequired
reviewer / reviewDate / evidenceLocation
```

执行步骤：

1. [ ] 按规划列出 S1～S5 的必需项、可选项、依赖和互斥组。
2. [ ] S2 明确包含 S1 并新增 9B W4A8 GPTQ 编码器，不复制出含义不清的第二套基础项。
3. [ ] S3 默认 Turbo 不选，4-step 与 8-step 同属一个互斥组，至多选择一项。
4. [ ] S4 的 Ref2V Turbo 与 S3 的 FL2V Turbo 使用不同 itemKey 和 optionalGroup。
5. [ ] S5 展开 S2＋S3，S4 只作为可选扩展；INT8 与 NVFP4 编码器不得因“用途相似”去重。
6. [ ] 只有目标相对路径和完整 SHA256 都一致的文件才能共享；只有路径相同但 hash 不同必须报冲突。
7. [ ] 清理普通目录中 W6A8“16GB 流畅”等未经实测文案，但不删除现有普通模型条目。

### 5.2 固定下载坐标

1. [ ] 所有出厂来源锁定不可变 revision，禁止只写 `main`。
2. [ ] 从可信来源获取精确字节数和 SHA256；没有官方 hash 时，在隔离下载区完成完整文件计算，再由第二名复核人确认后写入 manifest。
3. [ ] 主备源只有在 revision 对应内容、字节数和 hash 全部一致时才可互为主备。
4. [ ] 若主备源不一致，只保留已复核源，另一个标为不可用并记录原因；不能安装时临时改 hash 迁就下载文件。
5. [ ] 所有 URL 继续走现有源白名单、SSRF 和逐跳重定向检查。
6. [ ] manifest 只保存公开仓库坐标，不保存签名 URL、Token、Cookie 或 NAS 凭据。

### 5.3 许可冻结

1. [ ] 保存许可名称、原始链接、快照日期、NOTICE 要求和审核状态。
2. [ ] 默认 `reviewStatus=needs_review`，不得显示“可商用”。
3. [ ] `acknowledgementVersion` 与 manifest 内容绑定；许可变化必须生成新 bundleVersion。
4. [ ] 页面文案只表示“用户已阅读并确认”，不表示平台授予商业权利。
5. [ ] H3-Image 的模型名称在卡片、详情、许可和实例关联区域统一为 `MiniMax-H3-Image`。

### 5.4 冻结门槛

- 缺 revision、精确大小、hash 或许可快照的必需项不得进入可安装状态。
- 可保留为“清单预览／待补全”，但安装按钮必须禁用并显示具体缺失字段。
- 形成资产核对表和双人复核记录后，才进入 WP02。

## 六、WP02：Manifest 与 SQLite 数据底座

### 6.1 Manifest 类型和加载

1. [ ] 定义 `Bundle`、`BundleItem`、`Source`、`Variant`、`HardwareRule`、`WorkflowRef`、`License`、`Certification` 类型。
2. [ ] 使用 `embed` 或现有资源加载方式随二进制固定首版 `minimax-h3-bundles/v1`。
3. [ ] 启动时完整解析并校验；失败时明确记录套装 ID 和字段，不静默跳过错误套装。
4. [ ] 禁止本版后台在线更新 manifest，避免发布内容漂移。
5. [ ] `bundleVersion` 与内容 checksum 同时返回前端；安装、许可和验收记录必须保存二者。

### 6.2 严格校验规则

- [ ] ID、itemKey 和版本非空且格式稳定。
- [ ] category 只能映射现有受控模型目录。
- [ ] 目标路径必须是相对路径，拒绝绝对路径、`..`、空段、反斜杠逃逸和非法符号链接目标。
- [ ] SHA256 为 64 位十六进制，大小为非负整数，revision 非空且非浮动分支。
- [ ] 必需依赖存在，无循环依赖，无可选组自相依赖。
- [ ] 同一互斥组默认项不超过一个；S3 默认不选 Turbo。
- [ ] 必需项至少有一个已复核下载源或明确离线导入映射。
- [ ] 同一目标路径对应多个不同 hash 时启动校验直接失败。
- [ ] 工作流只是外部官方引用或说明，不注入可执行 Prompt，不自动调用 ComfyUI。
- [ ] `certified` 不能由普通人工验收字段写入。

### 6.3 选项展开纯函数

实现不访问网络的选项展开逻辑，输入为 `bundleVersion + variant + selectedOptionalKeys`，输出规范化安装快照：

- 必需项与已选可选项的稳定顺序。
- 去重后的目标文件及共享来源。
- 总字节数、必需字节数和可选字节数。
- 被互斥规则排除的项及原因。
- 许可版本和最低 ComfyUI／模板包要求。

该快照存入安装计划，后续 worker 不随新 manifest 静默改变旧计划内容。

### 6.4 SQLite Version 5

只追加迁移 `Version: 5, Name: model-bundles`。表职责如下：

#### `bundle_installs`

- 主键 `id`；保存 bundleId、bundleVersion、manifestChecksum、variant、selectedOptionsJson、targetRepository。
- 保存 status、currentItemKey、totalBytes、completedBytes、errorCode、errorMessage。
- 保存 requestKey／幂等标识、operator、createdAt、updatedAt、startedAt、finishedAt。
- 保存计划快照 JSON 和恢复原因；敏感来源信息不得入库。
- 对活动计划建立去重约束或等价事务锁，确保同套装＋版本＋变体＋目标仓库最多一个活动计划。

#### `bundle_install_items`

- 保存 installId、itemKey、ordinal、required、sourceRevision、targetPath、expectedBytes、expectedSHA256。
- 保存 status、childTaskId、actualBytes、actualSHA256、attempts、errorCode、errorMessage、timestamps。
- `(installId, itemKey)` 唯一；`childTaskId` 建索引，防止两个计划控制同一子任务。
- 已完成项重试前必须重新判断当前文件，不直接重复下载。

#### `bundle_license_confirmations`

- 保存 id、bundleId、bundleVersion、acknowledgementVersion、licenseSnapshotDate、deliveryMethod。
- 保存 operator、confirmedAt、requestId；不存许可复选框以外的虚构法律结论。

#### `bundle_acceptances`

- 保存 id、bundleId、bundleVersion、installId、instanceName、result、presetJson、environmentJson、metricsJson、notes、operator、createdAt。
- environmentJson 使用 GPU index＋型号、内存模式、主机型号、镜像 digest、Core／模板包版本。
- metricsJson 明确为人工填写，不得反写 certificationByHardware。

### 6.5 索引和事务

- [ ] 安装表按 bundleId、status、updatedAt 建索引。
- [ ] 子项表按 installId、status、childTaskId 建索引。
- [ ] 许可按 bundleId、bundleVersion、confirmedAt 建索引。
- [ ] 验收按 bundleId、createdAt、instanceName 建索引。
- [ ] 创建计划、写入选项快照和子项在同一个事务完成。
- [ ] 状态迁移和当前子任务绑定使用事务，避免崩溃后出现两个当前项。
- [ ] 列表读操作不长时间持有写事务；hash 和下载过程绝不占 SQLite 事务。

### 6.6 数据底座验收

- 从 `0.1.0.3` 数据库升级一次、重复启动一次，迁移结果一致。
- 旧实例、模型、下载、审计和任务数据不变。
- 回滚旧二进制后新表保留但不被读取；再升级时历史安装与验收仍可查询。
- 失败注入覆盖计划创建中途、子项写入失败和 checksum 不符。

## 七、WP03：文件状态与预检构建

### 7.1 仓库快照与状态计算

1. [ ] 每次套装摘要请求只生成一次目标仓库快照，五个套装共享，不逐卡片重复扫盘。
2. [ ] 快照只收集路径、大小、必要任务状态和已有安装记录，不读取完整大文件。
3. [ ] 路径匹配后再按大小判断 `present` 候选；同名同路径但大小不符为 `hash_mismatch` 或 `conflict`，按原因细分。
4. [ ] 页面列表不自动计算全量 SHA256；只有下载完成、导入完成或用户显式发起校验时流式计算。
5. [ ] 对安装记录中已完整验证且路径、大小未变化的文件，可沿用已验证 hash；文件变化后必须失效。
6. [ ] 同名不同 expected hash 进入 `conflict`，不覆盖、不自动改名伪装成功。
7. [ ] 已有普通下载任务可显示关联状态，但未被当前计划拥有的任务不能被擅自暂停或取消。

### 7.2 状态优先级

逐项状态统一为：

```text
missing / downloading / paused / verifying / present / hash_mismatch / conflict
```

套装状态统一为：

```text
not_installed / partial / queued / installing / paused
files_ready / failed / cancelled
```

计算规则：

- 必需项全部 `present`，且已选可选项无未解决冲突，才可为 `files_ready`。
- 必需项部分存在为 `partial`；有活动子项时为 `installing`。
- 可选项失败不阻断基础文件齐备，但详情中必须保留失败摘要。
- 服务重启恢复的计划显示 `paused`＋“待继续”，不能显示仍在运行。
- 实例关联、人工验收、慧浪认证使用独立字段，不塞进套装安装状态。

### 7.3 硬件预检

1. [ ] 复用一次硬件摘要，不在每张卡片内再次调用采集器。
2. [ ] 按 Spark 128 GB、PRO 6000 96 GB、4090／5090、其他 NVIDIA、无 GPU／采集失败输出规则结果。
3. [ ] 结果包含 `level`、原因、是否允许仅下载、是否建议关联和待确认事项。
4. [ ] 不使用文件大小总和推导显存需求，不叠加多卡显存，不重复计算 Spark 统一内存。
5. [ ] 4090／5090 可显示强警告但不禁止下载；S4／S5 不因硬件满足而移除实验标识。
6. [ ] 无 GPU 或采集失败允许资产下载，关联前再次提示无法评估运行环境。
7. [ ] 硬件数据过期时显示采集时间，不将旧数据当成当前实时结论。

### 7.4 镜像与版本预检

1. [ ] 从实例镜像标签读取 ComfyUI Core 版本、commit 和 digest。
2. [ ] H3-Image 和 S5 按 Core `>=0.45.0` 检查；其他套装按各自 manifest 最低版本。
3. [ ] Core `0.45.0` 只使 Core 项通过，不代表模板包、H3 节点或工作流通过。
4. [ ] 模板包 `0.11.104+` 和 H3 节点无法可靠读取时显示“待确认／待人工验收”。
5. [ ] 老镜像缺少元数据显示“无法确认”，不自动通过，也不直接阻断仅资产下载。
6. [ ] 镜像不满足时提供跳转镜像中心入口，本版不自动触发构建。

### 7.5 磁盘预检

分别返回并展示：

- 缺失文件需要下载的字节数。
- 已存在完整文件可复用的字节数。
- 已存在 `.part` 可续传的字节数及其估算口径。
- 下载临时空间、移动／导入复制峰值空间。
- 安全余量和用户配置输出预留。
- NAS 已存在文件与本地化新增空间。

规则：

- 空间不足阻断开始安装，错误中给出所需、可用和差额字节数。
- 不把已完成文件、多个套装共享文件重复计入需求。
- 不通过删除用户文件自动释放空间，只提供可操作建议。
- 预检只读，不创建目录、不创建下载任务、不写实例链接。

### 7.6 许可预检

- 当前 operator 是否存在同 bundleVersion、同 acknowledgementVersion 的确认。
- 旧版本确认不能复用；前端传“已确认”而后端无记录时仍返回阻断。
- 许可预检只查状态，真正确认通过独立写接口记录并审计。

### 7.7 预检输出和测试

每项统一返回：

```text
code / status(pass|warn|block|unknown) / title / detail
observed / required / remediation / checkedAt
```

测试覆盖 Spark、PRO 6000、4090／5090、未知 GPU、无 GPU、统一内存、老镜像、模板未知、磁盘不足、NAS 复用、许可未确认和许可过期。

## 八、WP04：串行安装、离线导入与故障恢复

### 8.1 创建幂等计划

1. [ ] 校验 bundleId、bundleVersion、variant、选项和目标仓库。
2. [ ] 服务端重新展开选项并重新预检，不信任前端总字节数和文件列表。
3. [ ] 对磁盘不足、必需项 hash 冲突、许可未确认、版本不匹配返回明确阻断。
4. [ ] 在事务内检查活动计划和 requestKey；重复请求返回原计划，不重复创建子任务。
5. [ ] 保存不可变计划快照、逐项初始状态和操作者。
6. [ ] 创建统一任务后启动唯一 worker；HTTP 重试不得再启动第二个 worker。

### 8.2 串行 worker

严格执行以下循环：

1. 读取计划快照和下一个待处理项。
2. 再检查目标文件是否已存在并匹配；匹配则标记跳过／完成。
3. 检查冲突和当前取消／暂停状态。
4. 为当前项选择已复核来源或离线导入映射。
5. **只创建一个现有下载／导入子任务**。
6. 等待该子任务进入完成、失败、暂停或取消终态。
7. 对完成项核对大小和 hash，持久化结果。
8. 更新总进度和当前项，然后才处理下一项。

禁止：

- 一次性把所有文件提交给现有 download manager。
- 为每个 item 启 goroutine 后并发等待。
- 因现有 `Spec` 创建后直接运行就再增加套装级无界并发。
- 用一个“整套成功”掩盖子项 hash 失败。

### 8.3 下载完成和校验

- 下载管理器继续负责断点、临时文件、流式写入和基础 SHA256。
- 套装 worker 只消费子任务结果，不复制第二套下载实现。
- 完整文件校验使用流式 IO，禁止一次性读入内存。
- 大小或 hash 不符时保留诊断信息并进入失败／冲突，不将文件标记为 present。
- 备用源只接受与当前计划 expected hash 一致的内容，失败换源不能改变计划期望值。
- 完成文件从临时位置到受控模型目录的移动遵守现有原子性和路径约束。

### 8.4 离线导入

- 仅接受现有 `/data/import` 白名单内路径。
- 服务端将导入文件名、大小和 hash 与当前计划 item 匹配，前端不能指定任意宿主机目标。
- 同名多项时要求用户选择明确 itemKey，不猜测匹配。
- 复制／移动峰值空间纳入预检；导入完成后再校验目标。
- 不允许通过符号链接逃逸白名单，不覆盖已有冲突文件。

### 8.5 暂停、继续、取消和重试

| 操作 | 允许状态 | 行为 | 不得发生 |
| --- | --- | --- | --- |
| pause | queued／installing | 暂停当前子任务并保存计划、`.part` 和进度 | 删除分片、继续下一项 |
| resume | paused／重启待继续 | 从缺失项和现有分片恢复 | 重下已验证文件 |
| cancel | 非终态 | 停止当前可控子任务，计划置 cancelled | 自动删除已入库模型 |
| retry | failed／部分失败 | 默认只重试失败或缺失项 | 重置全部已成功项 |

- 已存在但不归当前计划控制的普通任务，只显示占用／冲突，不强行控制。
- 取消按钮需二次确认并明确“已完成模型保留”。
- 可选 Turbo 失败可单独重试；基础套装文件状态不被可选失败倒退。

### 8.6 服务重启和崩溃恢复

1. [ ] 启动恢复时查询 `queued/installing` 计划及 childTaskId。
2. [ ] 对仍存在的子任务重新核对真实状态，不直接相信旧计划进度。
3. [ ] 对无法确认执行中的计划统一转为 `paused`＋“服务重启，待继续”。
4. [ ] 清理内存中的旧 worker 标记，确保恢复只发生一次。
5. [ ] resume 时从数据库快照重建，不依赖重启前内存队列。
6. [ ] 若子任务已完成但套装项未落库，先补校验和状态，再继续下一项。
7. [ ] 若子任务失败，保留失败原因，由用户选择 resume／retry，不无限自动重试。

### 8.7 进度和写库频率

- 总字节以计划快照为准，跳过已验证项也计入完成字节并注明“复用”。
- 当前项状态变化立即写库；字节进度按合理间隔限流，不随每个分片写 SQLite。
- 最后一笔进度、完成、失败、暂停和取消必须强制落库。
- UI 进度只能使用后端返回的真实字节，不用定时器假增长。
- 文件数进度与字节进度同时展示，避免单个大文件造成误解。

### 8.8 编排验收

必须注入并通过：网络中断、重定向失败、磁盘写满、hash 错误、重复提交、暂停中重启、下载完成后重启、当前项失败、可选项失败、取消后继续新计划、目标文件被外部修改。

## 十、WP06：后端 API、装配、安全与审计

### 10.1 API 实施清单

| 端点 | 实施动作 | 关键错误／保护 |
| --- | --- | --- |
| `GET /api/v1/model-bundles` | 一次仓库快照＋硬件摘要生成五张卡片 | 支持能力筛选；不触发全量 hash |
| `GET /api/v1/model-bundles/{id}` | 返回 manifest、逐项状态、工作流、许可、安装和最近验收 | 未知 ID 404；大历史分页，不一次返回全部 |
| `POST .../{id}/preflight` | 校验选项并执行只读预检 | 不写目录、不建任务、不改链接 |
| `POST .../{id}/installs` | 创建幂等计划并返回 installId | 活动锁、磁盘／冲突／许可阻断 |
| `GET .../{id}/installs/{installId}` | 单查计划和逐项进度 | ID 必须属于当前套装，否则 404 |
| `POST .../{installId}/pause` | 暂停当前计划和子任务 | 非法状态 409，重复暂停幂等 |
| `POST .../{installId}/resume` | 恢复缺失项和断点 | 重启待继续可恢复，重复执行防重 |
| `POST .../{installId}/cancel` | 取消计划，保留文件 | 二次确认由 UI 负责，服务端校验状态 |
| `POST .../{installId}/retry` | 只重试失败／缺失项 | 不重复下载已验证项 |
| `POST .../{id}/link` | 合并链接并返回差异结果 | 全量替换保护、并发冲突、旧实例错误 |
| `POST .../{id}/acceptances` | 保存人工验收 | 字段校验、结果枚举、操作者来自会话 |
| `GET .../{id}/acceptances` | 分页查询历史 | 稳定排序、页大小上限 |
| `GET .../acceptances/{acceptanceId}/export` | 导出脱敏 JSON | 文件名安全、无凭据、无签名 URL |

如实现时将 action 拆成独立路径，必须与规划保持同等语义，不再新增另一套重复端点。

### 10.2 请求与响应约束

- 所有列表响应包含 bundleVersion、manifestChecksum、状态和 checkedAt。
- 写请求只接受选项键和受控参数，不接受前端传入的目标绝对路径、operator、认证状态或总字节数。
- 错误响应统一包含稳定 errorCode、可读 message、可选 field／itemKey 和 retryable。
- 进度响应包含当前子任务 ID，但不返回签名 URL 或内部凭据。
- 创建成功表示“计划已创建”，不能响应“安装完成”。
- 预检带请求选项摘要；选项变化后旧 preflightToken 失效，安装时重新校验。

### 10.3 服务装配

1. [ ] 在 `server.New` 的现有依赖注入位置加入 manifest service、bundle store、worker 和关联服务。
2. [ ] 避免继续无约束增加位置参数造成错配；若改为配置结构体，必须小范围同步所有调用点和测试 fake。
3. [ ] 启动时完成 manifest 校验和恢复扫描，再注册可处理新任务的路由。
4. [ ] worker 关闭接入现有服务生命周期，退出时不再创建新子任务。
5. [ ] 通过 `server.New` 调用点定位实际启动入口，不假设或新建不存在的 `main.go`。
6. [ ] 为没有真实 GPU、下载器和实例服务的单元测试提供可控 fake。

### 10.4 认证、CSRF 和审计

- 所有写接口沿用登录认证、CSRF／Origin 和服务端权限校验。
- 预检虽只读，也避免暴露敏感内部路径；按现有管理员权限处理。
- `auditRequest` 目前只取 `{name}`，本版补充套装 ID、installId、acceptanceId、bundleVersion、result 和 errorCode。
- 审计不记录完整来源 URL 查询串、Token、Cookie、NAS 凭据、许可隐私信息或验收表单中的敏感备注。
- 许可确认、计划创建、暂停、继续、取消、重试、关联、新增验收和导出均留审计。
- 导出验收 JSON 也记录操作者和导出对象，但不记录文件内容。

6. 许可审核状态、人工验收状态、慧浪认证状态分行展示。
7. 主按钮和“查看详情”次按钮。

按钮映射：

- 未安装且无阻断：`预检安装`。
- 有活动计划：`查看进度`。
- 暂停／重启待继续：`继续安装`。
- 部分／失败：`查看并续装`。
- 文件齐备：`查看结果`／`关联实例`。
- manifest 未冻结或存在硬阻断：禁用主按钮并说明原因。

优化点：长名称两行截断、hash 不在卡片展示、状态不只靠颜色、进度条有无障碍文本、卡片不单独发请求。

### 11.4 `BundleDetailDrawer` 总体行为

- 桌面宽抽屉，移动端全屏；标题区固定显示套装版本和实验／认证状态。
- 打开时只请求当前套装详情，五个子页共享一份数据。
- 切换子页不重复请求；关闭时 abort 未完成请求和安装轮询。
- 数据刷新失败保留旧详情并显示非阻塞错误；首次失败显示重试。
- 关闭后焦点回到原卡片主按钮，Esc 和焦点陷阱符合现有 Dialog 规范。

### 11.5 子页一：概览

内容与操作：

- 场景说明、能力边界、标准／实验说明。
- 当前文件、实例关联、人工验收、慧浪认证四个独立状态。
- 当前主机和最低 Core／模板包摘要。
- 主操作“预检安装”，次操作“关联实例”“查看验收”。
- S4／S5 在首屏固定显示实验提示，不能藏在折叠区。

优化点：不用宣传性跑分；无数据时显示“未记录”，不填 0  ms 或虚构性能。

### 11.6 子页二：文件与依赖

- 必需项、可选项分组；每项显示 role、文件名、大小、本地状态。
- 可展开查看来源仓库、revision、源文件路径、SHA256 和目标相对路径。
- 变体和 Turbo 选择在安装前可改；已有活动计划时只读并显示计划快照。
- 冲突项显示“保留现有文件／返回处理”，本版不自动覆盖。
- 失败项提供“重试失败项”，成功项不重复勾选。

优化点：长路径中间省略但提供复制；大列表分组折叠；移动端每项纵向排列，无页面级横向滚动；复制按钮有反馈和键盘名称。

### 11.7 子页三：硬件与工作流

- 显示 GPU index＋型号、内存模式、硬件匹配原因和数据采集时间。
- 显示实例 Core、模板包、镜像 digest 的通过／警告／未知状态。
- 工作流只提供官方链接、模板名称和人工验收档位，不内嵌执行按钮。
- 提供“重新预检”和“跳转镜像中心”。
- 无实例时显示“可仅安装资产”，不自动创建实例。

优化点：技术元数据折叠，核心阻断原因优先；未知与失败使用不同文案。

### 11.8 子页四：许可

- 显示许可名称、原始链接、快照日期、NOTICE、审核状态和交付边界。
- 显示确认历史：版本、操作者、时间、交付方式。
- 新版许可需要重新确认，旧记录保留但标为历史版本。
- “确认”只记录阅读行为，附近固定说明“不代表平台授予商业授权”。

优化点：外链明确新窗口行为；链接失败仍显示许可名称和快照日期；长许可不嵌整页 iframe。

### 11.9 子页五：验收记录

- 历史按时间倒序分页，显示实例、硬件、档位、结果、操作者和时间。
- 单条可展开查看人工指标、输出检查、离线／重启检查和备注。
- 提供“新增人工记录”和“导出 JSON”。
- 没有记录时显示“尚无人工验收”，不是“验收失败”。
- 慧浪认证只能显示 manifest 审核状态，表单不提供修改入口。

## 十二、WP08：四步安装向导、进度和实例关联页面

### 12.1 向导公共状态机

```text
选择内容 → 环境预检 → 许可确认 → 确认执行
```

公共要求：

- 顶部显示四步和当前步；只允许回到已完成步骤，不跳过阻断步骤。
- 任一套装版本、变体、可选项、来源或目标仓库变化，都使后续预检和确认失效。
- 上一步保留选择，下一步前先校验当前步。
- 提交期间按钮 loading 并防连点，但服务端幂等锁才是最终保护。
- 关闭有未提交修改的向导需提示；创建成功后关闭不影响后台计划。
- 请求卸载 abort；前端 abort 不等于取消服务器安装计划。

### 12.2 第一步：选择内容

控件：

- 套装变体。
- Turbo／全参考扩展复选项。
- 在线来源或离线导入。
- 目标仓库摘要和实例关联意向。

校验：

- Turbo 默认不选；4／8-step 互斥。
- S4 只选 Ref2V 对应扩展，S5 全参考扩展单独列出。
- 离线导入显示白名单说明和逐项匹配，不开放任意路径文本框。
- 选择变化即时重新计算文件数、总字节和依赖，不发安装请求。

性能：只基于已加载 manifest 本地展开；不为每次复选重新扫描仓库。

### 12.3 第二步：环境预检

分区显示硬件、镜像、磁盘、已有文件、冲突和许可状态。

- pass／warn／block／unknown 使用图标＋文字。
- block 列出所需／当前值和解决建议，未解决不能进入执行。
- warn 可继续，但需要用户明确知悉；unknown 不伪装成 pass。
- “重新预检”只发一次请求，防连点并显示 checkedAt。
- 无 GPU 可仅下载；镜像待确认不自动触发构建。

性能：预检结果作为整体保存，不在每个卡片组件再次请求硬件或磁盘。

### 12.4 第三步：许可确认

- 展示当前 bundleVersion、acknowledgementVersion、许可链接和快照日期。
- 复选框默认未选，文案为“我已阅读模型许可与使用限制”。
- 已存在同版本确认可显示记录，但仍由后端安装接口复核。
- 确认失败停留当前页并显示可重试错误，不进入下一步。
- 许可版本与当前 manifest 不符时强制刷新，不提交旧确认。

### 12.5 第四步：确认执行

显示：

- 套装版本、选项快照、目标仓库。
- 必需／可选文件数、复用字节、新下载字节、临时空间。
- “默认一次一个文件”的串行说明。
- 预检警告、许可确认时间和实例关联意向。
- 提交按钮“创建安装计划”。

提交后：

- 成功文案“安装计划已创建”，跳进度，不显示“安装完成”。
- 409 重复计划时打开原计划。
- 预检过期时回到第二步并保留选择。
- 网络超时可查询 requestKey 对应计划，不能直接重复创建。

### 12.6 `BundleProgress` 安装进度

布局：

1. 总体状态、文件数进度、字节进度和当前文件。
2. 当前子任务状态、速度（若现有任务已提供）、已下载和总量。
3. 逐项列表：复用、下载、暂停、校验、完成、失败、冲突。
4. 暂停／继续／取消／重试操作区。
5. 必需项与可选项失败摘要。
6. 统一任务和实例关联入口。

轮询策略：

- 只有详情可见且计划活动时低频轮询单个 installId。
- 页面隐藏、抽屉关闭、组件卸载或计划终态时停止。
- 使用 AbortSignal，避免旧请求覆盖新状态。
- 操作后优先立即刷新一次，不额外叠加多个定时器。
- 服务重启计划显示“待继续”，取消后显示“已完成文件保留”。

### 12.7 `BundleLinkDialog` 实例关联

步骤：

1. 选择实例，查看健康、链接支持、Core 版本和 GPU。
2. 请求后端生成差异预览：新增、已存在、冲突、不可用。
3. 默认只新增套装缺失项，已有模型保持选中且不可被本流程移除。
4. 冲突时提供刷新，不提供强制全量覆盖。
5. 提交后显示逐项结果；部分失败可重试失败项。
6. 成功提示仍需人工运行工作流验证。

异常状态：无实例、实例离线、旧实例不支持、文件已不齐备、并发修改、部分关联和请求超时都必须有独立界面。

## 十三、WP09：人工验收和硬件页面入口

### 13.1 `BundleAcceptanceForm` 表单

字段分组：

**关联信息**

- 套装、bundleVersion、安装计划 ID。
- 实例名称；从当前上下文带入，可选择但不能伪造 operator。

**硬件与镜像**

- 主机型号。
- GPU index＋型号，多卡逐行填写，不计算显存总和。
- 统一／独立内存模式。
- 镜像 digest、ComfyUI Core、模板包版本。

**验收档位**

- 图像：4 MP／16 MP、T2I／编辑、参考数量。
- 视频：5／10／15 秒、T2V／I2V／参考类型、参考数量。
- Turbo 选项；S4／S5 保留实验标识。

**人工结果**

- 通过／失败／部分通过。
- 冷启动、首次生成、暖机耗时、资源峰值，均为可选手工数值并带单位。
- 输出检查、音／视频流检查、离线运行、重启恢复。
- 备注。

校验与保存：

- 数值非负，单位明确；未填写保存为 null，不默认写 0。
- 结果失败时必须填写失败说明；部分通过必须说明通过范围。
- 保存后显示“人工验收记录已保存”，不能显示“获得慧浪认证”。
- 列表分页刷新，导出只导出当前记录。

### 13.2 JSON 导出

导出包含：

- 套装和 manifest 版本、安装计划、实例、镜像和硬件指纹。
- 验收档位、结果、人工指标、检查项、备注、操作者别名和时间。
- `recordType: manual_acceptance`，以及不代表自动认证的说明。

导出排除：账号密码、Cookie、Token、NAS 凭据、签名 URL、完整内部下载 URL 和未脱敏连接信息。

### 13.3 `HardwareBundleMatch` 硬件页卡片

位置与布局：

- 作为现有硬件页的一个轻量卡片，不改变 GPU 列表和原 2 秒采集布局。
- 标题“模型套装匹配”，显示推荐认证候选／实验／未知数量。
- 最多列出三个相关套装及一条原因，提供“查看全部套装”。
- 点击跳模型中心组合套装标签并带硬件筛选上下文。

请求策略：

- 硬件摘要和套装摘要复用，不在每次 2 秒 GPU 轮询时请求套装。
- 只在卡片首次可见、手动刷新或硬件代际摘要变化时按需加载。
- 无 GPU／采集失败保留最后成功数据并标“数据过期”。
- 接口失败不影响原硬件指标和 GPU 告警。

## 十四、WP10：性能、可靠性和安全专项

### 14.1 后端性能优化清单

| 项目 | 实施动作 | 验证方式 |
| --- | --- | --- |
| 扫盘 | 一次请求一个仓库快照，五套装共享 | 统计扫描调用次数，不能每卡片一次 |
| SHA256 | 列表零全量 hash；终态或显式校验才流式计算 | 大文件打开列表无高 IO |
| 下载并发 | 每计划同时最多一个子任务 | 故障测试中观察活动子任务数 |
| 文件 IO | 下载、导入、hash 全流式，限制缓冲区 | 大文件测试内存不随文件大小增长 |
| SQLite | 状态变化立即写，字节进度限流写，终态强制写 | 统计写入频率，无每分片写入 |
| 详情查询 | installId 单查，历史分页 | 不重复聚合全部任务 |
| 硬件采集 | 套装摘要共享一次硬件结果 | 五卡片只产生一次采集 |
| 缓存失效 | 下载终态、导入、删除、手动刷新后失效 | 状态及时更新且无陈旧复用 |

建议验收预算：常规仓库、缓存有效时套装摘要不产生大文件读取；活动安装只存在一个子任务；连续 30 分钟进度刷新无 goroutine、内存或 SQLite 句柄持续增长。具体响应耗时在参考机实测记录，不预先虚构数字。

### 14.2 前端性能优化清单

- 套装摘要有独立请求生命周期，不塞进全局 3 秒轮询。
- 活动安装只轮询当前 installId；页面隐藏和抽屉关闭立即停止。
- `getJSON` 传 AbortSignal；新写请求如需可取消封装，沿用 `sendJSON` 风格扩展，不破坏既有调用。
- 筛选和选项展开本地计算，避免每次点击请求完整详情。
- 大列表折叠，不为五行卡片创建五套扫描和硬件请求。
- 已有内容刷新保持布局，骨架只用于首次加载，避免闪烁和布局位移。
- 硬件卡片独立于 2 秒轮询，Tasks 继续既有 5 秒刷新和 300 ms 搜索防抖。
- 定时器、AbortController、事件监听在卸载时全部清理。
- 慢请求返回乱序时以最新请求为准，旧响应不得覆盖新选择。

### 14.3 页面通用状态验收

每个新页面／弹窗都逐项检查：

- 首次加载、刷新加载、空数据、筛选无结果。
- 首次请求失败、后台刷新失败、离线、超时。
- 部分成功、必需失败、可选失败、冲突和重复提交。
- 按钮连点、键盘 Enter 重复提交、请求乱序。
- 375 px 移动布局、200% 缩放、长英文路径和长中文错误。
- 键盘焦点、Esc、焦点回收、屏幕阅读器状态文本。
- 浏览器控制台无未处理 Promise、React key 和重复请求警告。

### 14.4 安全专项

- manifest 和导入路径防穿越，目标目录解析后仍在受控根目录。
- 拒绝通过符号链接逃逸模型仓库和 `/data/import`。
- 所有下载源和重定向继续 SSRF／白名单检查。
- 写接口全部认证、CSRF／Origin、参数长度和枚举校验。
- 不将 URL 查询串和凭据写入日志、审计、任务、验收或浏览器持久化存储。
- JSON 导出设置安全文件名和正确 Content-Type，不包含可执行 HTML。
- 新页面外链使用安全的新窗口属性。
- 发布包扫描权重、测试 Token、内网地址凭据和大型临时文件。

## 十五、WP11：测试实施与验收矩阵

### 15.1 后端单元和集成测试

| 模块 | 必测步骤 | 通过标准 |
| --- | --- | --- |
| manifest | 缺必需项、循环依赖、非法路径、浮动 revision、错误 hash、重复目标 | 启动校验给出具体字段并拒绝错误清单 |
| 选项展开 | S2 继承、S3 Turbo 互斥、S4 独立 Turbo、S5 共享文件 | INT8／NVFP4 同时保留，只有精确同 hash 去重 |
| 状态 | 缺失、部分、复用、下载中、冲突、齐备 | 文件／关联／人工验收／认证不串状态 |
| 硬件 | Spark、PRO 6000、4090／5090、未知、无 GPU、过期数据 | 不建议和未知不猜测，实验标签不消失 |
| 镜像 | Core 满足、老镜像、模板未知、digest 缺失 | Core 通过不代表节点／模板通过 |
| 磁盘 | 完整文件、分片、共享文件、导入复制、NAS、安全余量 | 不重复计数，不足时给出差额 |
| 许可 | 未确认、同版本、旧版本、伪造 operator | 后端独立校验，旧确认不复用 |
| 安装幂等 | 同 requestKey、双击、两个并发请求 | 返回同一计划，仅一个 worker |
| 串行 | 五文件计划、可选项、已有文件 | 任一时刻最多一个子任务 |
| 暂停恢复 | 下载中暂停、续传、重启、完成后崩溃 | 状态可恢复，不重复下载成功项 |
| 完整性 | 大小错、hash 错、同名不同 hash、换源 | 不覆盖、不篡改 expected hash |
| 关联 | 已有链接、并发修改、旧实例、部分失败 | 合并不移除，冲突不覆盖 |
| 任务中心 | 聚合、筛选、详情、删除、清理 | 套装任务可见且活动计划不被误清理 |
| 验收 | 通过／失败／部分、分页、导出、认证字段 | 人工记录不改认证，JSON 脱敏 |
| 迁移 | 旧库升级、重复启动、旧版回滚、再升级 | 数据和历史保留，旧功能零回归 |

### 15.2 前端组件测试

- 五张卡片内容、标准／实验、许可和认证标签正确。
- 筛选、刷新失败、离线和空态不丢上下文。
- S3 Turbo 默认不选且互斥；活动计划选项只读。
- S5 文件清单同时显示图像 INT8 和视频 NVFP4 编码器。
- 向导选项变化使旧预检失效，阻断项不能跳过。
- 创建成功显示“计划已创建”，409 打开原计划。
- 进度终态停止轮询，卸载触发 abort，页面隐藏无套装请求。
- 关联预览不移除已有项，部分失败逐项展示。
- 人工指标未填写不显示 0，保存后仍标“人工记录”。
- 硬件卡片失败不影响原硬件页，Tasks 类型和跳转正确。

### 15.3 E2E 主流程

1. 管理员登录，进入模型中心组合套装。
2. 打开 S1，查看文件、硬件、许可和空验收历史。
3. 选择变体，执行预检，确认许可，创建计划。
4. 观察单文件串行、暂停、继续和最终文件齐备。
5. 选择现有实例，预览并合并链接，确认原有模型仍在。
6. 新增人工验收记录并导出 JSON，认证状态仍为待认证。
7. 在统一任务中查看套装任务并返回详情。
8. 对 S3 注入失败，只重试失败项；可选 Turbo 失败不污染基础齐备。
9. 对 S4／S5 验证实验提示贯穿卡片、详情、向导、进度和验收。
10. 回归本地仓库搜索、普通下载、导入、删除、NAS 和原实例关联。

### 15.4 故障注入和恢复测试

- 下载 10%／90% 时断网，恢复后续传。
- 下载中暂停并重启服务，显示待继续。
- 子任务完成、套装项未落库时重启，启动后补状态。
- 写盘失败、磁盘不足、目标文件外部修改、hash 不符。
- 创建计划响应丢失后重试，不生成重复任务。
- 关联读取后另一操作修改实例链接，返回冲突而非覆盖。
- SQLite 暂时写失败， worker 不继续宣称成功。
- 页面关闭和浏览器离线，后台计划状态不被前端伪造。

### 15.5 实机分层验收

| 层级 | 执行内容 | 发布含义 |
| --- | --- | --- |
| 软件功能 | 无 GPU 模拟＋Spark 升级、安装、恢复、回滚 | 通过后可发布编排软件 |
| Spark H3 | 人工执行 S3 的 5 秒 T2V／I2V，检查视频和音频 | 只登记人工记录 |
| Spark H3-Image | 人工执行 S1 的 4 MP T2I／单参考编辑 | 只登记人工记录 |
| PRO 6000 | 有设备后执行 S2 的 4 MP／16 MP／多参考 | 未测保持待认证 |
| S4／S5 | 实验安装和人工观察 | 不转销售认证 |

真实模型下载和生成不作为普通 CI 固定步骤；实测结果单独记录环境、时间、输入和证据。

## 十七、WP13：升级、回滚与 Go／No-Go

### 17.1 升级演练

1. 在 `0.1.0.3` 准备已有模型、实例链接、下载任务和验收前数据。
2. 创建 SQLite 自动快照并确认可恢复。
3. 升级 RC，检查 Version 5 只追加新表。
4. 创建一个套装计划，完成部分文件、许可和人工验收。
5. 验证旧模型、实例、下载、任务和审计仍可访问。
6. 重复启动 RC，确认迁移幂等、计划恢复正确。

### 17.2 回滚演练

1. 健康门失败或严重回归时回滚 `flowpilot-web:0.1.0.3`。
2. 保留 Version 5 新表，不执行向下删除迁移。
3. 已完成模型、下载分片、实例已有链接和验收历史不自动删除。
4. 回滚期间活动套装计划停止由新版 worker 控制；再升级后按真实子任务状态恢复为待继续或可续装。
5. 再升级 RC，确认安装和验收历史仍在，文件不重复下载。
6. 若需撤销错误关联，单独生成差异预览，只处理本次新增项，不全量清空。

### 17.3 Go／No-Go 检查单

以下全部为“是”才可正式发布：

- [ ] 五个 manifest 的来源、revision、大小、hash、依赖和许可已复核。
- [ ] S1～S3 的预检→许可→安装→校验→关联闭环通过。
- [ ] S4／S5 所有入口均为实验，不含销售承诺。
- [ ] 文件齐备、人工验收和慧浪认证始终分开。
- [ ] S5 的 INT8 与 NVFP4 编码器未错误去重。
- [ ] 单文件串行、幂等、暂停、续传、取消、重试和重启恢复有测试证据。
- [ ] 实例关联不会移除已有模型，并发冲突有保护。
- [ ] 套装任务能进入列表、详情、删除和清理，不破坏既有任务。
- [ ] 页面打开不做全量 hash，隐藏／关闭后无套装轮询泄漏。
- [ ] 所有写 API 的认证、CSRF／Origin、参数校验和审计通过。

任一必需项为“否”则保持 RC，不通过隐藏错误、修改文案或跳过回归强行发布。

## 十八、实施过程中的决策暂停点

以下情况出现时不由实施人员自行扩大范围，需要再次请周董决策：

1. 真实资产无法取得不可变 revision、精确 hash 或许可快照，是否将该套装仅保留为不可安装预览。
2. 主备源内容不一致，是否下架备用源或延后该套装。
3. 现有下载管理器无法安全暂停／恢复子任务，是否缩小首版暂停能力，而不是重写下载引擎。
4. 实例链接缺少可靠并发保护，是否首版仅提供差异预览和手动确认，不做自动关联。
5. 真实硬件结果与候选矩阵不符，只更新人工记录和后续审核，不在本版暗中改“已认证”。
6. 为修复问题需要改 PyTorch、镜像系统、实例创建向导或多 GPU 时，拆出新版本，不并入 `0.1.0.4`。
