# 慧浪智算·FlowPilot MVP 产品需求文档

> 文档性质：立项评审稿
> 项目版本：0.0.9.11
> 产品阶段：MVP
> 编写日期：2026-11-04
> 产品品牌：慧浪智算
> 产品名称：FlowPilot
> 首发副标题：ComfyUI 一体化部署与管理平台

---

## 1. 项目背景

ComfyUI 的生产部署通常涉及 GPU 驱动、Docker、NVIDIA 容器运行环境、端口、模型目录、数据持久化及版本兼容等配置。对交付人员和最终客户而言，重复部署成本高，失败原因分散，后续运维缺少统一入口。

慧浪智算计划将 FlowPilot 预装于自有 GPU 服务器，同时提供在线和离线安装形态，使交付人员与客户能够通过 Web 界面完成 ComfyUI 和模型的部署及日常管理。

## 2. 产品定位

### 2.1 一句话定义

FlowPilot 是面向 GPU 服务器的轻量化 AI 工作流交付与管理平台，MVP 聚焦单机 ComfyUI，通过一次安装和可视化操作，实现环境检测、容器化部署、模型管理及实例运维。

### 2.2 产品价值

- **对交付人员**：减少重复命令操作，形成标准化交付流程。
- **对最终客户**：无需掌握 Docker 和 ComfyUI 部署细节即可使用。
- **对售后人员**：统一查看环境、实例、任务和日志，缩短排障路径。
- **对慧浪智算**：形成可预装、可复用、可迭代的服务器软件交付能力。

### 2.3 产品原则

1. 单机优先、轻量优先，不引入 Kubernetes。
2. 所有 ComfyUI 实例优先通过 Docker 运行。
3. 安装过程可重复执行，失败后可恢复。
4. 镜像、实例、模型和任务状态必须可观察。
5. 容器与业务数据分离，默认保护模型、工作流和输出。
6. 首发版本控制边界，以稳定交付闭环优先于功能数量。

## 3. 项目目标与验收指标

### 3.1 MVP 目标

- 在兼容的 Ubuntu GPU 服务器上，通过一个在线脚本或离线包完成管理平台安装。
- 自动识别主机硬件和容器运行条件，给出可执行的检查结果。
- 用户可通过 Web 新建、启动、停止、重启和删除 ComfyUI 实例。
- 用户可通过 URL 或服务器本地文件导入模型，并管理下载任务。
- 多个实例共享统一模型仓库，避免重复存储。
- 实例重启后，其配置、工作流、输入和输出数据保持不变。
- 提供基础认证、操作日志和诊断包导出能力。

### 3.2 验收指标

以下为 MVP 验收目标，不作为未测试前的现状承诺：

| 指标 | 验收目标 |
|---|---|
| 安装闭环 | 在定义的兼容测试矩阵内，无需手工编写 Docker 命令即可进入 Web 控制台 |
| 部署闭环 | 从实例创建到健康检查通过，全流程可在 Web 完成 |
| 安装可恢复性 | 安装脚本重复执行不破坏已有配置和业务数据 |
| 数据持久化 | 容器停止、重启和重新创建后，实例业务数据不丢失 |
| 下载可恢复性 | 服务端支持 Range 时，模型下载可断点续传；不支持时明确提示并重新下载 |
| 异常可诊断 | 安装、部署和下载失败均展示错误原因、任务日志及建议处理方式 |
| 管理面轻量化 | 管理服务自身空闲内存目标不超过 200 MB，不含 Docker、ComfyUI 和模型进程 |

## 4. 用户与使用场景

### 4.1 目标用户

| 用户 | 核心诉求 |
|---|---|
| 出厂交付工程师 | 批量预装、离线部署、快速验证服务器可用性 |
| 客户系统管理员 | 创建和维护 ComfyUI 实例，管理模型和存储 |
| AI 业务人员 | 获取可访问的 ComfyUI 地址，使用已准备完毕的模型 |
| 售后支持人员 | 获取硬件、实例和任务日志，定位交付问题 |

### 4.2 核心场景

1. 新 GPU 服务器到货后，执行一次安装并完成初始化。
2. 交付人员选择已验证的 ComfyUI 模板，分配 GPU 和端口后创建实例。
3. 客户通过 URL 下载模型，或从随机交付的模型包导入模型。
4. 管理员停止、重启或删除实例，并保留需要的数据。
5. 部署失败时，管理员导出诊断包并提交给慧浪智算售后。

## 5. MVP 范围

### 5.1 首发兼容范围

- 操作系统：Ubuntu 22.04 LTS、Ubuntu 24.04 LTS。
- 架构：x86_64。
- GPU：NVIDIA GPU，具体型号列入项目测试矩阵。
- 容器：Docker Engine＋NVIDIA Container Toolkit。
- 部署形态：单服务器、单管理节点、单管理员。
- 访问方式：浏览器访问 Web 管理控制台。

### 5.2 MVP 包含

- 在线安装脚本和离线安装包。
- 硬件、驱动、Docker 和 NVIDIA 容器环境检测。
- 单管理员初始化、登录和密码修改。
- ComfyUI 实例全生命周期管理。
- GPU 分配、端口分配和开机自启配置。
- 模型 URL 下载、本地导入、暂停、继续、取消和删除。
- 全局共享模型仓库。
- 任务中心、实例日志和基础操作日志。
- 环境报告与诊断包导出。
- 默认数据保护及删除二次确认。

### 5.3 MVP 不包含

- 多服务器集中管理和集群调度。
- 多租户、角色权限、计费和配额审批。
- 自动安装、升级或更换 NVIDIA 显卡驱动。
- 在 Web 中安装和升级 ComfyUI 自定义节点。
- Hugging Face、ModelScope 等专用模型源连接器。
- 模型文件浏览器上传。
- 平台及 ComfyUI 一键升级、回滚。
- HTTPS 自动证书申请；生产需要时由现有反向代理提供。
- 自研工作流编辑器。

### 5.4 关键范围决策

1. **驱动处理**：MVP 只检测 NVIDIA 驱动，不自动变更驱动，避免影响既有 GPU 业务。
2. **模型共享**：MVP 使用全局共享模型库，所有就绪模型对实例可见，不做实例级模型授权。
3. **模板数量**：首发只提供 1～2 个经过慧浪智算验证的 ComfyUI 镜像模板，不开放任意镜像直接运行。
4. **实例数量**：软件允许创建多个实例，但实际可运行数量由 GPU、显存、内存和磁盘决定，系统只做资源预检，不承诺超卖调度。

## 6. 核心概念与状态定义

### 6.1 核心对象

| 对象 | 定义 |
|---|---|
| 镜像模板 | 经平台验证的 ComfyUI 镜像、版本、硬件要求、挂载约定和启动参数集合 |
| 实例 | 由模板创建的一套 ComfyUI 容器及其独立业务数据 |
| 模型 | 全局模型仓库中的一个受管文件及其元数据 |
| 任务 | 镜像拉取、模型下载、模型导入、实例创建等异步操作 |
| 环境报告 | 主机硬件、驱动、Docker、端口和存储检查结果 |

### 6.2 实例状态

- `创建中`：正在校验参数、准备目录或拉取镜像。
- `启动中`：容器已创建，正在等待健康检查。
- `运行中`：容器运行且健康检查通过。
- `停止中`：正在停止容器。
- `已停止`：容器处于停止状态。
- `重启中`：正在执行重启。
- `删除中`：正在删除容器及所选数据。
- `异常`：容器退出、健康检查失败或管理状态与 Docker 状态不一致。

### 6.3 模型与下载状态

- `等待中`、`下载中`、`已暂停`、`校验中`、`就绪`、`失败`、`已取消`、`删除中`。
- 模型只有进入“就绪”状态后才写入正式模型目录。
- “启动／停止模型”不作为产品术语；模型的可执行操作是下载、暂停、继续、取消、导入和删除。

### 6.4 状态一致性

后端以 Docker 实际状态为准进行周期 reconcile。管理端数据库不得长期覆盖或伪造容器真实状态；状态不一致时标记异常并记录事件。

## 7. 信息架构与页面结构

### 7.1 全局导航

```text
初始化页／登录页
└── 管理控制台
    ├── 首页看板
    ├── ComfyUI 实例
    │   ├── 实例列表
    │   ├── 新建实例
    │   └── 实例详情
    │       ├── 概览
    │       ├── 日志
    │       └── 配置
    ├── 模型中心
    ├── 任务中心
    └── 系统管理
        ├── 环境检测
        ├── 系统设置
        ├── 操作日志
        └── 诊断与关于
```

### 7.2 全局布局

- 左侧：一级导航及当前选中状态。
- 顶部：产品标识、主机名、进行中任务数量、管理员菜单。
- 内容区：页面标题、主要操作、筛选区、数据区。
- 全局任务入口：展示正在执行的部署和下载任务，失败任务突出提示。
- 危险操作：统一使用确认弹窗，不使用列表中的无确认直接删除。

### 7.3 初始化页

**路由建议**：`/setup`

仅未完成初始化的实例可访问。

页面内容：

- 管理员密码和确认密码。
- 管理访问地址展示；管理端口在安装阶段配置。
- 数据根目录展示；MVP 初始化后不允许直接在 Web 修改。
- 管理网访问提示，不建议直接暴露公网。
- 初始化结果及“进入控制台”按钮。

初始化成功后，一次性令牌立即失效，初始化页不可再次使用。

### 7.4 登录页

**路由建议**：`/login`

- 密码输入、登录、失败提示。
- 连续失败进行基础频率限制。
- 不提供自助找回密码；通过服务器命令行执行管理员密码重置流程。

### 7.5 首页看板

**路由建议**：`/dashboard`

展示内容：

1. 主机名称、操作系统、运行时间和管理平台版本。
2. CPU 型号、架构、核心数、实时利用率。
3. 内存总容量、已用容量、使用率和内存类型；存储总容量、已用容量、使用率及数据挂载说明。
4. GPU 数量、平均利用率，以及每张 GPU 的编号、型号、在线状态、计算利用率、核心温度、当前功耗／功耗上限、显存或共享内存容量与占用。
5. 实例统计：运行中、已停止、异常。
6. 模型统计：就绪数量、总占用空间。
7. 进行中任务和最近失败任务。
8. 快捷操作：新建实例、下载模型、重新检测环境。

硬件形态与内存规则：

- 支持单卡及多卡 GPU 服务器，界面至少适配 1～16 个设备；多卡使用响应式紧凑网格，不因卡数增加造成页面横向溢出。
- 独立显卡服务器展示系统内存和逐卡独立显存，显存总量可按卡累计。
- DGX Spark 等统一内存设备展示 CPU／GPU 共享内存，不重复累计为“系统内存＋显存”；不支持独立显存占用采集时明确降级说明。
- DGX Station GB300 等一致性内存设备分别表达 CPU 内存、GPU HBM 和一致性地址空间，不与普通统一内存或独立显存混用。
- 实时数据必须标明采集时间和来源；采集失败时保留最近快照并标记过期，不以模拟数据替代真实监控。

异常规则：

- 数据盘不足、Docker 不可用、GPU 不可用时显示阻塞性告警。
- 单块 GPU 被多个实例分配时显示资源冲突提醒。
- GPU 高温、功耗或遥测采集中断时按设备显示告警，不影响其他设备信息展示。

### 7.6 实例列表

**路由建议**：`/instances`

列表字段：

- 实例名称。
- ComfyUI 版本／模板。
- 状态。
- GPU 编号及型号。
- 访问地址。
- 开机自启。
- 数据目录。
- 创建时间。

支持操作：

- 新建、启动、停止、重启、删除。
- 打开 ComfyUI。
- 查看详情和日志。
- 按状态筛选、按名称搜索。

操作限制：

- 创建中、删除中禁止重复操作。
- 运行中才能打开 ComfyUI。
- 端口或 GPU 冲突时禁止启动，并显示冲突实例。

### 7.7 新建实例

**路由建议**：`/instances/new`

采用四步向导：

#### 第一步：选择模板

- 模板名称、ComfyUI 版本、镜像大小、最低显存建议。
- 显示当前驱动、GPU 和磁盘预检结果。
- 只允许选择启用且经过验证的模板。

#### 第二步：资源配置

- 实例名称：唯一，1～32 个字符。
- GPU：单选；MVP 每实例分配一块 GPU。
- 管理访问端口：默认从 8188 起自动选择空闲端口。
- 是否开机自启。
- 可选启动参数：使用模板白名单，不开放任意 Docker 参数。

#### 第三步：模型准备

- 显示全局模型及其状态，已就绪模型可直接使用。
- 可勾选尚未就绪的模型，在部署前创建并等待对应下载任务。
- 显示待下载模型总大小与剩余磁盘空间。
- 允许跳过模型准备，先创建空实例。

#### 第四步：确认与部署

- 汇总模板、GPU、端口、数据目录和模型。
- 提交后进入任务详情。
- 支持失败重试；重试不得创建重复容器或重复数据目录。

### 7.8 实例详情

**路由建议**：`/instances/:id`

#### 概览

- 状态、访问地址、模板、镜像摘要、GPU、端口。
- 容器 ID、创建时间、最近启动时间、重启次数。
- 数据目录、输出目录、磁盘占用。
- 启动、停止、重启、打开 ComfyUI、删除。

#### 日志

- 实时容器日志和历史日志。
- 按时间、关键字查询。
- 下载当前实例日志。
- 日志区不展示密码、代理凭据和访问令牌。

#### 配置

- 查看实例名称、GPU、端口和自启配置。
- MVP 允许修改自启配置。
- GPU 和端口仅允许在实例停止后修改；修改前重新校验资源冲突。
- 模板版本不在原实例上直接变更或升级，避免 MVP 引入迁移和回滚复杂度。

### 7.9 删除实例

提供两种明确选项：

1. **仅删除实例容器和管理记录**：默认保留实例业务数据，标记为“未纳管遗留数据”。
2. **删除实例及业务数据**：删除工作流、输入、输出和独立配置，需要输入实例名称确认。

共享模型始终不随实例删除。删除任务必须可审计。

### 7.10 模型中心

**路由建议**：`/models`

列表字段：

- 模型名称、类型、文件大小。
- 来源、状态、下载进度。
- 存储位置、校验值。
- 创建时间。

支持操作：

- URL 下载。
- 从服务器本地路径导入。
- 暂停、继续、取消、重试。
- 删除模型。
- 查看模型详情和关联任务。

模型类型：

- Checkpoints、LoRA、VAE、ControlNet、Embeddings、Upscale Models、其他。

URL 下载表单：

- 下载地址、模型名称、模型类型、可选 SHA256。
- 文件名经过规范化，禁止路径穿越。
- 磁盘空间不足时禁止提交。

本地导入表单：

- 服务器绝对路径、模型名称、模型类型、可选 SHA256。
- 仅允许读取安装配置中声明的导入目录。
- 默认复制到受管模型库；MVP 不直接纳管任意外部路径。

删除规则：

- 删除为物理文件删除，需二次确认。
- 存在运行中的 ComfyUI 实例时，MVP 采用保守策略，禁止删除模型文件，并提示先停止实例。
- 删除模型不影响实例配置、工作流和输出。

### 7.11 任务中心

**路由建议**：`/tasks`

任务类型：

- 环境检测、镜像拉取、实例创建、模型下载、模型导入、诊断包导出。

展示字段：

- 任务类型、关联对象、状态、进度、速度、已用时间、创建时间。

任务详情：

- 分阶段步骤及当前步骤。
- 可下载日志。
- 可取消、重试或查看失败建议。
- 服务重启后恢复任务状态；无法安全续执行的任务标记失败并允许重试，不能长期停留在“进行中”。

### 7.12 系统管理

#### 环境检测

- CPU、内存、GPU、显存、驱动、Docker、NVIDIA Container Toolkit。
- 数据盘容量、端口占用、时间同步状态。
- 一键重新检测、复制报告、导出报告。

#### 系统设置

- 管理端口和访问地址展示。
- 镜像仓库／镜像加速地址。
- HTTP／HTTPS 代理配置。
- 数据根目录和允许导入目录展示。
- 管理员密码修改。
- 敏感配置写入页面和日志时必须脱敏。

#### 操作日志

- 登录、实例操作、模型删除、系统设置修改。
- 操作者、时间、来源 IP、对象、结果和失败原因。

#### 诊断与关于

- FlowPilot 版本、模板版本、浏览器兼容性说明。
- 一键导出诊断包。
- 诊断包包含环境报告、服务日志、实例元数据和任务日志，不包含管理员密码、会话和代理密码。

## 8. 核心业务流程

### 8.1 首次使用流程

```text
执行安装
→ 获取管理地址和一次性令牌
→ 打开初始化页
→ 设置管理员密码
→ 查看环境报告
→ 新建 ComfyUI 实例
→ 选择模板、GPU、端口和模型
→ 等待镜像及模型任务完成
→ 健康检查通过
→ 打开 ComfyUI
```

### 8.2 实例创建流程

1. 校验模板、名称、GPU、端口和磁盘空间。
2. 在数据库创建实例和任务记录。
3. 创建实例数据目录并写入配置。
4. 拉取固定版本镜像并校验摘要。
5. 创建容器，配置 GPU、端口、挂载和重启策略。
6. 启动容器并执行健康检查。
7. 健康检查通过后标记“运行中”。
8. 任一步骤失败均记录失败阶段；重试从可安全恢复的步骤继续。

### 8.3 模型下载流程

1. 校验 URL、模型类型、文件名和磁盘空间。
2. 创建任务，在临时下载目录写入 `.part` 文件。
3. 定期持久化下载字节数和临时文件位置。
4. 下载完成后计算校验值；用户未提供 SHA256 时记录实际计算结果。
5. 校验通过后以原子重命名进入正式模型目录。
6. 数据库状态更新为“就绪”。
7. 失败保留日志；是否保留临时文件由“可续传”状态决定。

## 9. 安装流程设计

### 9.1 安装形态

#### 在线安装

交付一个版本化安装脚本，下载固定版本的程序包并校验 SHA256。不得使用无版本约束的 `latest` 作为正式发布依赖。

#### 离线安装

离线包包含：

- 安装及卸载脚本。
- FlowPilot 后端程序与前端静态资源。
- 默认配置和镜像模板清单。
- ComfyUI Docker 镜像归档。
- 对应 Ubuntu 版本所需的 Docker／NVIDIA 容器组件离线依赖。
- 文件清单、版本信息和 SHA256 校验文件。
- 安装说明和故障处理说明。

模型包与主程序包分离，避免基础离线包过大。

### 9.2 安装步骤

| 步骤 | 行为 | 失败处理 |
|---|---|---|
| 1. 权限检查 | 要求 root 或 sudo；识别是否已有安装 | 非权限用户直接退出并提示 |
| 2. 系统检查 | 检查 Ubuntu 版本、架构和必要命令 | 不兼容时输出明确原因 |
| 3. 硬件检查 | 采集 CPU、内存、磁盘、GPU 和驱动 | 驱动缺失只告警，不自动变更驱动 |
| 4. Docker 检查 | 复用可用 Docker；缺失时在线或离线安装 | 不覆盖已有有效配置 |
| 5. NVIDIA 容器检查 | 验证容器内 GPU 可用性 | 失败则允许管理平台安装，但阻塞 GPU 实例创建 |
| 6. 参数确认 | 设置安装目录、数据目录、端口和镜像仓库 | 提供默认值，支持命令行参数覆盖 |
| 7. 文件安装 | 写入二进制、前端、模板和配置 | 先写临时位置，再原子替换 |
| 8. 镜像准备 | 拉取或导入模板镜像并校验摘要 | 失败可重试，不影响已安装程序 |
| 9. 服务启动 | 配置并启动 systemd 服务 | 输出服务状态和日志位置 |
| 10. 健康检查 | 检查本地管理 API 和数据库 | 失败返回非零退出码 |
| 11. 输出信息 | 展示管理地址和一次性初始化令牌 | 令牌文件权限仅 root 可读 |

### 9.4 安装脚本要求

- 幂等：重复执行不会清空数据库、模型或实例数据。
- 可审计：完整安装日志保存到独立文件。
- 可失败：任一步骤失败返回非零退出码。
- 可恢复：再次执行可跳过已完成且校验通过的步骤。
- 可配置：支持数据目录、端口、镜像仓库和离线包路径参数。
- 可卸载：默认保留业务数据；只有显式参数才允许删除数据根目录。
- 不执行与产品无关的系统优化，不自动关闭防火墙，不自动替换 GPU 驱动。

## 10. 容器与数据规划

### 10.1 容器设计

- 每个 ComfyUI 实例对应一个独立 Docker 容器。
- 后端通过 Docker API 管理容器，不依赖用户安装 Docker Compose。
- 容器统一添加 `managed-by=flowpilot` 和实例 ID 标签。
- 镜像使用版本标签与不可变摘要，不使用浮动 `latest`。
- 仅映射指定 ComfyUI 服务端口，不映射 Docker Socket 到业务容器。
- 业务容器不使用 `--privileged`，仅申请指定 GPU。
- 共享模型目录只读挂载，实例目录读写挂载。
- 健康检查路径、超时和启动等待时间由模板定义。
- 开机自启实例使用受控重启策略；用户主动停止后不得被自动拉起。


### 10.3 容器挂载约定

| 主机目录 | 容器目录 | 权限 | 用途 |
|---|---|---|---|
| `instances/<id>/workspace` | `/workspace` | 读写 | 工作流、输入、输出、自定义节点和临时数据 |
| `instances/<id>/config` | `/flowpilot/config` | 只读 | 实例配置和模型路径配置 |
| `models` | `/models` | 只读 | 全局共享模型库 |

容器内 ComfyUI 程序本体保留在镜像中，不放进实例可写目录。镜像入口根据模板约定，将 `/workspace` 和 `/models` 接入 ComfyUI；具体内部路径由镜像模板声明，后端不硬编码某一镜像的私有目录结构。

### 10.4 数据归属

| 数据 | 生命周期 |
|---|---|
| ComfyUI 程序及依赖 | 随镜像版本管理 |
| 实例配置 | 随实例保留，默认不随容器删除 |
| 工作流、输入、输出 | 随实例业务数据保留 |
| 自定义节点 | MVP 由镜像预置；目录持久化，后续版本开放管理 |
| 模型 | 全局共享，独立于实例生命周期 |
| 下载临时文件 | 随任务管理，可续传或清理 |
| 平台数据库 | 随平台保留，卸载默认不删除 |

### 10.5 端口与 GPU 分配

- 平台数据库记录已分配端口和 GPU，同时启动前检查主机真实占用。
- MVP 每个实例只能绑定一块 GPU。
- 同一块 GPU 默认不分配给多个“运行中”实例；停止实例可以保留原 GPU 绑定。
- 删除实例后释放端口和 GPU 锁。
- Docker 与实际状态不一致时，以实测结果为准并提示异常。

### 10.6 磁盘保护

- 创建实例、拉取镜像、下载模型前执行空间预检。
- 预检除文件大小外，保留可配置的安全余量。
- 磁盘低于告警阈值时，首页提示；低于阻塞阈值时禁止新增下载和部署。
- 不允许通过模型名称、URL 文件名或实例名称逃逸受管目录。

## 11. 技术方案约束

### 11.1 推荐架构

- 后端：Go 单二进制服务。
- 前端：React 19＋TypeScript（Vite 构建，后端托管静态资源；原设想的 Vue 3 已在实现中调整为 React）。
- 数据库：嵌入式 SQLite（0.0.9.5 起落地，modernc.org/sqlite 纯 Go 驱动）。
- 容器控制：Docker API。
- 系统服务：容器化交付（`--restart unless-stopped`），不依赖 systemd；systemd 服务配置作为可选增强保留。
- 实时日志和进度：SSE（实例日志流已落地，WebSocket 不再采用）。
- CLI：提供状态查看、密码重置、诊断导出和卸载辅助命令。

### 11.2 内部 API 建议

| 领域 | API 示例 |
|---|---|
| 初始化与登录 | `POST /api/v1/setup`、`POST /api/v1/auth/login` |
| 环境 | `GET /api/v1/environment`、`POST /api/v1/environment/check` |
| 模板 | `GET /api/v1/templates` |
| 实例 | `GET/POST /api/v1/instances`、`GET/PATCH/DELETE /api/v1/instances/{id}` |
| 实例动作 | `POST /api/v1/instances/{id}/start|stop|restart` |
| 实例日志 | `GET /api/v1/instances/{id}/logs` |
| 模型 | `GET/POST /api/v1/models`、`DELETE /api/v1/models/{id}` |
| 任务 | `GET /api/v1/tasks`、`GET /api/v1/tasks/{id}` |
| 任务动作 | `POST /api/v1/tasks/{id}/pause|resume|cancel|retry` |
| 系统 | `GET/PATCH /api/v1/settings`、`GET /api/v1/audit-logs` |
| 诊断 | `POST /api/v1/diagnostics/export` |

所有变更接口必须校验登录状态；异步操作统一返回任务 ID。

### 11.3 核心数据实体

- `Instance`：名称、模板、镜像摘要、GPU、端口、状态、自启、目录、时间戳。
- `Model`：名称、类型、来源、路径、大小、SHA256、状态、时间戳。
- `Task`：类型、对象 ID、状态、阶段、进度、错误码、重试来源、时间戳。
- `Template`：版本、镜像、摘要、硬件要求、挂载和健康检查定义。
- `Setting`：管理配置、网络配置和存储配置。
- `AuditLog`：操作者、来源、动作、对象、结果和时间。

## 12. 非功能与安全要求

### 12.1 可靠性

- FlowPilot 服务异常退出后由 systemd 拉起。
- 服务启动时执行数据库与 Docker 状态对账。
- 实例和模型操作必须具备幂等键或等价保护，避免重复创建。
- 任务中断后能够恢复或明确失败，不允许状态永久悬挂。

### 12.2 安全

- 初始化令牌仅使用一次，初始化后立即失效。
- 密码只保存强哈希，不明文存储或写入日志。
- 登录接口进行频率限制，会话具备过期机制。
- 默认面向管理网使用，安装完成页明确提示不要直接暴露公网。
- 代理密码、令牌等敏感字段在 API 返回和诊断包中脱敏。
- 本地导入限制在允许目录内，防止读取任意服务器文件。
- Shell 调用必须使用参数数组，禁止拼接未校验的用户输入。
- 删除实例数据、删除模型和清除下载文件均为高风险操作，必须确认并审计。

### 12.3 日志

- 平台服务、安装过程、实例、任务和审计日志分类保存。
- 日志采用大小或时间轮转，避免占满数据盘。
- 默认日志保留周期建议 14 天，可配置。
- 日志中不得出现密码、完整会话令牌和代理凭据。

## 13. MVP 验收用例

### 13.1 安装与环境

1. 在兼容 Ubuntu 服务器上完成在线安装，服务健康检查通过。
2. 在无外网测试环境使用离线包完成安装和镜像导入。
3. 重复执行安装脚本，原管理员配置、实例和模型不受影响。
4. Docker 缺失时可安装；已有可用 Docker 时不被替换。
5. GPU 驱动或 NVIDIA 容器环境异常时，报告具体失败项并阻塞实例创建。
6. 管理端口被占用时，安装失败原因明确，可更换端口重试。

### 13.2 实例管理

1. 创建实例后生成唯一容器、独立目录和端口。
2. 启动后健康检查通过，可点击打开 ComfyUI。
3. 停止后 ComfyUI 不可访问，数据目录保留。
4. 重启后工作流、输入和输出数据保留。
5. 端口或 GPU 冲突时禁止启动并指出冲突对象。
6. 仅删除实例时业务数据保留；彻底删除时必须输入实例名称。
7. 删除实例不会删除共享模型。
8. 服务器重启后，自启实例恢复，手动停止实例不被自动拉起。

### 13.3 模型与任务

1. URL 下载完成后计算校验值并进入正确模型分类目录。
2. 支持 Range 的下载任务可暂停和继续，不重复下载已完成部分。
3. SHA256 不匹配时模型不进入“就绪”状态。
4. 本地导入仅允许配置目录，越权路径被拒绝。
5. 磁盘不足时禁止开始任务并给出所需空间。
6. 下载失败可查看日志并重试。
7. 存在运行实例时模型物理删除被阻止，并有明确提示。

### 13.4 安全与诊断

1. 初始化后原令牌不能再次使用。
2. 未登录不能调用实例和模型管理接口。
3. 日志和诊断包不包含密码、会话和代理凭据。
4. 诊断包能够辅助确认硬件、Docker、实例和任务问题。

## 16. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| GPU 驱动与容器环境差异 | 安装或实例启动失败 | 明确兼容矩阵，只检测不自动换驱动，提供诊断报告 |
| ComfyUI 及依赖更新较快 | 模板不可用或实例异常 | 固定镜像摘要，镜像由专人维护，验证后再发布模板 |
| 自定义节点依赖复杂 | 实例构建和启动失败 | MVP 仅使用预验证镜像，节点管理后置 |
| 模型文件大且网络不稳定 | 下载慢、磁盘耗尽、任务失败 | 断点续传、空间预检、离线模型包、任务重试 |
| Docker Socket 权限较高 | 管理端被攻破后影响主机 | 管理网隔离、认证、输入校验、最小化接口、审计和公网暴露提示 |
| 多实例资源冲突 | 端口冲突、显存不足 | GPU／端口锁、启动前实测、资源冲突提示 |
| 安装脚本影响已有服务 | 生产事故 | 不覆盖有效 Docker 配置、不改驱动、不关闭防火墙、重复安装保护 |
| 删除操作误解 | 工作流或模型丢失 | 分离容器与数据删除、默认保留、输入名称确认、审计 |

## 19. MVP 完成定义

只有同时满足以下条件，才可认定 MVP 完成：

- 范围内功能全部可用，核心验收用例通过。

- 数据持久化、删除保护、异常恢复和诊断能力通过专项测试。
- 无阻塞发布的严重安全问题。
- 安装包、镜像模板、文档和测试报告可追踪到同一发布版本。
