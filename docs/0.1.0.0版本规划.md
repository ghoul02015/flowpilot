# FlowPilot 0.1.0.0 版本规划

> 文档性质：阶段 1 全模块实施与验收规划  
> 基线版本：`0.0.9.4`  
> 迭代范围：`0.0.9.5`～`0.0.9.16`  
> 正式启用：`0.1.0.0 Community`，仅在全部模块验收通过后启用  
> 本文只做规划，不代表功能已经开发或验收通过。

## 一、已确认决策

| 决策项 | 已确认方案 | 对实施的影响 |
| --- | --- | --- |
| 首发兼容矩阵 | NVIDIA 双架构 | Ubuntu 22.04／24.04；linux/amd64＋linux/arm64；DGX Spark＋至少一种 x86 NVIDIA 多卡服务器 |

## 二、阶段 1 总目标与边界

### 2.1 正式版目标

`0.1.0.0` 应达到以下结果：

- 用户可通过在线或完全离线包安装，在受控管理网或 HTTPS 入口完成初始化。
- 管理平台具备认证、会话、审计、服务端授权和危险操作保护。
- 每个 ComfyUI 实例拥有独立 outputs、workflows、user、config；共享模型只读。
- 容器状态、应用健康和生成队列分层展示。
- 镜像、模型、实例、备份、诊断、升级均进入统一任务体系。
- 管理包、ComfyUI 模板包和模型包独立分发，可追溯、可校验、可回滚。
- 真实 x86 NVIDIA 多卡与 DGX Spark 均通过安装、真实生成、恢复和升级验收。
- 开源仓库、许可证、CI、Release、文档和慧浪出厂交付件同步完成。

### 2.2 阶段 1 不做

- 多用户完整 RBAC、SSO、多租户和计费。
- 多机控制中心、K8s、运行中实例热迁移。
- 单实例多 GPU、GPU 超分和显存隔离承诺。
- 自研工作流编辑器、提示词应用和基础模型。
- 自动升级或替换宿主机 NVIDIA 驱动。
- 不受控在线安装任意自定义节点。
- 将所有在线模型宣传为可商用或可随服务器再分发。

### 2.4 每个版本的固定工程步骤

以下步骤适用于所有版本，后文不再重复展开：

1. **设计冻结：** 记录本版范围、不做项、API／数据库／目录变化、兼容与回滚方案。
2. **测试先行：** 先补失败用例和验收用例，再实现；危险操作必须有后端负向测试。
3. **小步实现：** 后端领域逻辑、API、前端状态、文档分别评审，不用一次性全量重写替代模块改造。
4. **数据兼容：** 每次迁移先备份；记录 schema 版本；重复执行迁移不得重复复制或破坏数据。
5. **性能检查：** 大文件流式处理；列表有分页／上限；后台任务有界并发；页面不可见时降低轮询。
6. **安全复核：** 所有新 API 走认证与授权；敏感值不进日志、审计、URL 和诊断。
7. **版本记录：** 按项目规则更新版本、变更索引和详细变更记录。
8. **独立验收：** 功能、异常、兼容、性能、UI、文档六项全部通过，才能关闭模块。
9. **可回退：** 保留上一版管理镜像和数据快照；回退步骤必须实际演练，而非只写说明。

## 三、`0.0.9.5`——数据底座与现状基线

### 3.1 模块目标

将 Docker 标签中的平台事实逐步迁移到嵌入式 SQLite，为认证、统一任务、模型元数据、审计和升级回滚提供事务基础；本版不改变普通用户主要操作流程。

### 3.2 后端详细修改

1. 引入 SQLite 数据访问层和 `schema_migrations`，迁移包含版本、执行时间、checksum、结果。
2. 建立核心表：`instances`、`instance_configs`、`settings`、`schema_migrations`；为后续用户、任务、审计预留稳定对象 ID 规范。
3. 实例采用 UUID 主键，容器名不再是唯一业务身份；保留 Docker 标签与 UUID 的映射。
4. 编写现有实例导入器：读取 `flowpilot.*` 标签、端口、GPU、镜像、自启动、挂载和模型链接支持状态。
5. 启动时执行“导入→比对→报告”，冲突不静默覆盖；无法识别的容器列入异常清单。
6. 写操作采用事务；实例配置更新同时保证数据库与 Docker 实际状态可核对。
7. SQLite 使用合理 WAL、busy timeout 和外键设置；高频硬件采样不写入业务数据库。
8. 提供数据库备份、检查和只读一致性检查命令；不默认提供任意 SQL Web 控制台。
9. 整理“现状能力矩阵”，清除 PRD／README 中 Vue、SQLite 旧设想、systemd 已实现等文档漂移。

### 3.3 前端与页面布局

- 系统管理新增“数据底座”状态卡：schema 版本、实例映射数、异常映射数、最近一致性检查。
- 异常实例提供“查看差异”，字段分为数据库值、Docker 实际值、采用值和原因。
- 普通实例列表保持现有布局，避免本版同时改导航。
- 加载失败显示迁移错误码与恢复文档入口，不回退成空数据或演示数据。

### 3.4 性能与可靠性优化

- 启动导入只扫描 FlowPilot 管理容器，不遍历无关宿主机资源。
- 所有实例查询建立必要索引，禁止每 2 秒硬件刷新触发数据库重写。
- 迁移与一致性检查有超时和取消；数据库锁冲突返回可重试错误，而非长时间卡死。

### 3.5 验收与回退

- 从 `0.0.9.4` 数据目录升级，所有实例配置完整导入。
- 重复启动、重复迁移结果一致；异常标签不会导致整个平台无法启动。
- 后端测试、API 兼容测试、前端 lint／build、本机 E2E 通过。
- 回退前导出数据库与映射报告；旧版仍能通过标签识别原有实例。

## 四、`0.0.9.6`——认证、安全与操作审计

### 4.1 模块目标

关闭未认证管理 API，形成单管理员安全闭环；默认仍限定受控管理网，不因加入登录就自动宣称可公网开放。

### 4.2 实施步骤

1. 增加初始化状态接口；未初始化时只允许读取初始化状态和提交初始化。
2. 安装时生成一次性初始化令牌，从安装输出或权限为 `0600` 的文件获取；完成后立即失效。
3. 管理员密码使用 Argon2id 或经验证的 bcrypt 哈希；提供密码强度与恢复码。
4. 建立随机会话 ID、服务端会话存储、闲置与绝对过期、注销和密码修改后撤销。
5. Cookie 设置 HttpOnly、SameSite，HTTPS 下 Secure；反向代理正确传递协议和 Host。
6. 对写请求执行 CSRF token、Origin／Host 校验；CORS 默认关闭，不用通配符。
7. 认证中间件覆盖除健康探针和初始化状态外的所有业务 API；静态资源不携带私密配置。
8. 登录限流、失败临时锁定、统一登录错误文案；限制请求头、JSON 和上传大小。
9. 审计记录登录、退出、密码修改、实例／模型／镜像／存储操作、配置变更和失败原因。
10. 审计字段包含 actor、时间、来源 IP 摘要、动作、对象、结果、request ID、task ID；不记密码、cookie、令牌和 NAS 密码。

### 4.3 UI 页面与布局

- 新增全屏初始化页：左侧产品与安全说明，右侧分步表单；完成后进入环境预检。
- 登录页仅保留必要字段、版本、管理网提示和 CLI 恢复入口说明。
- 顶栏增加管理员菜单：修改密码、会话管理、退出。
- 系统管理新增“安全与会话”“操作审计”两个子页。
- 审计页采用固定表头、条件筛选、详情抽屉；敏感参数显示“已脱敏”。
- 401 统一跳登录并保留安全的返回地址；403 显示无权限，不伪装为接口失败。

### 4.4 性能与安全测试

- 会话读取使用索引和过期清理，不在每个请求全表扫描。
- 审计批量写入但不牺牲危险操作记录；写入失败时危险操作默认失败关闭。
- 验证未认证 API、CSRF、会话固定、暴力登录、注销后复用、初始化重放、Host 欺骗。
- 验证 Docker Socket 风险文档、管理网绑定和 HTTPS 示例。

### 4.5 发布门槛

全部旧 API 都有认证测试；初始化和恢复演练通过；审计可追踪每一次危险操作；无敏感值泄漏。

## 五、`0.0.9.7`——实例数据隔离与历史迁移

### 5.1 模块目标

新建实例全面使用独立 workspace，旧共享数据通过备份后向导迁移；默认删除实例但保留数据。

### 5.2 数据结构调整

```text
shared/models/                  # 全局只读模型库
instance-links/<instance-id>/   # 每实例模型视图
instances/<instance-id>/
  outputs/
  workflows/
  user/
  config/
backups/
```

1. 实例创建由后端生成 UUID 和标准目录，不接受任意宿主机路径。
2. outputs、workflows、user、config 使用每实例独立挂载；共享模型继续只读。
3. 模型链接目录由名称迁移到稳定实例 ID，并提供名称变化兼容。
4. 重建沿用同一 workspace；镜像、GPU、端口变化不重新分配数据目录。
5. 删除分为“删除实例、保留数据”和“彻底删除实例及数据”；默认前者。
6. 彻底删除要求输入实例名，展示目录、大小、备份状态和运行队列影响。
7. 孤儿数据有独立记录，可用于恢复实例或经确认清理。

### 5.3 历史迁移向导

1. 扫描旧实例及共享 outputs／workflows，计算文件数、大小和可用空间。
2. 创建完整备份并验证备份可读，未成功不得进入下一步。
3. 管理员按实例确认归属；支持按既有目录规则建议，但不自动猜测敏感文件所有权。
4. 无明确归属的数据进入“待认领区”，默认不在新实例中自动挂载。
5. 选择复制或移动：空间充足优先复制＋校验；移动也需先备份。
6. 生成迁移预览：每个实例文件数、目标目录、空间、是否需重建和预计中断。
7. 停止受影响实例并迁移，验证数量、大小和必要的 checksum。
8. 更新挂载与数据库，启动实例并进行健康检查。
9. 旧共享目录只有全部确认后才可归档；不自动物理删除。

### 5.4 UI 布局

- 实例详情新增“数据”子页：四个目录的容量、最近修改、备份状态、文件清单入口。
- 新建实例第四步显示独立 workspace 摘要，不暴露可任意编辑的宿主机路径。
- 删除弹窗用两个清晰选项，不用单个“级联删除”复选框隐藏风险。
- 系统或存储页提供“历史数据迁移”入口，采用步骤条＋迁移预览表＋逐项结果。
- 待认领区支持按文件、大小、时间和目标实例筛选，操作全部审计。

### 5.5 性能与验收

- 大目录统计和复制流式、分批执行，显示真实进度；避免一次性遍历阻塞 API。
- 复制前后核对文件数和大小，抽样或全量 hash 由迁移策略明确选择。
- 磁盘不足在开始前阻断；中途失败可恢复，不产生半挂载实例。
- 双实例验证输出互不可见；旧数据迁移、重复迁移、回退、保留删除、彻底删除均实测。

## 六、`0.0.9.8`——应用健康与实例生命周期

### 6.1 模块目标

建立容器、应用、队列三层状态，使“启动成功”真正代表 ComfyUI 可用，并完善创建、重建、启停和异常诊断。

### 6.2 状态与后端改造

```text
容器：created / running / exited / dead / unknown
应用：provisioning / starting / ready / degraded / failed / not_running
队列：idle / running / pending
```

1. 健康检查器独立运行，不依赖用户打开页面。
2. 频繁检查使用轻量 `/system_stats`；`/object_info` 只在启动、版本变化或按需诊断时调用。
3. 记录启动开始、容器 running、API 首次可达、ready、degraded、failed 等事件。
4. 启动超时可配置；超时保留容器与日志，显示最后完成步骤，不循环删除重建。
5. 将 DNS、网络、pip、CUDA、端口、挂载、进程退出和 API 异常分类为错误码。
6. 创建实例返回关联任务；容器已创建但应用未就绪时状态明确。
7. 重建先生成计划：变更字段、是否中断、数据目录、镜像兼容、端口和 GPU 检查。
8. 停止／重启前读取队列；存在任务时明确提示，阶段 1 不承诺生成任务无损续跑。
9. 同一实例操作互斥；数据库期望状态与 Docker 实际状态定期核对。
10. 健康恢复也记录事件，避免只记录失败。

### 6.3 UI 页面布局优化

- 实例列表将“应用健康”和“容器状态”拆成两列；队列单独展示。
- 状态徽章统一：就绪、启动中、降级、失败、停止、未知；鼠标悬停显示最近检查时间。
- “打开 ComfyUI”仅 ready 时作为主按钮；其他状态提供日志或诊断。
- 实例概览首屏为健康条＋关键资源＋最近事件，配置细节下移。
- 新增“事件”子页，用时间线显示状态变化和关联任务。
- 重建弹窗改为差异预览，不再只显示“重建不丢数据”的笼统说明。

### 6.4 性能与验收

- 启动期短间隔、稳定期长间隔；失败指数退避；页面后台不增加额外轮询。
- 多实例检查有界并发，单实例检查 singleflight，避免首页和详情重复请求 ComfyUI。
- 验证启动成功、API 永不就绪、进程退出、CUDA 失败、弱网、超时、恢复、并发操作。
- 验证 20 个以上实例状态采集时不造成明显 CPU／网络峰值；具体阈值在目标机型基线测试中确定。

## 七、`0.0.9.9`——统一任务、步骤日志与错误码

### 7.1 模块目标

统一模型和镜像已有任务，并为后续备份、升级、诊断提供同一套任务协议；页面文案与真实能力一致。

### 7.2 后端详细修改

1. 建立 `tasks`、`task_steps`、`task_logs`、`task_events`；记录对象类型、对象 ID、操作者和幂等键。
2. 状态统一为 queued、running、paused、succeeded、failed、canceling、cancelled、partial_success。
3. 不支持暂停的任务不显示暂停；未知总量使用不确定进度，不能伪造百分比。
4. 将现有下载／导入和镜像拉取／构建适配到统一模型，保留旧任务历史导入或明确归档。
5. 任务 worker 有界并发，按类型设置队列；镜像构建、下载、备份互不争抢无限资源。
6. 取消通过 context 和底层操作协作完成；无法立即停止时显示 canceling。
7. 重试生成新 attempt；网络任务可断点，创建任务使用幂等键，恢复／升级需新计划。
8. 服务重启后恢复可续任务，其他任务明确标记“服务重启导致中断”。
9. 统一错误响应：code、message、action、requestId、taskId、retryable。
10. 日志有大小和保留上限，截断必须标注；敏感参数入库前脱敏。

### 7.3 任务中心 UI

- 列表字段：类型、对象、操作者、当前步骤、进度、开始时间、耗时、状态、错误码。
- 筛选：类型、状态、对象、时间；支持从我的失败任务和关联对象进入。
- 详情采用上方摘要、左侧步骤时间线、右侧日志的布局；窄屏改为上下结构。
- 日志支持级别、关键字、暂停跟随、回到底部、下载和复制支持摘要。
- 关联对象可跳转实例、镜像、模型；对象删除后仍保留只读历史。
- 批量清理历史仅清理过期记录，不取消运行任务；保留策略可配置。

### 7.4 性能与验收

- 高频进度按事件或合理间隔持久化，不每接收一个分片写一次数据库。
- 日志批量追加、前端虚拟化，长连接断线有退避重连。
- 列表分页，避免历史任务一次全部加载。
- 测试排队、并发上限、取消、暂停、失败重试、重复提交、服务重启、日志截断和保留清理。
- 页面宣称的任务类型必须全部能在列表中找到。

## 九、`0.0.9.11`——模型中心、安全与资产治理

### 9.1 模块目标

强化下载、导入、hash、来源许可和引用保护，使模型中心从“文件管理”升级为可交付的资产管理。

### 9.2 后端与安全步骤

1. 服务端删除前计算模型链接、实例状态和进行中任务；运行实例引用默认禁止删除。
2. 批量删除逐项校验，返回成功、跳过、失败和原因，不能只依赖前端禁用按钮。
3. URL 下载默认仅 https；逐跳检查重定向、DNS 和 IP，阻断 loopback、私网、链路本地等目标。
4. 合法内网模型源采用管理员显式白名单并审计，不用全局放开私网访问作为替代。
5. 下载与导入设置并发、速度、文件大小和磁盘预检；保留 Range 续传。
6. 下载完成后默认计算并保存 SHA256；校验失败文件进入隔离状态，不自动标记可用。
7. 本地导入只允许白名单目录，防路径穿越和符号链接逃逸。
8. 模型元数据记录来源、仓库、revision、原始文件、许可链接、审核状态、hash、下载时间和引用。
9. “可能闲置”和“名称疑似重复”保持启发式文案；内容重复必须基于完整 hash。
10. hash 扫描、NAS 本地化、空间清理全部进入统一任务。

### 9.3 UI 页面布局

- 本地仓库新增来源、hash、许可、关联实例筛选；大表格支持列配置和分页。
- 模型详情采用左侧基本信息、右侧操作，下方来源、许可、引用、完整性四个区块。
- 在线下载确认页显示仓库 revision、文件大小、目标类别、磁盘需求、许可链接和 hash 状态。
- 模型许可状态统一为已审核、需复核、禁止再分发、未知；未知不等于禁止在线下载，但禁止进入慧浪可再分发包。
- 空间治理分为大文件、可能闲置、名称疑似重复、内容重复、失效链接。
- 删除弹窗列出占用实例和运行状态；允许跳转到实例先解除关联。

### 9.4 性能与验收

- 下载、hash 和扫描均流式执行；大文件 hash 可取消、分批和限速。
- 扫描结果缓存按文件大小和修改时间失效，避免每次打开页面全量重读。
- 模型市场搜索超时、限流、空结果和离线状态分别处理。
- 测试 SSRF、重定向到私网、路径穿越、符号链接、磁盘不足、重复下载、hash 不匹配、运行引用删除。
- 验证模型元数据导出不含签名 URL、凭据等敏感信息。

## 十、`0.0.9.12`——存储、备份与恢复

### 10.1 模块目标

形成平台数据容量视图、NAS 影响管理和可实际恢复的备份体系，为升级回滚提供基础。

### 10.2 本地存储与 NAS

1. 统计系统盘、数据盘、模型、镜像、实例、备份、诊断的空间；采集结果带时间。
2. 清理缓存、孤儿数据和过期诊断先生成计划，展示可释放空间与影响对象。
3. NAS 配置凭据不回显、不进 URL／日志／审计／诊断。
4. NAS 状态区分未配置、未挂载、正常、降级、断开；断开时不把远程文件误判为已删除。
5. 新增或修改 NAS 前列出受影响实例；已有实例生成重建计划，不声称 Docker 挂载可热补。
6. NAS 本地化先计算空间、来源和冲突策略，恢复后重新扫描。

### 10.3 备份与恢复步骤

1. 备份范围包括平台配置、SQLite、实例配置、workflows、outputs、user；模型和镜像默认记录来源／digest，不重复打包大文件。
2. 新建备份显示对象、包含项、目标目录、预计空间和保留策略。
3. SQLite 使用一致性快照，不直接复制正在写入的数据库文件。
4. 备份采用临时目录＋完成后原子改名，生成 manifest、版本兼容信息和 checksum。
5. 备份任务可取消；失败文件不得显示为可恢复备份。
6. 恢复向导依次执行选择备份、版本兼容、空间、影响预览、当前状态安全备份、恢复、健康验证。
7. 恢复冲突时禁止直接覆盖正在运行实例；明确需要停止的实例和队列影响。
8. 恢复失败返回原状态或停在明确、可人工处理的安全点，并生成报告。
9. 本版支持本机／挂载目录；计划备份、异地和对象存储留阶段 2。

### 10.4 UI 与性能

- 一级导航新增“存储与数据”，包含本地存储、网络存储、备份与恢复。
- 容量条可下钻到分类和对象；清理不直接放在容量图旁形成误触。
- 备份列表显示状态、范围、大小、版本、校验、保留到期和最近恢复验证。
- 大目录打包和恢复流式处理；进度按文件数和字节双维度展示。
- 实测数据库备份、实例备份、部分恢复、版本不兼容、磁盘不足、中途取消、恢复失败回退。

## 十五、`0.1.0.0`——总体验收与正式启用

### 15.1 版本原则

- 只有 `0.0.9.5`～`0.0.9.16` 所有验收项关闭后才启用。
- 正式版不叠加规划外新功能；只修改版本、发布元数据和已确认的阻断修复。
- 若存在未关闭 P0，继续使用 RC，不为了日期强行发布。

### 15.2 最终验收矩阵

| 维度 | 必测内容 | 通过标准 |
| --- | --- | --- |
| OS／架构 | Ubuntu 22.04／24.04；amd64／arm64 | 认证矩阵全部有记录，失败项不进入支持承诺 |
| GPU | DGX Spark；x86 NVIDIA 双卡或多卡 | 逐卡识别、分配、真实生成、重启恢复通过 |
| 安装 | 在线、受限网络、完全离线 | 按文档独立安装成功，签名校验有效 |
| 数据 | 新装、`0.0.9.4` 历史迁移 | 备份、归属确认、隔离、回退无数据丢失 |
| 主链路 | 初始化→镜像→实例→模型→真实生成 | ComfyUI ready，输出有效，事件与任务完整 |
| 运维 | 启停、日志、诊断、备份、恢复 | 故障可定位，备份实际可恢复 |
| 升级 | 升级、失败注入、自动回滚 | 管理和数据恢复，实例映射正确 |
| 安全 | 认证、CSRF、SSRF、路径穿越、越权、暴力登录 | 高危问题清零，敏感信息不泄漏 |
| 性能 | 多实例、大模型、长日志、大任务列表 | 达到已记录基线，无无限并发和明显页面卡死 |
| 开源 | 许可、CI、Release、SBOM、文档 | 公开包与 commit 一致，第三方义务明确 |
| 出厂 | 预装、验收报告、清理测试资产 | 非研发可执行，客户可复核 |

### 15.3 正式发布动作

1. 冻结代码并完成最终安全、数据和许可审查。
2. 将全部验收报告关联到同一 commit 和候选包 checksum。
3. 启用 `0.1.0.0`，更新版本文件、CHANGELOG、详细变更记录。
4. 创建 Git tag 和 GitHub Release，公开 Apache-2.0 仓库。
5. 发布双架构管理包、签名、SBOM、文档和兼容矩阵。
6. 发布慧浪认证 ComfyUI 模板及独立出厂验收报告。
7. 模型包仅在逐资产许可通过后独立发布。
8. 发布社区支持边界、慧浪支持服务边界和安全响应渠道。
9. 保留上一稳定版安装包和回退说明，监控首批安装反馈。

### 15.4 Go／No-Go 清单

任何一项为“否”即 No-Go：

- 所有 P0 是否关闭并有证据？
- 历史数据是否完成真实迁移和回退演练？
- 是否完成两种架构真实生成？
- 是否完成升级失败自动回滚？
- 是否完成完全离线首次启动且不在线安装依赖？
- 是否完成备份恢复，而不仅是备份成功？
- 是否没有高危安全和许可阻断？
- 是否由非研发按公开文档独立安装成功？
- 销售材料是否只包含已验收能力？

## 十七、实施管理建议

- 主线按版本顺序合并，文档、测试和部分 UI 可并行，但不得绕开前置数据与安全设计。
- 每版都有“功能完成”和“商用验收完成”两个状态，只有后者才能关闭。
- 每版维护阻塞项、遗留项和下一阶段复验项，禁止把 P0 转为普通优化。
- RC 后只允许修复阻断缺陷；新需求进入阶段 2 路线图。
- 慧浪销售、交付和售后从 `0.0.9.13` 起参与实机验收，避免研发完成后才发现交付件不可用。
