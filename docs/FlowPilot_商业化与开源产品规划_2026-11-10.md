## 一、给管理层的结论

### 1.1 一句话定位

**FlowPilot 应定位为“慧浪智算 GPU 服务器上的 ComfyUI 交付与运维控制面”，而不是另一个 ComfyUI 工作流编辑器。**

慧浪智算销售的是一套可验收的整体结果：

> GPU 服务器＋预装 FlowPilot＋慧浪验证的 ComfyUI 镜像模板＋可选授权模型包＋出厂验收＋升级与运维服务。

ComfyUI 继续负责节点、工作流编辑和生成；FlowPilot 负责把“服务器到货后能安装、能启动、能恢复、能排障、能升级”做好。

### 1.2 当前能不能卖

| 使用方式 | 当前判断 | 前提 |
| --- | --- | --- |
| 慧浪工程师陪同的内网 POC | 可以有条件开展 | 受信管理网、单管理员、明确数据共享语义、人工备份与验收 |
| 随服务器交付的客户试用版 | 可以，但应标为交付预览版 | 提供书面安全边界、验收清单和人工支持，不承诺 GA |
| 公开下载并宣称商用 GA | 暂不建议 | 先清零本文 P0 项 |
| 公网直接开放管理台 | 不可以 | 当前所有管理 API 无认证，且管理容器具有 Docker Socket 权限 |

当前 README 已明确“仅限受信任本机或管理网络、当前没有认证、不应暴露公网”。这不是界面文案问题，而是发布阻断条件。[README](kimi-cite://md-line?path=%2FUsers%2Fzhouyazhou%2FDocuments%2Fkimi%2F%E6%85%A7%E6%B5%AA%E6%99%BA%E7%AE%97comfyui%E7%AE%A1%E7%90%86%E5%B9%B3%E5%8F%B0%2FREADME.md&line=36&text=%E5%90%AF%E5%8A%A8%E8%84%9A%E6%9C%AC%E4%BC%9A%E6%8C%82%E8%BD%BD%20%60%2Fvar%2Frun%2Fdocker.sock%60%EF%BC%8C%E4%BB%85%E9%99%90%E5%8F%97%E4%BF%A1%E4%BB%BB%E7%9A%84%E6%9C%AC%E6%9C%BA%E6%88%96%E7%AE%A1%E7%90%86%E7%BD%91%E7%BB%9C%E4%BD%BF%E7%94%A8%E3%80%82%E5%BD%93%E5%89%8D%E7%89%88%E6%9C%AC%E6%B2%A1%E6%9C%89%E8%AE%A4%E8%AF%81%EF%BC%8C%E4%B8%8D%E5%BA%94%E7%9B%B4%E6%8E%A5%E6%9A%B4%E9%9C%B2%E5%88%B0%E5%85%AC%E7%BD%91%E3%80%82 "citation")

### 1.3 建议的版本与商业分层

- 建议阶段 1 正式版本命名为 **`0.1.0.0 Community`**，名称待批准。
- 核心管理平台开源，建议采用 **Apache-2.0**；是否采用及未来是否保留闭源增值模块，需先确定版权与贡献协议。
- “开源版”“慧浪验证出厂版”尽量使用同一套核心代码，避免长期维护两个产品。
- 慧浪的商业价值不依赖把核心代码闭源，而来自：**硬件兼容验证、签名镜像模板、工厂预装、交付验收、支持 SLA、远程运维、企业控制和场景包**。
- 阶段 1 不同时上 K8s、多租户、计费、复杂 GPU 调度、自研工作流编辑器；这些会稀释“开箱即用与运维”的主线。

### 1.4 阶段 1 的六个发布硬门槛

1. 管理台具备初始化、认证、会话保护、操作审计，危险操作全部由服务端授权与校验。
2. 每个实例的输出、工作流、用户配置独立；共享模型只读；删除与迁移语义清晰。
3. “容器运行”和“ComfyUI 可用”分离，不再以 Docker `running` 代替应用就绪。
4. 镜像、模型、实例、备份、升级等进入统一任务与日志体系。
5. 提供 amd64＋arm64 离线包、校验和、签名／验签、SBOM、版本固定、备份升级回滚。
6. 在真实 NVIDIA 多卡 x86 服务器和 DGX Spark 上完成在线、离线、恢复、升级全链路验收，而不是仅凭单机功能演示发布。

### 2.4 文档与代码的偏差

早期 PRD 或局部 README 中仍有 Vue、SQLite、systemd、初始化登录、每实例独立数据等表述，但当前真实实现并不完全如此。阶段 1 开工前应建立一份“已实现／未实现／已变更设计”的现状基线，后续销售材料只能引用该基线和验收报告，不能照旧 PRD 宣传。

### 3.2 P1：商用体验必须补齐，但可在 P0 之后并行

- 服务端诊断包、错误码、日志检索、售后脱敏规则。

### 3.3 两个容易被误判为“已治理”的功能

- “疑似闲置”当前依据文件时间，不等于真实使用次数；界面必须写“可能闲置”，不能写“未使用”。
- “同名同大小”不是内容级重复。阶段 1 可提供按需 SHA256 扫描，并将“名称疑似重复”和“内容完全一致”分开；扫描大模型库必须是有进度、可取消的后台任务。

## 四、产品边界与总体架构

### 4.1 做什么、不做什么

| FlowPilot 负责 | ComfyUI／合作方负责 | 阶段 1 明确不做 |
| --- | --- | --- |
| 服务器兼容检查、GPU 可见性 | 节点与工作流编辑 | 自研节点画布、提示词编辑器 |
| ComfyUI 镜像模板构建、固化、导入 | 具体出图、视频生成效果 | 自研基础模型 |
| 实例生命周期、端口、GPU 分配 | 工作流内部参数调优 | 深度出图教学作为软件义务 |
| 模型入库、共享、hash、来源和许可元数据 | 模型本身的生成质量与授权 | 承诺所有市场模型可商用 |
| 每实例数据隔离、备份、恢复 | 业务素材版权 | 自动替换宿主机 GPU 驱动 |
| 任务、日志、诊断、升级、回滚 | 定制业务工作流开发 | K8s、多机联邦、多租户计费 |
| 出厂环境验收与售后支持 | 场景咨询服务（可另购） | 不受控地在线安装任意自定义节点 |

### 4.2 阶段 1 推荐技术架构

```text
浏览器（仅管理网／HTTPS）
        │
Caddy 或 Nginx（HTTPS、请求限制、安全头）
        │
FlowPilot Server（Go）
  ├─ 认证／会话／CSRF／审计
  ├─ 实例、镜像、模型、存储、硬件服务
  ├─ 统一任务调度与日志
  ├─ 健康检查、诊断、备份、升级
  └─ 嵌入式 SQLite（平台元数据、任务、审计、模板、模型元数据）
        │
受控 Docker Adapter ── Docker Socket
        │
ComfyUI 实例容器（仅批准镜像）
  ├─ 只读共享模型库
  ├─ 每实例模型链接视图
  └─ 每实例 outputs／workflows／user／config
```

**为什么建议引入 SQLite：** 当前 Docker 标签适合描述容器，但不适合承载用户、会话、审计、统一任务、模型许可、升级版本等事务数据。SQLite 与现有“单机、无外部数据库依赖”定位一致。Docker 标签可保留为容器识别与兼容信息，但不应继续作为所有平台状态的唯一事实源。迁移时采用一次性导入＋校验报告，避免双写长期不一致。

### 4.3 标准目录与删除语义

```text
<FlowPilot Home>/
  config/                 # 平台配置，0600/0640，密钥不明文导出
  flowpilot.db            # 元数据、任务、审计
  backups/                # 配置与实例数据备份
  diagnostics/            # 有保留期的诊断包
  shared/models/          # 全局只读模型库
  instance-links/<id>/    # 每实例模型视图
  instances/<id>/
    outputs/
    workflows/
    user/
    config/
  imports/                # 受控导入白名单
```

- **停止实例**：只停容器，不动数据。
- **删除实例（默认）**：删除容器和模型链接，保留 workspace，生成“可恢复 orphan 数据”记录。
- **彻底删除**：独立二次确认，输入实例名，列出将删除的目录和大小；默认先建议备份。
- **重建／升级实例**：沿用同一实例 ID 和 workspace；镜像、GPU、端口变化形成审计事件。
- **模型共享**：所有实例只读访问总库，但由链接视图决定各自能看到哪些模型。
- **阶段 2 的项目共享空间**另做显式授权，不恢复阶段 1 的全局混用。

## 五、慧浪智算服务器组合方案

### 5.1 出厂产品组成

| 交付层 | 内容 | 慧浪增值点 |
| --- | --- | --- |
| 硬件 | 慧浪 GPU 服务器、管理网口、系统盘与数据盘规划 | 整机质量、GPU／显存／存储规格、售后责任统一 |
| 基础环境 | 经验证的 Ubuntu、Docker、NVIDIA 驱动与 Container Toolkit | 客户不必自行拼驱动和容器运行时 |
| 开源平台 | FlowPilot Community | 透明、可审查、可自主部署 |
| 慧浪验证镜像 | 固定版本的 ComfyUI／Manager、依赖锁、镜像签名、SBOM | 避免首次启动在线装依赖，弱网／离线可重复交付 |
| 可选模型包 | 单独分发的模型、来源与许可清单、SHA256 | 减少下载时间；不将未授权模型混入开源仓库 |
| 场景包 | 镜像＋模型清单＋授权工作流＋依赖＋验收样例＋资源建议 | 把硬件参数转成客户能理解的业务结果 |
| 服务 | 出厂验收、部署培训、保修、SLA、远程诊断、升级 | 持续收入与降低客户运维成本 |

### 5.2 出厂镜像要求

每台机器生成一份可下载、可打印的《出厂验收报告》，至少包括：

- 服务器序列号、机型、CPU、内存、系统盘／数据盘、GPU 逐卡型号与 UUID。
- OS、内核、Docker、NVIDIA 驱动、CUDA 可见版本、Container Toolkit。
- FlowPilot 版本、安装包 SHA256、管理镜像 digest。
- ComfyUI commit、Manager commit、基础镜像 digest、Python 锁文件版本、镜像 digest、SBOM 编号。
- 模型包清单及许可状态；没有模型时明确写“未预置模型”。
- 测试实例、测试模型、真实工作流运行结果、输出文件存在性与基本属性。
- 重启后实例恢复、数据保留、管理台健康、诊断包可生成。
- 验收人、时间、失败项及客户确认。

### 5.3 支持矩阵应分级，不用“支持所有 GPU”宣传

| 等级 | 含义 | 首发建议 |
| --- | --- | --- |
| 慧浪认证 | 完整自动化＋真实生成＋升级回滚验收，纳入销售 SLA | 选定的慧浪 x86 NVIDIA 机型＋DGX Spark |
| 社区验证 | 有测试报告但不在标准 SLA | 其他相近驱动／CUDA 组合 |
| 实验性 | 可构建或能启动，未承诺完整兼容 | AMD ROCm、CPU、未测 GPU |
| 不支持 | 已知冲突或缺依赖 | 明确阻断和替代建议 |

首发应优先把少数 NVIDIA 配置做深；AMD／CPU 可保留社区构建能力，但不进入标准商用承诺。

### 5.4 商业 SKU 建议

| SKU | 软件与交付 | 收费逻辑，不含定价 |
| --- | --- | --- |

## 六、阶段 1：开源且可打包销售的版本

### 6.1 目标与范围

**目标：** 客户在受控管理网内，能够从离线包完成初始化，在 30 分钟左右创建第一个健康实例；已有镜像和模型时，可完成真实生成、重启恢复、诊断、升级和回滚。这里的 30 分钟是产品设计目标，不是当前实测 SLA；验收时应按镜像大小和机型记录实测值。

**阶段 1 包含：** 单机、单管理员、单 GPU／CPU 实例、NVIDIA 优先、amd64＋arm64、在线与完全离线、每实例独立数据、核心审计和备份。

**阶段 1 不包含：** 多用户复杂权限、多机集中控制、GPU 超分、多 GPU 单实例、按用户计费、场景工作流在线编辑。

### 6.2 目标信息架构

```text
初始化（仅首次）
登录
首页
ComfyUI 实例
  ├─ 实例列表
  ├─ 新建实例（四步向导）
  └─ 实例详情：概览／日志／模型／配置／数据／事件
镜像中心
  ├─ 本机镜像
  ├─ 镜像模板
  └─ 模板详情／构建／拉取／导入
模型中心
  ├─ 本地仓库
  ├─ 在线来源
  ├─ 模型详情
  └─ 空间治理
任务中心
  └─ 任务详情：步骤／日志／关联对象／重试
硬件管理
存储与数据
  ├─ 本地存储
  ├─ 网络存储
  └─ 备份与恢复
系统管理
  ├─ 环境与兼容性
  ├─ 通用设置
  ├─ 安全与会话
  ├─ 操作审计
  ├─ 诊断中心
  ├─ 版本与升级
  └─ 关于／开源许可
```

镜像、存储、安全、审计、升级从实例页和系统页中清晰拆出，是为了形成可销售的运维产品，而不是继续堆叠弹窗。

### 6.3 全局设计规范

每个页面统一处理以下状态，不能只设计成功态：

- **加载：** 表格骨架屏；已有数据刷新时保留内容并显示更新时间，不反复闪空。
- **空态：** 区分“从未配置”“筛选无结果”“无权限”“后端不可用”；给出唯一下一步。
- **失败：** 显示人话摘要、错误码、关联任务、复制详情、重试；不直接暴露堆栈和敏感路径。
- **超时：** 明确后台任务是否仍运行，避免用户重复点击创建多个任务。
- **部分成功：** 批量操作逐项列出成功／跳过／失败及原因，允许只重试失败项。
- **危险操作：** 停止、重启、删除、清缓存、恢复、升级说明影响范围；彻底删除要求输入名称。
- **重复提交：** 创建、升级、恢复采用幂等键或服务端操作锁；按钮 loading 不是唯一保护。
- **权限：** 前端隐藏不是安全边界，所有 API 在服务端重新认证、授权和参数校验。
- **可访问性：** 键盘焦点、弹窗焦点回收、状态不只依赖颜色、移动端 375px 无横向溢出。
- **时间／容量：** 统一时区、绝对时间＋相对时间、GiB／GB 单位；所有进度支持未知总量的不确定态。

## 七、阶段 1 页面、功能与子页面详规

### 7.1 初始化与登录

| 页面 | 字段与内容 | 操作 | 异常与优化 | 验收重点 |

| 首次初始化 | 管理员账号、密码、确认密码、服务器显示名、时区、管理地址；安全须知 | 创建管理员、生成恢复码、进入环境预检 | 一次性初始化令牌只从安装输出／0600 文件获得；完成后失效；弱密码拒绝 | 未初始化不能调用业务 API；刷新不能重复初始化；令牌不进入诊断和审计 |

### 7.2 首页

| 区块 | 展示字段 | 操作与跳转 | 设计与优化点 |
| --- | --- | --- | --- |

### 7.3 ComfyUI 实例——列表

**列字段：** 实例名、应用健康、容器状态、镜像及版本、GPU、端口、队列运行／等待、模型数、数据大小、自启动、创建时间、最近健康时间。

**操作：** 新建、打开 ComfyUI、启动、停止、重启、重建、备份、删除；按健康／GPU／镜像／自启动筛选；名称搜索；列显示配置。

**关键优化：**

- “打开 ComfyUI”仅在应用就绪时作为主按钮；启动中可查看日志，失败时显示诊断。
- 停止／重启若队列有任务，提示“运行 X、等待 Y”，要求确认；阶段 1 不承诺生成任务无损续跑。
- 操作锁防止同时重建和删除；状态变更后通过事件或短轮询刷新。
- 批量操作阶段 1 只做启动／停止，不做批量彻底删除。

### 7.4 新建实例——四步向导

| 步骤 | 字段 | 校验与默认值 | 完成后的反馈 |
| --- | --- | --- | --- |
| 1. 基本信息 | 名称、显示名、描述 | 名称唯一、DNS／容器安全字符、长度限制；自动生成可用名称 | 显示实例 ID 与数据目录，不让用户手填宿主机路径 |
| 2. 镜像模板 | 慧浪认证／社区模板、ComfyUI 版本、镜像 digest、架构、CUDA／ROCm、Manager 版本 | 只显示与当前架构兼容且经后端允许的镜像；缺镜像时跳转导入任务 | 明确“固定版本”或“未认证”，未认证模板给出风险 |
| 3. 资源与访问 | 单 GPU／CPU、GPU 型号与当前占用、宿主机端口、自启动 | 默认 GPU 独占；端口冲突在服务端复核；显示显存建议而非伪保证 | 选择 CPU 时提示性能不在标准 SLA |
| 4. 数据与确认 | 独立 workspace、共享模型链接、NAS 影响、初始容量、参数摘要 | 磁盘预检；数据目录自动创建；所有设置可返回修改 | 创建任务进入统一任务中心；步骤为建目录→创建容器→启动→等待应用就绪 |

**补充：** 创建成功不等于只返回容器 ID；最终状态必须区分“容器已建、应用未就绪”。超时可保留实例和日志，不自动反复删除重建。

### 7.5 实例详情——六个子页

| 子页 | 展示内容 | 操作 | 设计与验收重点 |
| --- | --- | --- | --- |
| 概览 | 容器状态、应用健康、就绪耗时、镜像 digest、GPU、端口、队列、版本、uptime、最近事件 | 打开、启停、重启、复制访问地址、运行健康检查 | `/system_stats` 用于频繁健康检查；`/object_info` 在启动或版本变化时检查，避免高频拉取大响应 |
| 日志 | stdout／stderr、时间、级别、关键字、来源、跟随状态 | 暂停跟随、回到底部、下载、按时间范围查询、创建诊断包 | SSE 断线重连且不漏提示；大日志虚拟化；下载走服务端文件；过滤不修改原日志 |
| 模型 | 已关联模型、类别、大小、来源、hash 状态、失效链接 | 搜索、批量关联／取消、定位模型详情 | 保存采用版本号／etag，冲突时提示他人已修改；不再静默后写覆盖 |
| 配置 | 镜像、GPU、端口、自启动、挂载目标、环境变量白名单 | 生成重建计划、比较变更、确认重建 | 不直接编辑任意容器 env／命令；变更前显示是否需重建、数据是否保留 |
| 数据 | outputs／workflows／user／config 大小、最近修改、备份状态 | 备份、导出、恢复、打开文件清单、保留数据删除 | 不默认暴露任意宿主机文件浏览；仅实例目录；大导出转后台任务 |
| 事件 | 状态迁移、操作者、操作、结果、错误码、关联任务 | 过滤、复制事件 ID、跳转审计 | 用时间线解释“何时为何失败”，不只给当前状态 |

### 7.6 镜像中心

#### A. 本机镜像

- 字段：名称、标签、digest、架构、大小、ComfyUI／Manager commit、CUDA／ROCm、认证状态、创建时间、引用实例数。
- 操作：导入、导出、打标签、拉取、构建、删除、清理悬空镜像和构建缓存。
- 保护：被实例引用的镜像默认禁止删除；提供查看引用；删除只删标签还是删镜像层必须说明。
- 优化：GB 级导入导出全部任务化；导出显示磁盘需求；导入先验 manifest、架构和 checksum。

#### B. 镜像模板目录

- 字段：模板名称、适用 GPU／架构、最低驱动、ComfyUI 版本、镜像大小、认证等级、发布日期、许可入口。
- 慧浪认证模板默认置顶；社区自定义模板与认证模板明显分区。
- “master／latest”只允许作为高级社区构建输入，不能作为慧浪出厂模板。
- 每个模板有依赖锁、SBOM、签名和已知问题；下载前检查磁盘、架构和驱动。

#### C. 模板详情／构建抽屉

- 概览：版本来源、依赖、预计磁盘、构建参数、变更记录。
- 兼容性：当前主机逐项通过／警告／阻断。
- 操作：拉取固定 digest、离线导入、从锁文件构建、复制可复现构建命令。
- 构建日志进入统一任务详情；失败可重试但不能悄悄改变 ref。

### 7.7 模型中心

#### A. 本地仓库

- 字段：名称、类别、来源、仓库／版本、大小、SHA256 状态、许可状态、关联实例、修改时间、存储来源。
- 操作：URL 下载、本地导入、NAS 本地化、关联实例、导出元数据、删除。
- 筛选：类别、来源、许可、hash 状态、是否关联、大小、可能闲置。
- 默认保护：运行实例引用、下载中、hash 计算中模型禁止删除；服务端返回具体占用对象。

#### B. 在线来源

- ModelScope／HF 镜像源状态、搜索、仓库文件列表、版本／revision、文件大小、预计磁盘。
- 下载确认页显示原始来源 URL、目标类别、目标路径、许可链接、已知大小和 hash。
- 搜索不可用与没有结果分开；限流给重试时间；离线环境提示使用离线模型包。
- 自定义 URL 是高级功能，默认只允许 https；私网、loopback、链路本地地址和重定向逐跳检查，例外策略仅管理员配置并审计。

#### C. 模型详情

- 基本信息：文件路径、格式、大小、SHA256、创建／修改时间。
- 来源：提供方、仓库、revision、原始文件、下载时间、完整来源 URL。
- 许可：许可证名称、模型卡链接、商用状态“已审核／需复核／禁止再分发／未知”、审核人及说明。
- 引用：实例关联、是否运行、NAS／本地来源。
- 完整性：开始 hash、重新校验、查看校验报告；大文件任务可取消。
- 操作：关联、下载元数据、删除。FlowPilot 不替模型作者作商业授权判断。

#### D. 空间治理

- 磁盘分布、按类别／来源排序、大文件、名称疑似重复、内容 hash 重复、可能闲置、失效链接。
- hash 扫描分批、限速、可暂停；显示对 IO 的影响。
- 清理先生成计划：文件数、可释放空间、受影响实例；执行后形成审计与任务报告。

### 7.8 统一任务中心

#### A. 任务列表

**覆盖类型：** 模型下载／导入／本地化／hash、镜像拉取／构建／导入／导出／清理、实例创建／重建／删除、备份／恢复、诊断、升级／回滚。

**统一状态：** 排队、运行、暂停（仅支持的任务）、成功、失败、取消中、已取消、部分成功；不允许用 `running` 同时表达“等待”和“执行”。

**字段：** 类型、关联对象、操作者、进度、当前步骤、开始时间、耗时、状态、错误码。支持类型／状态／对象／时间筛选和清理历史。

#### B. 任务详情

- 参数摘要：敏感字段脱敏；镜像 ref、模型来源、目标对象可复制。
- 步骤时间线：每步开始／结束、重试次数、当前错误、前后置条件。
- 日志：实时流、搜索、级别、下载；历史任务保留截断说明。
- 关联对象：实例、模型、镜像、备份、升级报告相互跳转。
- 操作：取消、暂停／恢复（底层支持才展示）、安全重试、复制支持摘要。
- 重试规则：网络下载可从断点；实例创建使用幂等键；恢复和升级不能简单重复执行，必须生成新计划。
- 服务重启：任务恢复或明确标记“因服务重启中断”，不能永久显示运行中。

### 7.9 硬件管理

| 子区域 | 字段与功能 | 优化点 |
| --- | --- | --- |
| 主机概览 | 机型、SN（有权限才显示）、OS、内核、CPU、内存、系统／数据盘 | 当前值与采集时间同时展示；采集失败不清空最后成功数据，标为过期 |
| GPU 逐卡 | index、UUID、型号、显存／统一内存、利用率、温度、功耗、驱动、CUDA、分配实例 | “空闲”只表示未分配，不代表生成队列为空；点击进入实例 |
| 兼容性 | Docker、NVIDIA runtime、驱动与模板要求、架构、磁盘、端口 | 每项提供通过／警告／阻断和修复文档；阶段 1 不自动改驱动 |
| 本地告警 | 高温、显存高、磁盘低、GPU 采集失败、实例异常 | 阶段 1 为页内事件和阈值；邮件／Webhook 集中告警放阶段 2 |
| 验收工具 | 创建测试实例、运行标准样例、查看结果、生成报告 | 测试资产独立命名，完成后可清理，绝不影响客户实例 |

### 7.10 存储与数据

#### A. 本地存储

- 系统盘、数据盘、模型、镜像、实例、备份、诊断占用；阈值和剩余可工作时间只作趋势提示。
- 目录只展示平台管理的白名单路径，不提供任意宿主机路径写入。
- 清理缓存、孤儿实例数据、过期诊断均先预检，再形成任务。

#### B. 网络存储

- NFS／SMB 类型、服务器、共享名、挂载状态、容量、只读状态、最近检测；凭据不回显。
- 提供挂载脚本和验证结果；密码不写入 URL、日志、审计或诊断。
- 启用／修改 NAS 前列出受影响实例。由于 Docker 挂载不可变，已有实例需要“重建计划”，不能假称热补挂载。
- NAS 断开时状态降级，不将远程文件误判为已删除；恢复后重新扫描。
- 本地化任务计算剩余空间并保留来源信息。

#### C. 备份与恢复

- 备份对象：平台配置／SQLite、实例配置、workflows、outputs、user；模型和镜像默认不重复备份，可记录 digest 和来源。
- 新建备份：名称、范围、目标目录、包含项、预计大小、保留策略。
- 备份列表：状态、大小、版本兼容、创建人、校验结果、保留到期。
- 恢复向导：选择备份→兼容性检查→空间检查→影响预览→停止相关操作→恢复→健康验证。
- 恢复默认先生成当前状态的安全备份；失败自动回到恢复前状态或明确停在可人工处理的安全点。
- 阶段 1 支持本机／挂载目录备份；异地副本、对象存储和计划策略放阶段 2。

### 7.12 错误码与支持体验

```json
{
```

## 八、阶段 1 后端与工程改造清单

### 8.1 安全

- 认证中间件覆盖除健康探针和初始化状态外的所有 API；静态资源不泄露配置。
- 密码使用 Argon2id 或经验证的 bcrypt 方案；随机会话 ID，服务端可撤销，cookie 安全属性完整。
- 对 Cookie 认证使用 CSRF token＋Origin／Host 校验；限制 CORS，不默认允许任意来源。
- 登录、下载、导入、构建、恢复、升级分别限流和限制并发；大请求使用流式与配额，不读入无限内存。
- URL 下载逐跳解析 DNS 与目标 IP，阻断私网／loopback／链路本地等；重定向后重新校验。合法内网镜像源采用管理员显式白名单，而非完全放开。
- 所有危险操作校验对象归属、状态、引用和版本；防路径穿越、符号链接逃逸、命令注入。
- Docker Socket 风险写入安全模型；管理面不绑定公网；提供防火墙与反向代理示例。
- 安全测试包含未认证 API、CSRF、SSRF、路径穿越、暴力登录、会话固定、越权、恶意镜像名／模型路径。

### 8.2 数据与状态

- SQLite 事务与迁移版本化；升级前备份；禁止不可回退迁移静默执行。
- 实例以稳定 UUID 为主键，容器名可变；Docker 标签仅做映射和恢复。
- 模型、实例、任务采用乐观锁或操作锁，避免两人／多标签页覆盖。
- 所有删除优先“保留数据／软删除记录＋可恢复”；物理清理由明确任务完成。
- 任务和审计采用不同保留策略；审计删除本身也记录。

### 8.3 健康模型

```text
容器：created / running / exited / dead / unknown
应用：provisioning / starting / ready / degraded / failed / not_running
队列：idle / running / pending（单独展示，不参与容器健康）
```

- 启动早期较短间隔，稳定后降低频率；页面不可见时进一步降频。
- Manager 首次在线安装不再作为出厂镜像的正常路径；依赖在构建期固化。
- 启动超时时间可配置，并显示最后正常步骤；弱网、DNS、pip、CUDA、端口、挂载、进程退出采用不同错误分类。
- 记录最近状态变化和失败原因，健康恢复也形成事件。

### 8.4 交付与升级

**管理包：** FlowPilot 前后端镜像、安装／升级／卸载、manifest、LICENSE、NOTICE、SBOM、checksum、签名、文档。  
**ComfyUI 模板包：** 固定 digest 镜像、版本元数据、依赖锁、上游许可证、SBOM、验收样例。  
**模型包：** 可选、独立、逐文件 SHA256、来源和许可，不进入 FlowPilot 源码 Release。

安装流程：

```text
检查架构／OS／Docker／GPU runtime／端口／磁盘
→ 验证包签名与 SHA256
→ 加载管理镜像和选定模板
→ 初始化数据目录与管理员
→ 启动 HTTPS 入口和管理服务
→ 环境预检
→ 创建验收实例（可选）
→ 输出访问方式、恢复方法与验收报告
```

升级流程：

```text
检查目标版本兼容与磁盘
→ 阻止冲突任务并备份平台数据
→ 保存旧镜像与数据库快照
→ 执行迁移
→ 启动新版本并通过健康门
→ 验证实例与数据映射
→ 失败则恢复旧镜像和快照
→ 生成升级／回滚报告
```

原则上不为了升级管理面而停止正在生成的 ComfyUI 实例；若必须影响，升级预览中明确列出并取得确认。

## 九、开源发布与许可合规

### 9.1 推荐策略

**FlowPilot 核心建议 Apache-2.0。** 原因是宽松许可更适合服务器 OEM、企业内网部署和社区二次集成，也符合“核心开源，慧浪以验证、硬件与服务增值”的策略。

开源不等于放弃品牌：

- “FlowPilot”代码许可与“慧浪智算认证／HuiLang Verified”标识分开管理。
- 只有满足兼容矩阵、签名模板和验收流程的交付物才能使用慧浪认证标识。
- 企业增值模块若未来闭源，优先通过独立仓库、独立进程或清晰插件边界提供；不要在社区贡献后再模糊核心版权。
- 若计划未来重新许可核心，需在上开源前确定版权归属及 CLA；只采用 DCO 并不自动赋予任意重新许可权。此项应由法务确认。

### 9.2 上游许可边界

本次直接核查的上游许可证显示，ComfyUI 和 ComfyUI-Manager 均为 GPL-3.0。[ComfyUI LICENSE](kimi-cite://web?url=https%3A%2F%2Fraw.githubusercontent.com%2FComfy-Org%2FComfyUI%2Fmaster%2FLICENSE "citation"), [ComfyUI-Manager LICENSE](kimi-cite://web?url=https%3A%2F%2Fraw.githubusercontent.com%2FComfy-Org%2FComfyUI-Manager%2Fmain%2FLICENSE.txt "citation")

GPL 不禁止收费分发或付费支持，但分发对应软件时需要履行许可声明、对应源码等义务。实际交付应让法务按镜像构建与分发方式审查：

1. **FlowPilot 管理平台：** Apache-2.0（建议），保留版权与 NOTICE。
2. **独立 ComfyUI／Manager 镜像：** 保留 GPL-3.0 文本和来源，提供对应 commit、完整构建配方及获取对应源码的方式。
3. **自定义节点／Python 依赖／基础镜像：** 逐项记录，不因外层镜像或许可证而消失。
4. **模型、LoRA、工作流、客户素材：** 每个资产单独审查，不使用“平台 Apache-2.0，所以包内模型都可商用”的错误推论。
5. **在线市场：** 提供下载便利不等于取得再分发权；出厂内置模型比提供链接需要更严格的再分发审核。

本文是产品合规规划，不替代正式法律意见。

### 9.3 开源仓库发布清单

- `LICENSE`、`NOTICE`、`THIRD_PARTY_NOTICES.md`。
- `CONTRIBUTING.md`、`CODE_OF_CONDUCT.md`、`SECURITY.md`。

## 十、阶段 1 实施顺序与发布节奏

以下为在 1–2 名后端、1 名前端、1 名测试，产品／交付／DevOps 部分投入的假设下的工作量级估算，不是已批准工期。

| 里程碑 | 建议量级 | 主要交付 | 退出条件 |
| --- | --- | --- | --- |
| M0 基线冻结 | 1 周 | 现状基线、范围、许可决策、支持矩阵、数据迁移设计 | 决策项签字；不再按旧 PRD 理解现状 |

| M2 交付闭环 | 3–4 周 | 双架构包、签名／SBOM、备份恢复、升级回滚、诊断、出厂验收 | 在线／离线安装与回滚全链路通过 |
| M3 产品化 | 2–3 周 | 全部页面状态、错误码、文档、UI 优化、兼容测试 | 真实 x86 多卡和 Spark 验收；文档可交给非研发执行 |
| M4 开源 GA | 1–2 周 | 仓库治理、CI、安全审查、许可清单、Release、销售验收件 | P0 清零，公开包与出厂包一致可追溯 |

**合计约 10–15 周量级。** 若只做当前界面换皮并立即公开，不能达到本文定义的商用 GA；若团队缩减或首发支持矩阵扩大，应重新估算。

建议发布节奏：`0.1.0.0-alpha`（内部迁移）→`beta`（慧浪 POC）→`RC`（2 台以上客户样机／试点）→`0.1.0.0 Community GA`。在 RC 前冻结非必要新功能。

### 10.1 阶段 1 发布验收矩阵

至少覆盖：

- Ubuntu 22.04／24.04。
- linux/amd64 与 linux/arm64。
- 一台真实 x86 NVIDIA 双卡或多卡服务器；一台 DGX Spark。
- 在线、受限网络、完全离线三种安装。
- 有模型包与无模型包两种出厂。
- 新安装与从 `0.0.9.4` 数据迁移。

端到端用例：

```text
安装 → 初始化 → HTTPS 登录 → 导入／选择认证镜像
→ 创建实例 → 关联模型 → 真实 ComfyUI 生成
→ 停止／启动／重启恢复 → 数据与配置检查
→ 备份 → 升级 → 回滚 → 恢复演练 → 卸载（保留数据）
```

同时必须通过：未认证访问、CSRF、SSRF、路径穿越、端口冲突、磁盘不足、镜像损坏、模型删除占用、NAS 断开、服务重启中任务、升级失败回滚等负向测试。

## 十一、阶段 2：产品力与增值服务规划

### 11.1 企业运维增强

| 模块 | 功能 | 增值点 |
| --- | --- | --- |
| 组织与权限 | 组织／项目、管理员、运维、操作员、只读；按实例／模型库授权 | 从单管理员扩展到企业协作，减少越权 |
| SSO | OIDC、企业 AD／LDAP（按实际需求）、SCIM 可作为后续 | 融入现有账号体系，支持离职回收 |
| 审计合规 | 审计保留策略、不可抵赖导出、合规报表、外部日志服务 | 满足企业检查与责任追踪 |
| 告警 | 邮件、Webhook、企业微信／钉钉等适配；告警分组、静默、恢复通知 | 从“人看页面”变为主动运维 |
| 巡检 | 定期健康、磁盘、GPU、证书、备份和版本检查 | 形成可按机器销售的巡检服务 |
| 远程支持 | 客户授权的一次性诊断上传、限时支持会话、操作审批 | 慧浪售后降本，客户保留控制权 |

### 11.2 多机集中管理

**建议采用轻量 agent，不为多机强行引入 K8s。**

- 每台服务器运行 FlowPilot Agent，出站 mTLS 连接控制中心，适应客户内网与 NAT。
- 节点分组、标签、机型、GPU、版本、健康和容量统一视图。
- 认证镜像模板分发：签名校验、断点续传、按组灰度。
- 实例跨机部署时做架构、驱动、显存、存储预检；阶段 2 初期不承诺运行中热迁移。
- 平台滚动升级、失败暂停、单机回滚、版本偏差报告。
- 节点失联时保留本地管理能力，中心显示最后同步时间，不伪造实时状态。
- 批量任务限速、维护窗口、并发和失败阈值。

### 11.3 GPU 资源运营

- 单机先实现 GPU 分配日历、占用视图、实例排队和资源申请审批。
- 再多机实现按 GPU 型号／显存／驱动／标签选择节点。
- 项目配额：实例数、GPU 数、并发任务、磁盘、模型库；配额与真实 Linux／Docker 限制对齐。
- 共享 GPU／超分只作为显式策略，显示风险，不承诺显存隔离；支持 MIG 的机型可单独认证。
- 用量报表：GPU 分配时长、实际利用采样、实例运行时长、存储、任务成功率；不将采样值伪装成精确计费计量。
- 回收建议：长期停止实例、低利用 GPU、孤儿数据、可能闲置模型；由管理员审批执行。

### 11.4 数据保障

- 计划备份、保留策略、异地副本、S3 兼容对象存储。
- 实例快照与项目级恢复，恢复前兼容检查和权限检查。
- 模型库多机同步、hash 去重、按需缓存、源站不可用降级。
- 备份可恢复性定期演练，报告“最近成功恢复时间”，而不是只看备份成功。
- 可选不可变备份和勒索防护策略，是否支持取决于底层存储。

### 11.5 模型供应链增值

- 私有模型仓库、内网镜像站、代理缓存和离线导入审批。
- 模型版本、来源、hash、许可、依赖、适用镜像、验收结果形成 Model Manifest。
- 模型升级差异、回滚、受影响实例和场景包分析。
- 标准样例评测：能否加载、显存峰值、耗时、输出基本有效性；生成质量由业务人员复核。
- 恶意文件／异常格式／依赖漏洞扫描，结合格式白名单与供应商信誉，不宣称扫描可证明模型绝对安全。
- 许可到期或限制变化时通知，不自动删除客户资产。

### 11.6 受控自定义节点管理

这是有价值的后续能力，但不能在阶段 1 无边界开放：

- 白名单源、固定 commit、依赖锁、隔离构建、漏洞与许可证扫描。
- 节点包与 ComfyUI／Python／CUDA 的兼容矩阵。
- 先在测试实例验收，再发布到实例组；可回滚。
- 禁止在运行实例上无审计执行任意安装命令。
- 慧浪可提供“节点适配与认证服务”，这是明确的专业服务增值点。

### 11.7 开放集成

- 稳定版本化只读 API：节点、实例、健康、任务、用量。
- 写操作 API token 单独授权、过期、轮换和审计，不复用管理员 cookie。
- 事件 Webhook：实例异常、任务完成、备份失败、版本偏差；签名、重试、重放保护。
- Prometheus 指标和外部日志输出。
- 与慧浪 CRM／售后系统关联机器 SN、验收报告、支持工单；只有客户授权才上传诊断。

## 十二、阶段 2 场景包设计

### 12.1 场景包标准，不是“多装几个模型”

```text
Scene Package
  ├─ 认证镜像及 digest
  ├─ 模型清单、hash、来源、许可
  ├─ 官方或客户授权的工作流模板
  ├─ 固定版本的自定义节点与依赖
  ├─ 最低／推荐 GPU、显存、内存、磁盘
  ├─ 安装前置条件与冲突检查
  ├─ 验收工作流、测试素材和成功标准
  ├─ 初始化与恢复步骤
  └─ 支持边界、版本记录和升级回滚方案
```

FlowPilot 负责安装、依赖、资源和验收；用户仍在 ComfyUI 中编辑工作流。若客户需要提示词界面、批量商品业务系统或审片流程，应由独立业务应用／合作伙伴提供，通过 API 集成，不把 FlowPilot 核心变成垂直业务软件。

### 12.2 五类优先场景

| 场景包 | 环境内容 | FlowPilot 增值功能 | 验收标准示例 | 服务机会 |
| --- | --- | --- | --- | --- |
| 电商视觉 | 授权商品图工作流、背景／风格相关模型、固定节点、批量输出目录 | 按店铺／项目隔离实例、模型包离线导入、素材与输出备份、资源推荐 | 样例商品完成指定工作流，输出数量／分辨率／格式符合要求 | 模板部署、模型许可审核、店铺环境交付、扩容 |
| 短视频／广告 | 图生视频、放大、帧处理等经验证环境；大容量输出规划 | 大任务磁盘预检、长时间健康、输出保留策略、GPU 排队、NAS | 标准短片跑通且无依赖下载，输出可恢复，失败能定位 | 大显存机型、存储扩展、性能调优、模板适配 |
| 设计工作室 | 多项目工作流、共享模型、独立输出、风格模板 | 项目权限、NAS、模板分发、实例快照、低利用回收 | 多项目数据互不可见，模板升级可回滚 | 多机管理、备份、SSO、运维订阅 |
| 教育实训 | 教师认证模板、学生实例、标准模型、重置样例 | 批量开班、配额、课后重置、统一镜像、课堂巡检 | N 个学生实例并行启动，资源不超额，课后可还原 | 教室整体交付、课程环境服务、巡检 |
| 企业私有创作 | 私有模型库、批准工作流、内网源、审计 | SSO／RBAC、审批、审计、私有仓库、异地备份 | 完全离线安装、权限隔离、审计完整、恢复演练通过 | 私有化、合规、SLA、多机中心 |

**场景包不能承诺：** 任意素材都达到固定艺术效果、所有模型均可商业使用、所有自定义节点永远兼容、生成结果拥有无争议版权。

### 12.3 阶段 2 推荐顺序

1. **先做企业可运维性：** RBAC／SSO、告警、巡检、备份策略，直接服务已购服务器客户。
2. **再做多机集中管理：** 当客户节点数和售后成本出现时形成明确付费理由。
3. **同步沉淀 1–2 个场景包：** 优先选择慧浪已有客户和可合法分发资产的场景，不追求场景数量。
4. **最后做市场与生态：** 认证模板、受控节点、合作方发布、API 集成；以安全和验收为前提。

## 十四、需要周董拍板的决策

| 决策 | 推荐方案 | 不决策的影响 |
| --- | --- | --- |
| 1. 核心开源许可 | Apache-2.0；商标与认证体系独立；法务审核 CLA／DCO 与上游 GPL 交付义务 | 无法正式公开仓库和建立增值边界 |
| 2. 首发支持矩阵 | 少量慧浪 NVIDIA 机型；Ubuntu 22.04／24.04；amd64＋arm64；Spark＋至少一种 x86 多卡机型 | 测试范围无法收敛，销售承诺不清 |
| 3. 阶段 1 GPU 策略 | 每实例默认单卡独占，CPU 为高级／测试选项；多卡和超分后置 | 调度与验收复杂度会显著上升 |
| 4. 数据迁移 | 每实例独立 workspace；旧共享 outputs／workflows 先备份，按实例归属映射，无归属则进入待认领区 | 升级可能混用或丢失客户数据 |
| 5. 出厂模型策略 | 默认不内置未知许可模型；模型包独立交付，逐模型许可与 hash 审核 | 无法合法稳定地做场景包和宣传 |
| 6. 开源与慧浪版边界 | 核心同码；慧浪版增值为认证模板、预装、验收、SLA；企业多机等后续独立授权 | 容易形成双分支和长期维护成本 |
| 7. 支持服务 | 明确标准保修、远程诊断、升级服务和响应等级的区分 | 开源用户与付费客户的服务预期混乱 |
| 8. 首发场景 | 先选电商视觉或企业私有创作之一做真实标杆，再复制 | 阶段 2 容易变成泛场景清单而无可售样板 |

## 十五、最终建议

1. **保留现有技术底座。** Go＋React＋Docker、真实实例／模型／日志／硬件能力已具备良好起点，不需要重做平台。
2. **不要直接把 `0.0.9.4` 改名为开源正式版。** 先做 P0 安全、数据隔离和交付链，再发布 `0.1.0.0 Community`。
3. **把首发的商业完成度放在“可信交付”而非功能数量。** 认证镜像、出厂验收、备份恢复、升级回滚、诊断和文档，比继续增加市场条目更重要。
4. **核心开源、认证与服务收费。** 慧浪的优势是知道哪些 GPU／驱动／镜像／模型组合真正可用，并对结果负责。
5. **阶段 2 围绕运维和场景验收增值。** 多机、权限、巡检、私有模型供应链、场景包和受控节点认证都能增强产品，而不必深入重做 ComfyUI 应用本身。

**建议批准的第一步：先冻结阶段 1 范围与首发兼容矩阵，按 M0 形成数据迁移和开源许可两份专项决策，再进入开发。**
