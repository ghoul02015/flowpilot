# FlowPilot 阶段 2 路线图

> 文档性质：阶段 2 产品、技术与商业增值路线  
> 前置条件：`0.1.0.0 Community` 全部验收通过并正式发布  
> 路线原则：核心继续聚焦部署与运维；场景包独立交付；不重做 ComfyUI 工作流编辑器  
> 文中版本号为规划建议，后续根据客户价值和前一版本验收结果启停，不代表已承诺发布时间。

---

## 一、阶段 2 目标

阶段 1 解决“一台慧浪 GPU 服务器可安装、可使用、可恢复、可交付”；阶段 2 解决：

1. **多人可管：** 从单管理员扩展到企业账号、项目权限和审计协作。
2. **多机可管：** 从单机管理扩展到多服务器模板、健康、升级和容量集中管理。
3. **资源可运营：** GPU、存储、实例和任务可配额、可排队、可统计、可优化。
4. **数据可保障：** 从手工备份扩展到计划、异地、恢复演练和模型库同步。
5. **场景可复制：** 将一次性项目沉淀为认证场景包，而不是每次人工装模型和节点。
6. **服务可增值：** 形成远程运维、企业控制、场景交付、模型与节点认证等持续服务。

## 二、路线总览

### 2.1 平台主线

## 三、`0.1.1.0`——主动运维与开放告警

### 3.1 目标

把“管理员打开页面才发现问题”升级为“平台主动发现、通知并形成处理闭环”，优先服务已交付服务器客户。

### 3.2 功能模块

| 模块 | 功能 | 设计要求 |
| --- | --- | --- |
| 告警规则 | GPU 高温、采集失败、磁盘低、实例异常、任务失败、备份失败、证书临近过期 | 阈值、持续时间、恢复条件、严重级别可配置；避免瞬时抖动反复告警 |
| 告警生命周期 | 触发、确认、处理中、恢复、关闭、静默 | 记录操作者、时间和备注；静默不能永久隐藏高危项 |
| 通知渠道 | 邮件、通用 Webhook；企业微信／钉钉按客户需求适配 | 密钥加密保存、不回显；通知失败有重试和降级 |
| 定期巡检 | Docker、GPU、磁盘、实例、备份、证书、版本偏差 | 生成周期报告和待办；巡检任务不干扰生成负载 |
| 指标输出 | 节点、GPU、实例、任务、备份等 Prometheus 指标 | 指标命名稳定、基数受控，不把实例标签无限扩张 |
| 远程支持 | 客户授权的一次性诊断上传、限时支持令牌、支持会话记录 | 默认关闭；客户可撤销；不开放永久隐蔽通道 |

### 3.3 页面规划

- 首页新增“告警与待办”，与现有健康状态分开。
- 硬件和系统页增加告警中心：当前告警、历史告警、通知渠道、静默计划。
- 巡检报告详情：检查项、趋势、失败原因、建议、处理记录。
- 远程支持页展示授权范围、到期时间、上传内容和撤销按钮。

### 3.4 性能与验收

- 告警基于采样去抖和去重，不每次轮询发送通知。
- 通知异步、有界重试，不阻塞实例和硬件 API。
- 验证告警触发、恢复、静默、通知失败、令牌过期、客户撤销和敏感信息脱敏。

### 3.5 商业交付

形成“慧浪巡检与远程支持服务包”：软件提供工具，服务方承诺响应流程和报告，不将通知数量作为服务价值。

## 四、`0.1.2.0`——数据保障增强

### 4.1 目标

将阶段 1 的手工备份扩展为计划、异地和定期恢复验证，销售重点是“可恢复”，不是备份文件数量。

### 4.2 功能模块

1. 备份策略：按平台、实例、项目设置周期、保留份数、保留天数和维护窗口。
2. 存储目标：本机／挂载目录、S3 兼容对象存储；凭据加密与最小权限。
3. 异地副本：本地备份完成后再复制，远端失败不伪造本地备份失败。
4. 增量与去重：先针对元数据、工作流和配置；大输出文件按实际收益评估，不承诺所有存储后端均支持。
5. 恢复演练：在隔离目录或验收实例中恢复，验证数据库、配置、文件和应用健康。
6. 模型库同步：按 manifest 和 hash 同步，不在多机间盲目整目录覆盖。
7. 不可变备份：底层存储支持时提供对象锁／保留策略，不支持时明确降级。
8. 数据报表：最近成功备份、最近成功恢复、失败对象、容量和保留到期。

### 4.3 页面规划

- 存储与数据新增“备份策略”“存储目标”“恢复演练”。
- 实例数据页显示适用策略和最近恢复验证，而非只有最近备份。
- 恢复报告展示恢复点、耗时、校验、应用健康和失败项。

### 4.4 验收门槛

- 验证断网、对象存储凭据失效、远端空间不足、重复任务、保留清理和恢复冲突。
- 至少完成一次从异地副本恢复到干净服务器的演练。
- 大文件传输流式、可取消、有 checksum；不得因备份占满数据盘。

### 4.5 商业交付

可形成数据保障服务等级：基础本地备份、异地副本、定期恢复演练；等级按实际技术能力和客户存储条件定义。

## 五、`0.2.0.0`——企业协作、项目与权限

### 5.1 目标

在保留单机简单部署的基础上支持多人协作，权限围绕项目和资源对象，不做复杂而难验证的泛化多租户。

### 5.2 角色与资源模型

| 角色 | 典型权限 |
| --- | --- |
| 平台管理员 | 主机、安全、节点、模板、全部项目和系统设置 |
| 项目管理员 | 项目成员、实例、模型视图、备份和配额内操作 |
| 运维操作员 | 实例启停、任务、日志、诊断，不可管理安全策略 |
| 项目成员 | 使用被授权实例、打开 ComfyUI、查看项目资源 |
| 只读审计员 | 查看健康、任务、审计和报表，不执行变更 |

1. 建立组织、项目、用户、组、角色和资源授权。
2. 实例、模型库视图、备份和场景包归属项目；全局共享模型由平台管理员管理。
3. 项目输出和工作流仍按实例隔离；项目共享空间必须显式授权。
4. SSO 优先 OIDC；AD／LDAP 根据真实企业需求增加。
5. 支持用户禁用、离职回收、会话撤销和权限变更审计。
6. 配额先支持项目实例数、GPU 数、磁盘和并发任务；复杂调度在 `0.4.0.0` 完成。
7. 审计报表支持按项目、用户、对象和时间导出。

### 5.3 页面规划

- 顶栏增加项目切换器，页面明确当前项目上下文。
- 系统管理新增组织、用户／组、角色、SSO。
- 项目详情包含概览、成员、实例、模型视图、配额、备份、审计。
- 所有列表遵循服务端权限过滤，不能先返回全量再由前端隐藏。

### 5.4 验收与商业边界

- 重点测试水平越权、项目切换、禁用用户、SSO 登出、共享模型与共享输出边界。
- 单管理员开源版继续可用；企业协作是否作为独立授权模块，在开发前根据已确定的版权策略决定。
- 商业价值为多人企业管理、审计和支持服务，不以牺牲社区单机体验为代价。

## 六、`0.3.0.0`——多机集中管理

### 6.1 目标

用轻量 Agent 管理多台慧浪服务器，优先解决模板分发、健康、升级和售后，不为架构统一强行引入 K8s。

### 6.2 架构

```text
企业控制中心
  ├─ 节点／项目／模板／策略／告警／升级
  └─ API 与审计
          ▲
          │ 出站 mTLS、心跳、事件、任务结果
          │
FlowPilot Agent（每台服务器）
  ├─ 本地 Docker 与实例管理
  ├─ 模板缓存和校验
  ├─ 健康、指标和任务执行
  └─ 中心失联时保留本地管理
```

### 6.3 功能步骤

1. 节点注册使用一次性 enrollment token，证书可轮换和撤销。
2. 节点记录机型、GPU、架构、驱动、容量、版本、标签和分组。
3. 中心只保存必要元数据，客户素材和输出默认不上传。
4. 模板按 digest 分发，支持断点、校验、并发限制和节点缓存。
5. 创建实例时按架构、驱动、GPU、磁盘和项目策略预检节点。
6. 初期不做运行中实例热迁移；迁移采用备份＋目标恢复＋验证。
7. 滚动升级按节点组、并发、维护窗口和失败阈值执行，失败自动暂停。
8. 节点失联显示最后同步时间，不把缓存状态标为实时。
9. 批量操作可预览节点和失败影响，支持只重试失败节点。
10. 中心高可用在客户规模需要时单独设计，首版不把简单交付变成复杂集群工程。

### 6.4 页面规划

- 新增“节点中心”：地图／分组不是必需，优先表格和状态层级。
- 节点详情：概览、GPU、实例、模板、任务、告警、升级、事件。
- 模板分发页：目标组、版本、进度、失败节点和回滚。
- 升级页：批次、维护窗口、健康门和失败暂停。
- 全局首页展示多节点健康和容量聚合，可下钻单机。

### 6.5 验收与商业价值

- 测试节点失联、证书过期、中心重启、模板断点、部分节点升级失败和本地接管。
- 至少覆盖两种认证机型和混合架构模板分发。
- 商业交付为慧浪多机运维版、集中售后和批量场景部署服务。

## 七、`0.4.0.0`——GPU 资源运营

### 7.1 目标

提高资源透明度和使用效率，先提供可信的分配、排队和报表，再逐步增加共享策略。

### 7.2 功能模块

| 模块 | 功能 | 边界 |
| --- | --- | --- |
| 资源申请 | 按项目申请 GPU 型号、显存建议、数量、时长和场景 | 申请不等于硬性资源保证，需节点预检 |
| 实例排队 | 资源不足时排队，资源释放后按策略启动 | 支持优先级、公平和人工调整；防止饥饿 |
| 项目配额 | GPU 数、实例数、并发、磁盘、模型缓存 | 与底层实际限制对齐，不能只记数字 |
| GPU 共享 | 显式允许多实例共享单卡 | 显示显存和干扰风险，不承诺隔离 |
| MIG 等硬隔离 | 在支持且认证机型上单独配置 | 不是所有 GPU 通用能力 |
| 维护与回收 | 长期停止、低利用、孤儿数据和可能闲置模型建议 | 管理员审批后执行 |
| 用量报表 | 分配时长、运行时长、利用采样、任务成功率、存储 | 采样数据不包装成精确计费计量 |

### 7.3 页面规划

- 新增“资源运营”：GPU 分配视图、资源申请、排队、配额、用量报表。
- GPU 时间线用于显示分配和运行，不用单纯高利用率判断业务价值。
- 报表支持项目、节点、GPU 型号和时间筛选，导出带口径说明。

### 7.4 验收与商业机会

- 测试资源竞争、优先级、配额、队列取消、节点离线和共享风险。
- 增值服务包括容量规划、利用率优化、资源运营报表和多机扩容建议。

## 八、`0.5.0.0`——模型供应链与受控节点认证

### 8.1 目标

把模型和自定义节点从“文件与安装脚本”升级为可审核、可复现、可升级、可回滚的企业资产。

### 8.2 私有模型供应链

1. 私有模型仓库、内网镜像站和代理缓存。
2. Model Manifest：名称、版本、文件、hash、来源、许可、适用镜像、依赖、资源建议和验收结果。
3. 模型审批：上传、完整性检查、许可审核、样例加载、发布。
4. 模型升级：差异、受影响实例／场景、灰度、回滚。
5. 多机缓存：按 manifest 同步，按需拉取，源站不可用降级。
6. 标准评测：能否加载、显存峰值、耗时、输出基本有效性；艺术质量由业务人员验收。
7. 安全扫描：格式白名单、异常文件和依赖风险；不宣称扫描证明模型绝对安全。
8. 许可变化只通知和限制新发布，不自动删除客户已存资产。

### 8.3 受控自定义节点

1. 节点源白名单、固定 commit、依赖锁和许可证检查。
2. 隔离构建，限制网络、文件和权限；禁止任意宿主机命令透传。
3. 建立节点与 ComfyUI、Python、CUDA、GPU 模板兼容矩阵。
4. 先在验收实例运行标准工作流，再发布到实例组。
5. 节点包版本化、可回滚，全部安装和升级有审计。
6. 对不兼容或停止维护节点提供替代建议和慧浪适配服务。

### 8.4 页面规划

- 模型中心新增私有仓库、审批、版本、评测和同步。
- 新增“节点包管理”：目录、详情、兼容、扫描、验收、发布记录。
- 场景包可引用固定模型与节点 manifest，避免交付时重新选择最新版。

### 8.5 商业交付

- 私有模型库部署和许可治理。
- 节点适配、兼容认证和长期维护。
- 模型／节点升级影响分析和灰度服务。

## 九、`0.6.0.0`——开放生态与企业集成

### 9.1 稳定 API 与事件

- 版本化只读 API：节点、实例、健康、任务、用量。
- 写操作 token 独立授权、范围、过期、轮换和审计，不复用管理员 cookie。
- Webhook：实例异常、任务完成、备份失败、版本偏差；签名、重试和重放保护。
- Prometheus、外部日志和企业工单系统集成。
- API 变更遵循兼容政策和弃用周期。

### 9.2 合作方场景发布

1. 合作方提交场景 manifest、模型与工作流许可、节点包、测试素材和验收结果。
2. 平台校验签名、版本、依赖、资源和兼容矩阵。
3. 慧浪执行安全、许可和真实样例审核。
4. 通过后使用“慧浪认证”标识；未通过只能作为社区未认证包。
5. 场景包独立版本和升级，不强制随 FlowPilot 核心发版。
6. 支持客户私有场景目录，不强制公开发布客户资产。

### 9.3 慧浪业务集成

- 通过机器 SN 关联出厂验收、保修、支持工单和巡检报告。
- 只有客户授权才上传诊断和资产信息。
- 与 CRM／售后系统集成时提供最小字段和撤回机制。

## 十、场景包产品路线

### 10.1 场景包统一结构

```text
Scene Package
  ├─ 认证镜像及 digest
  ├─ 模型 manifest、hash、来源、许可
  ├─ 官方或客户授权工作流
  ├─ 固定版本节点与依赖
  ├─ 最低／推荐 GPU、显存、内存、磁盘
  ├─ 前置条件与冲突检查
  ├─ 验收工作流、测试素材、成功标准
  ├─ 初始化、备份与恢复步骤
  └─ 支持边界、版本记录、升级回滚
```

FlowPilot 负责环境交付和验收；ComfyUI 负责工作流编辑。提示词业务系统、商品管理、审片等由独立业务应用或合作方提供。

### 10.2 五类场景包

| 场景 | 第一版内容 | 后续产品增强 | 验收示例 | 可售服务 |
| --- | --- | --- | --- | --- |
| 电商视觉 | 授权商品图工作流、模型与固定节点、独立输出目录 | 按店铺／项目隔离、批量环境、模板灰度 | 样例商品完成指定工作流，输出数量／尺寸／格式符合要求 | 场景部署、许可审核、模板适配、扩容 |
| 短视频／广告 | 图生视频、放大、帧处理环境和大容量输出规划 | GPU 排队、输出保留、NAS、长任务健康 | 标准短片跑通，无在线依赖，输出可恢复 | 大显存机型、存储、性能调优 |
| 设计工作室 | 多项目模板、共享模型、独立输出 | 项目权限、快照、版本分发、低利用回收 | 项目数据互不可见，模板升级可回滚 | 多机、SSO、备份、运维订阅 |
| 教育实训 | 教师模板、学生实例、标准模型和重置样例 | 批量开班、配额、课后重置、课堂巡检 | N 个实例按资源计划启动，课后可还原 | 教室整体交付、课程环境、巡检 |
| 企业私有创作 | 私有模型库、批准工作流、内网源 | SSO、审批、审计、异地备份、多机 | 完全离线、权限隔离、审计和恢复通过 | 私有化、合规、SLA、集中管理 |

### 10.3 场景发布顺序

1. 从慧浪已有客户中选择一类，优先完成一个真实标杆，而非同时开发五类。
2. 固化安装和验收，形成内部 POC 包。
3. 完成模型和工作流许可审查，再形成可销售 V1。
4. 将第二台服务器／第二位客户的部署结果与第一份验收对比，证明可复制。
5. 最后才开放合作方分发，避免未成熟场景包破坏慧浪认证信誉。

## 十一、商业产品组合演进

| 层级 | 阶段 1 | 阶段 2 演进 |
| --- | --- | --- |
| Community | 单机、单管理员、核心部署运维 | 持续获得安全更新和适用的基础能力 |
| 慧浪服务器出厂版 | 认证模板、预装、验收、整机支持 | 增加多机验收、场景包预装和资源规划 |
| 慧浪支持服务 | 安装、诊断、升级、培训 | 主动巡检、远程支持、恢复演练、版本托管 |

## 十二、阶段 2 版本准入与退出机制

### 12.1 每个版本启动前

- 至少有明确客户问题、目标用户和商业价值，不只因为技术先进而开发。
- 前一版本关键缺陷和支持负担已进入可接受范围。
- 明确是否影响开源核心、数据迁移、API 和现有认证矩阵。
- 场景包必须已有合法资产来源和真实验收素材。
- 多机和企业功能必须定义中心失联、权限和回退的安全边界。

### 12.2 每个版本退出前

- 功能、异常、性能、安全、迁移、UI、文档和实机验收通过。
- 至少一个真实客户或内部交付标杆完成闭环。
- 新能力不破坏 `0.1.0.0` 的单机离线主链路。
- 销售、交付和售后获得一致的功能边界和操作文档。
- 版本号、变更记录、签名包、SBOM 和许可清单同步更新。

## 十三、关键指标

### 13.1 运维与商业指标

- 告警有效率、平均发现时间、平均恢复时间、远程解决率。
- 巡检覆盖率、支持服务附着率、续保／续订率。
- 多机节点数、模板分发成功率、滚动升级成功率。
- 场景包复制交付时间、一次验收通过率、场景续用客户数。

### 13.2 资源与数据指标

- GPU 分配时长与实际利用采样、排队时长、低利用实例回收率。
- 备份成功率、最近成功恢复时间、异地副本覆盖率、恢复演练通过率。
- 私有模型 manifest 完整率、许可审核覆盖率、认证节点包复用率。

所有指标都要带统计口径；采样利用率不直接作为精确收费依据。

## 十四、主要风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 多机架构过早复杂化 | 轻量 Agent 先行，中心失联本地可管，不默认 K8s |
| RBAC 造成越权 | 服务端对象级授权、项目隔离测试、默认最小权限 |
| GPU 报表被误用于计费 | 明示采样口径，计费另做计量设计 |
| 场景包陷入工作流定制 | 核心只交付环境，业务应用由合作方或独立项目承担 |
| 模型与节点许可风险 | 逐资产清单、审核、固定版本、认证与再分发边界 |
| 告警过多失去信任 | 去抖、去重、恢复通知、静默和规则复盘 |
| 多版本核心分叉 | 尽量同核心模块化，企业能力通过清晰边界扩展 |
| 支持范围无限扩大 | 认证矩阵分级，实验功能不进入标准 SLA |

## 十五、推荐执行顺序

1. `0.1.0.0` 发布后，优先观察真实安装、升级和售后问题，启动 `0.1.1.0` 主动运维。
2. 同步选一个已有客户场景做 POC，但不等场景定制完成才发布运维版本。
3. 以恢复演练为目标完成 `0.1.2.0`，让场景 V1 具备数据保障。
4. 客户出现多人协作需求时启动 `0.2.0.0`，不要提前构建复杂多租户。
5. 客户节点数量和集中售后成本明确后启动 `0.3.0.0`。
6. 资源排队和利用率成为真实问题后再做 `0.4.0.0`。
7. 用已交付场景反哺 `0.5.0.0` 模型／节点认证，最后开放 `0.6.0.0` 合作生态。

**阶段 2 的核心不是功能更多，而是让慧浪能够从“卖一台已装好的服务器”，逐步升级为“持续管理一批可信的 AI 创作环境”。**
